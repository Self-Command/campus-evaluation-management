## 通用约束

NextAuth凭据会话每次读取实时状态；首次改密限制，角色、停用、版本或会话撤销会失权。写入在事务内复核，账号独占锁与周期共享账号锁/周期锁按固定顺序取得。业务写请求要求Origin与配置站点一致，缺失也拒绝；认证catch-all仍遵循NextAuth自身协议。

统一包装的私有业务JSON与apiError响应使用no-store；部分旧路由前置Origin/限流响应仍未统一。ScoringError/ZodError及损坏JSON为400；URI文件名解码异常当前可能500，尚未专门映射。AccountError按其status；唯一冲突409通用提示；未知500不返回堆栈或秘密。响应主要为`{error:string}`，稳定code/requestId/fieldErrors尚未实现，不能写作已交付。Decimal经过JSON安全投影或toFixed输出普通十进制字符串，日期为ISO字符串。

列表先按权限/筛选，再稳定排序/分页及total；每页20，page上限100000。周期名录仍有界全量读取；发布与更正容量2000人，导入每批100行且预览15分钟，不建设通用异步平台。超过限制明确拒绝，不截断冒充完整。

## 活动关键兼容变更

- 发布不再需要管理员预确认或预检token：ADMIN、COLLEGE（本院）及历史PUBLISHER对可管理活动点发布后，服务端在事务内重新校验所选范围方式（全校/按学院/按班级，同一方式内为并集）并写`confirmed=true`、`publishedAt`；撤回须理由。`confirm`动作已删除。
- 修改已发布活动的分值、计分项或参与范围会自动撤回发布并写`publishRevision`与前后值审计；只改名称、时间、介绍或附件不撤回。
- `content`改为Markdown正文，长度上限20000；列表/信息流返回去标记的`contentText`摘要；`requirements`字段已从模型、接口和页面删除。
- 活动附件走独立接口：上传为原始二进制加`x-file-name`、可选`x-activity-id`，下载鉴权并复核SHA-256；数量、单文件大小和后缀白名单由系统设置控制。
- 名单导入只接受`publishedAt != null`的活动；参与事实仍由学院维护或导入，学生不能自行报名，审核通过后才计分。
