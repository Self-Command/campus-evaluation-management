# 学院流程增量契约

2026-10-20。按[统一审核规范](../product/学院职责与统一审核规范.md)及ADR0005实施，和现有接口分开记录；本文件是本批前后端约定，不代表接口已全部运行通过。修订与错误仍遵守现有同源、会话、权限及事务复核。

## 第一批：组织与账号

- 新身份代码为`COLLEGE`、`COUNSELOR`；保留`ADMIN`、`STUDENT`。`PUBLISHER`只保留旧数据解释和明确移交，新建/更新不能分配它。
- 新增`College`、`Major`、`SchoolClass`，各有稳定id、code、name、enabled、revision。专业绑定学院、班级绑定专业，创建后不直接改父级。班级绑定本院启用的`COUNSELOR`，未绑定时为待完善，不能新建/转入学生。
- `User.collegeId`绑定学院/辅导员账号；学生只传`classId`，由班级推导全部归属。旧档案字符串保留作兼容显示，旧记录不自动猜测绑定。当前归属变更留历史生效时间与审计，冻结结果不改。
- `GET /api/organizations`：学校管理员全部；学院本院；辅导员授权班级。返回`{role,canManage,colleges,counselors,totals}`。colleges嵌套majors/classes；class含`counselor:{id,name,login}|null`和studentCount；counselors只含范围内可选人员及collegeId/disabled。所有层级返回真实启停、修订和完整归属，不泄露跨院名录。
- `POST /api/organizations`：学校管理员维护学院/专业/班级；学院只维护本院专业/班级。请求为`{kind:"college"|"major"|"class",code,name,enabled,parentId?,counselorId?}`；更新额外带`id,revision,reason`（理由必填）。学院无parentId；专业parentId为学院；班级parentId为专业。未绑定辅导员传null。成功返回刷新后的组织树。无删除接口；停用有启用下级或在读学生/责任账号的组织被拒绝。
- `GET/POST/PATCH /api/admin/accounts...`仍仅学校管理员，列表支持五个历史/当前角色。新账号字段改为`{name,login,role,collegeId?,classId?}`；学院/辅导员必须选启用学院，学生必须选已配辅导员班级，ADMIN不带归属。禁止传自由college/major/className。PATCH保留`revision,reason,disabled,account`外层；更改辅导员学院/身份/停用前须先交接其班级，学生转班写归属历史。既有密码不变。
- `GET /api/students`：管理员全校、学院本院、辅导员授权班级，原q/page/college/major/className筛选只作为范围内交集；新增`classId`精确筛选。返回分页名录及范围内筛选项，档案增补classId、班级路径和责任辅导员。未配置旧档案仅学校管理员待完善清单可见。
- `GET /api/students/[id]`范围同上，学生只本人；`PATCH`仅学校管理员/本院学院，字段`{revision,reason,name,classId}`，禁止自由组织文本和跨院转入。更正返回重新查询后的完整档案。

## 后续批次

第一批实施补充：既有学生账号PATCH省略或留空classId时保留原归属，不解除已配置绑定；旧未绑定档案允许先停用账号，不因此猜测归属。实际新建/转班仍须配置完整。学生详情另返回最近20条`affiliationHistory`（classId、当时identity、起止时间、actorId、reason）。组织筛选及页码写入URL，账号和学生档案职责分别独立。`/api/account`及周期读取接受新增身份，改密仍重新检查会话和原密码。当前学院/辅导员首页进入授权学生名录，后续专属工作台另批实现。

第二批直接个人申报取消projectId/activityId/学生分数，增加独立termId/title及辅导员初审/学院终审；第三至五批活动、成绩扣分、导出/证明接口随各任务开始前补充。旧认定项目保留历史读取模型，停止所有项目管理写入口，不能建同用途替代配置。待审输入与原有效版本分离，避免半迁移影响正式成绩。

所有接口必须重新校验启停、组织绑定、角色、版本与归属；错误零写入，错误消息不输出凭据。现有接口契约在完成实现与隔离验证后逐项更新，不把目标状态写成既成事实。
