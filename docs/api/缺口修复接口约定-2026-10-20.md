# 缺口修复接口约定

2026-10-20，用户已批准按17项审查修复。现已按约定实施，实际证据见docs/audit/缺口修复实施与验证-2026-10-20.md；本文件仍只描述契约，不作为检查通过记录。

## 已采用的规则

- 三组非空、多选，组内OR、组间AND；班级使用college/major/className完整路径。草稿允许未选，发布和新增参与时必须命中完整范围。
- 信息流按当前有效身份及当前已发布范围；本人后台登记参与按历史快照保留。旧未标记来源不自动猜测成导入。
- ADMIN/PUBLISHER仅可为ownerId=本人活动登记参与和录分；管理员审核和分值确认保持独立。
- FIXED固定分保持原计分；INDIVIDUAL逐人分以活动points为上限，缺分不视为零，审核通过前必须录分。更改已审核个人分须重新审核，不直接修改生效成绩。
- 导入追加，立即显示本人已登记，仍须审核才计分。重导不删除漏行，不从当前角色倒推历史来源。
- 待补本人可withdraw；管理员可close待审/待补并说明理由。所有角色变更后操作按当前身份重新授权。
- 规则/已确认分值采用预览token、理由、全量影响检查和事务更正；保留所有旧结果/快照。结果预检绑定完整名录及输入摘要；重开后默认沿用原发布名录，明确变更名录才重新预检。
- 确认核对可有理由延期，旧确认保留，不引入代确认或免确认。延期以独立治理事件记录，不覆盖原发布成绩。
- 个人申报factKey沿用周期内唯一；可关联activityId，审核遇已有效活动或同活动关联申报冲突时阻断，不靠标题自动吞分。

## 活动接口（UI agent负责页面；主负责人负责实现以下服务和API）

- `pageActivities(sessionId,termId,q,page)`：ADMIN所有/PUBLISHER本人活动；STUDENT本人后台登记参与。返回`{items,total,page}`，每项保留现有字段并加`publishedAt,publishRevision,scoreMode,audience`；学生audience为null、`ownParticipation`含`id,registeredAt,registrationSnapshot,score,revision,sources[{id,status,reviewReason}]`。
- `pageActivityFeed(sessionId,termId,q,page)`：仅STUDENT，已发布且命中资格的分页活动，结构同上；不展示其他学生名单。
- `getActivity(sessionId,id)`：学生仅符合当前信息流资格或已有本人后台登记历史可读，返回安全字段；历史参与不授予新的范围资格。
- `POST /api/activities/audience`，ADMIN/PUBLISHER：`{action:'options',q?,page?,audience?}`返回`{colleges:string[],classes:{college,major,className}[],students:{id,login,name,college,major,className}[],total,page}`；`{action:'preview',audience}`返回`{count,students:前20,errors:string[],token}`。audience固定为`{colleges:string[],classes:{college,major,className}[],studentIds:string[]}`。
- 现有`POST /api/activities action=save`的activity新增`audience,scoreMode:'FIXED'|'INDIVIDUAL'`；保存草稿不等于发布。已发布范围变更会撤回发布，必须重新核对发布。
- `POST /api/activities {action:'publish',termId,id,revision,token}`，本人owner，必须分值confirmed、有效非空交集，token来自audience预览且绑定当前范围及学生身份；`action:'unpublish'`带`reason`，保留历史。
- `GET /api/activities/participants?termId=&activityId=&page=&q=`返回`{items,total,page}`，owner或ADMIN审核只读；items含`id,studentId,login,name,college,major,className,registeredAt,registrationSnapshot,score,revision,sources`。
- `POST /api/activities {action:'score',termId,participationId,revision,value,reason}`仅owner，INDIVIDUAL且后台登记；修改分数使已通过来源回待审，保留历史。
- 原单人`action:'submit'`保留证明、说明与学生标识；仅owner代录算后台登记，学生自行申报不算登记且必须符合发布资格。
- 旧`GET /api/activities`改成分页对象，view=feed/reviews/默认，前端消费者同步；不保留200条静默截断。

## 其他修复接口

- 认定/个人申报增加`action:'close'`，管理员、PENDING/NEEDS_CHANGES、revision、reason；withdraw支持NEEDS_CHANGES。
- `POST /api/terms/:id/publication action=preview`返回增加`token,reviewBreakdown:{recognitionsPending,recognitionsNeedsChanges,claimsPending,claimsNeedsChanges},cohortPolicy,cohortChanges`；publish必须附token。history返回`effectiveCheckingEndsAt`。
- publication `action:'extend'`带`revision,publicationId,checkingEndsAt,reason`；CHECKING、有理由、只能延长。`action:'cohort'`带`revision,policy:'PREVIOUS'|'CURRENT',reason`，ACTIVE重开阶段可显式选择名单政策，默认PREVIOUS。
- `POST /api/terms/:id/correction`：preview `{kind:'scheme'|'activity'|'project',scheme? ,id?,nodeId?,points?,scoreMode?}`返回`{token,affectedStudents,changes:[{studentId,login,name,before,after}],errors}`；commit相同字段加token/revision/reason。只允许ACTIVE，需先理由重开；旧发布不改。
- `GET /api/input-history?termId=&kind=grade|deduction&id=`：ADMIN或本人，返回`{items:[{id,at,actor,action,before,after,reason}]}`。
- 个人申报submit增加可选`activityId`。审核冲突在关联同活动已通过时返回409，并给可定位业务提示；认定审核也反向检查。

锁定preview亦返回reviewBreakdown四项，界面分别直达原周期/状态队列。成绩与扣分页支持login指定学号首屏授权读取，错误不回退其他学生。\n\n每项实施记录与FL编号对照，界面只基于已选完整模板改造。
