# 本轮页面接口约定

## 三角色工作台服务（2026-10-20）

首页服务器组件调用`getWorkbench(sessionId, termId)`，不新增面向浏览器的汇总API。服务在事务内按账号→周期顺序取得共享锁，再重新校验会话、停用、认证版本与强制改密；读取已完成的并发写入，不使用等待锁前的旧认证快照。只返回最小身份字段，按role返回互斥数据结构。

- ADMIN：当前周期活动/个人待审、未确认活动、未决异议全量数；最早8条审核、6条异议；最近8周期当前发布名单/确认数与核对期限。全校有效学生另明确全校口径。
- PUBLISHER：仅本人负责活动及这些活动的合法认定运营统计；有效参与按学生+活动事实去重。待补材料仅包含本人提交且本人可重提的NEEDS_CHANGES/REJECTED，不能把别人的待补记录分配给本人。活动最近8条，完整记录保留原业务入口。
- STUDENT：仅本人成绩、输入缺失、模块、本人待补及最近记录；已生效周期的已确认、尚未结束活动。发布后读取固定结果及对应确认，名次只返回本人班级名次/班级人数，不返回他人名单；无档案、配置中、未纳入发布名单均保持空分数，不能伪造成零分。

页面沿用`measurementContext`显式周期与记忆规则；链接携相同termId。管理员、发布者、学生分别使用default、productivity、academy完整模板主体，逐文件来源见模板清单。服务、HTTP、界面验收分别记录。

2026-10-20。本轮新增功能的实施契约；运行验证与迁移状态另记，不能把本契约当成已通过验收。三基础角色、每周期一套方案。所有写入Origin检查、会话事务内复核、revision冲突409，私有响应no-store。十进制值用字符串，日期ISO。分页20条。

## 个人申报

`/claims`默认记录页同时提供当前角色主操作：STUDENT在ACTIVE且有启用项目时可直接新建个人申报；ADMIN在ACTIVE可直接新建认定项目。无项目及CONFIGURATION/CHECKING/LOCKED显示实际业务原因，不能静默隐藏全部操作让用户猜测。学生按项目固定规则提交，管理员不能冒充学生本人申报。

项目及当前20条申报记录由服务器首次授权读取，白名单投影为普通字符串/数组后传给模板名录，首屏不再等待浏览器请求才出现操作。客户端仍按原API重新读取和提交后刷新；重新读取失败显示错误并禁用依赖项目的提交，不用旧初始数据冒充刷新成功。读取不创建项目、申报或更改周期阶段。

- `GET /api/projects?termId=`：三角色，返回项目数组；学生只读启用项目。
- `POST /api/projects`：ADMIN，`{termId,id?,revision?,name,description,nodeId,points,enabled}`。ACTIVE可创建；有申报后不可改计分字段，可改说明/停用，停用不取消已申报分数。
- `GET /api/claims?termId=&page=&status=`：ADMIN全部、STUDENT本人，返回`{items,total,page}`。item含project、student `{id,name,login}`、evidence `[{id,name}]`、history、status、revision。
- `POST /api/claims`：STUDENT，`{termId,projectId,factKey,occurredOn,note,evidenceIds}`。日期YYYY-MM-DD，事实标识1..120、说明2..2000，材料1..5，学生不能自定分值。学生+周期+规范事实标识唯一，跨项目同事实也拒绝；本轮可选activityId关联活动，双方审核防重复计分。
- `PATCH /api/claims/[id]`：`{termId,revision,action,...}`；本人`withdraw`仅PENDING；本人`resubmit`仅REJECTED/NEEDS_CHANGES/WITHDRAWN，附note/evidenceIds；ADMIN `review`附`status:APPROVED|REJECTED|NEEDS_CHANGES,reason`；ADMIN `revoke`仅APPROVED、附reason。状态改变留历史，计分有效性改变递增inputRevision。
- 原活动认定继续 `/api/activities action=submit/review`；追加 `withdraw`、`resubmit`、`revoke`，字段同上，resubmit须note/evidenceIds。review可NEEDS_CHANGES，仅待审；已通过变更必须revoke。

## 实时结果与发布

- `GET /api/results/students?termId=&q=&page=&college=&major=&className=`：仅ADMIN，返回`{items,total,page,phase,publication,scopeOptions}`；每项`{id,login,name,college,major,className,total,complete,confirmedAt}`。CONFIGURATION总分/完整性均null；ACTIVE仅批量计算当前20条，缺失总分null；CHECKING/LOCKED使用当前发布冻结身份、分数及确认，后续转班/停用不改历史。`scopeOptions:{colleges,majors,classes}`父级过滤。

- `GET /api/results?termId=&studentLogin=`：ADMIN按学号或STUDENT本人；ACTIVE返回实时`getStudentResult`形状（含个人申报依据），CHECKING/LOCKED返回当前固定发布记录。固定记录附`publication:{id,sequence,publishedAt,checkingEndsAt,requireConfirmation}`、`resultHash`、`confirmation`、本人`rank`与`population`；`rank`/`population`按发布快照中的班级范围计算，不返回其他学生名单。
- `GET /api/terms/[id]/publication`：ADMIN，返回`{term,current,history}`；current/publication元信息含id、sequence、publishedAt、checkingEndsAt、requireConfirmation、studentCount、inputRevision；history不可变，current可null。
- `POST /api/terms/[id]/publication` action=`preview`，ADMIN，返回`{termRevision,inputRevision,studentCount,pendingReviews,missing:[{studentId,login,name,nodes}],canPublish}`。显式全体当前有效有档案学生，最多2000人，完整性/待审阻断，不默默截断。
- 同路由action=`publish`：`{revision,inputRevision,checkingEndsAt,requireConfirmation,requestId}`；requestId UUID；截止必须将来，requireConfirmation显式选择。ACTIVE发布完整不可变结果，原子转CHECKING。更正须先reopen到ACTIVE，再发布新版本；旧结果/确认保留。
- `POST /api/results/[publicationId]/confirm`：STUDENT，`{termId,resultHash}`；只接受当前发布、本人hash、CHECKING及核对期限内；同版本重复确认返回同一记录。

## 异议

- `GET /api/appeals?termId=&page=&status=`：ADMIN全部、STUDENT本人，`{items,total,page}`，含学生、publication元信息、evidence、revision、处理结论。
- `POST /api/appeals`：STUDENT，`{termId,publicationId,resultHash,target,reason,evidenceIds}`；target1..120（总分/节点/事实等），reason2..2000，材料0..5，只针对本人当前版本、期限内。
- `PATCH /api/appeals/[id]`：`{termId,revision,action,...}`；本人withdraw仅OPEN；管理员process OPEN→PROCESSING；reject附resolution2..2000；resolve附resolution及resolvedPublicationId，必须是同周期后续版本且该学生结果hash改变，不能文字解决未更正的分数。

## 排名、锁定和更正

- `GET /api/rankings?termId=&publicationId=&college=&major=&className=&page=`：ADMIN完整分页名单`{items,total,page,publication,scopeOptions}`；STUDENT仅本人名次/人数。数据取冻结发布成员，按最终displayTotal精确降序，同分竞赛名次1,1,3。筛选冻结学院/专业/班级；筛选只影响页面名单。
- `GET /api/rankings/export?termId=&publicationId=`：ADMIN直接下载XLSX全校成绩明细表，按学院、专业、班级、学号排序；`publicationId`缺省取当前发布版本，所选历史版本使用其冻结组织与成绩；不采用页面学院/专业/班级筛选，写导出审计。
- `POST /api/terms/[id]/settlement` action=`preview`：ADMIN，返回`{revision,inputRevision,publicationId,studentCount,confirmedCount,blockers:[{type,message,count}],token,expiresAt}`；预检绑定操作者和状态，15分钟。
- 同路由action=`lock`：`{revision,token,requestId}`，CHECKING，重检期限/确认/异议/待审/结果基线，全通过生成不可变快照并LOCKED。
- 同路由action=`reopen`：`{revision,reason}`，CHECKING或LOCKED→ACTIVE，理由2..1000，保留旧发布、确认、快照，当前指针清空，修订递增，需重新发布核对。
- `GET /api/terms/[id]/snapshots`：ADMIN返回冻结快照元信息列表；`GET /api/snapshots/[id]`：ADMIN返回快照完整冻结内容。

## 常用设置

- `GET /api/settings/public`：公开，返回`{siteName,siteDescription,pageTitle,themePreset,logoAssetId,faviconAssetId,revision}`，初始默认“序衡”“高校综合测评管理”，不影响评分。
- `GET /api/admin/settings`：ADMIN返回同公开内容及updatedAt。
- `PUT /api/admin/settings`：ADMIN，`{revision,reason,siteName,siteDescription,pageTitle,themePreset,logoAssetId,faviconAssetId}`；白名单即时生效、revision和审计，themePreset=default|violet|blue，资源可null。采用简化即时生效，不提供未实现的草稿审批导航。
- `POST /api/admin/brand-assets`：ADMIN原始二进制，x-file-name URI编码；PNG/JPEG/ICO，最大1MiB，返回`{id,mime,size}`；`GET /api/brand-assets/[id]`公开仅供站点引用的已发布图片，未引用资源仅管理员可读。

## 独立学生档案与账号筛选

- 原`GET /api/grades`和`GET /api/deductions`保留输入列表形状，管理员读取扩展至四阶段；CHECKING/LOCKED以当前发布冻结姓名/学号匹配学生，再读取本周期只读输入。写入接口仍仅ACTIVE，不能从只读页面绕过阶段。ACTIVE以当前有效有档案学生为准；停用学生的历史发布读取仍可用。

- `GET /api/students?q=&page=&college=&major=&className=`：仅ADMIN，返回`{items,total,page,scopeOptions}`，每页20。item为`{id,login,name,revision,disabled,createdAt,studentProfile:{studentNumber,college,major,className}}`，不返回密码/会话/凭据。含启用或停用的学生档案；组织选项来自当前学生归属。
- 原`GET /api/students/[id]`保留ADMIN或本人STUDENT读取语义；新增`PATCH /api/students/[id]`仅ADMIN，严格白名单`{revision,reason,name,college,major,className}`，理由2..500、四项1..80。原子改姓名/归属，账号revision递增与审计；不能通过此入口更改login/role/disabled/密码，旧修订409。
- `GET /api/admin/accounts`在既有q/page上新增`role=ADMIN|PUBLISHER|STUDENT`、`disabled=true|false`过滤，列表仍为20条分页。账号生命周期服务保留原兼容能力；正式UI把后续学生归属更正移至独立学生档案页。

上述路径由主负责人实现。UI agent负责从完整模板原页改造对应页面；接口未就绪可先编写最终交互，交付前由主负责人补齐并验证，不显示假成功或开发占位。
