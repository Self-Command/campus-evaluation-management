状态：已批准并实施（2026-10-27，0.5.1）  
日期：2026-10-27  
范围：活动详情页单页签展示、活动介绍图片的加载与失败恢复、相关品牌图片兜底、活动附件图片接口缓存；不含权限、数据库结构和审核逻辑变更  
相关文档：[界面设计规范](./界面设计规范.md)、[前端从零重建规范](./前端从零重建规范.md)、[模板来源与适配清单](./模板来源与适配清单.md)

## 1. 结论

### 1.1 “活动详情”下面那根线是什么

那根线不是内容分隔线，而是页签栏的边框和当前页签下划线叠在一起的结果：

- 活动详情把页签栏包在一个带 `border-y` 的横向滚动容器里，上下各有 1px 边框（`activity-detail.tsx:237`）。
- 页签触发器使用 `flex-1`，只有一个可见页签时会被拉满整行，标签因此居中（`tabs.tsx:53`）。
- `line` 变体的选中指示条是 2px 前景色横线，定位在触发器底部（`tabs.tsx:56`）。
- 当一个页面只剩一个页签时，这条 2px 选中线横跨整行，并与容器底边框几乎重合，看起来就像“居中的活动详情标题下面压了一根粗线”。多页签时它是正常的页签栏；只有学生无参与记录、无活动证明时才会退化成单页签，于是被看见。

### 1.2 图片为什么直接破碎

- 活动介绍由 Markdown 渲染，图片是原生 `<img loading="lazy">`，没有加载占位、没有加载完成回调、没有失败回调、没有重试（`markdown-content.tsx:40-43`）。
- `<img>` 请求失败后，浏览器只能显示破图图标；`loading="lazy"` 只是延迟加载，不会重试。页面不刷新，失败状态就一直保留。
- 活动附件图片接口返回 `Cache-Control: private, no-store`（`activity-attachments/[id]/route.ts:20`），每次进入页面都会重新下载；弱网中断的请求没有缓存可兜底。
- 每张图片的 GET 都会重新执行一次完整活动可见性校验和文件哈希校验（`activity-attachments.ts:155-166`）；会话过期返回 401、附件尚未绑定返回 404、瞬时超时或 5xx 都会被浏览器直接表现为破图。
- 已在服务器核对：截图中的附件文件存在（891,664 字节）且已绑定到该活动，不是文件丢失；在现有日志中没有发现路由异常。也就是说，本次现象属于“请求失败后没有任何恢复手段”，具体触发可能是弱网、会话状态或请求时序，但当前页面无法把任何一种情况恢复回来。

### 1.3 全局结论

同类缺口不止这一处。按影响排序：

| 优先级 | 位置 | 现状 | 用户可见后果 | 本轮处理 |
| --- | --- | --- | --- | --- |
| P0 | 活动详情单页签栏 | 单页签被拉满整行，选中线与边框叠加 | “居中标题 + 粗横线”的异常视觉 | 修 |
| P0 | 活动介绍 Markdown 图片 | 无占位、无错误处理、无重试 | 弱网/会话过期后永久破图、页面跳动 | 修 |
| P1 | 活动附件图片 GET | `no-store`，无 ETag，每次全量鉴权下载 | 重复进入重复下载，弱网更易失败 | 修 |
| P1 | 品牌 Logo（侧栏、登录页、设置预览） | 原生 `<img>`，加载失败显示破图 | 站点标识位置出现破图 | 修 |
| P1 | 设置页登录背景/网站图标预览 | 只有成功态，没有失败态 | 管理员无法判断图片是否仍可用 | 修（少量） |
| P2 | 活动附件、附件管理、学生证明的文件链接 | 直接新窗口打开接口地址 | 失败时显示 JSON，没有业务提示 | 暂缓 |
| P2 | 富文本编辑态图片 | TipTap 内图片无失败占位 | 编辑时偶发破图，可重新插入 | 暂缓 |

| P2 | 50MB 活动附件、证明材料上传 | 有“上传中/重试”，无进度、无超时 | 弱网时不知道还要等多久 | 暂缓 |

## 2. 现状证据

### 2.1 页签渲染链路

活动详情的可见页签由角色和数据共同决定：

- 所有角色都有“活动详情”。
- 非学生且有权查看参与名单时显示“参与名单”。
- 有参与、已登记且未移除的学生显示“活动证明”。
- 有本人参与记录的学生显示“我的参与”。

因此学生没有参与记录时只剩一个“活动详情”页签。页签栏容器固定带 `border-y`，触发器又使用 `flex-1`，单页签就被拉伸成整行，并叠加选中下划线。

### 2.2 图片加载链路

1. 编辑活动时上传图片，富文本编辑器把图片写进 Markdown，例如 `![文件名](/api/activity-attachments/<id>)`。
2. 打开详情页后，`MarkdownContent` 用原生 `<img>` 请求 `/api/activity-attachments/<id>`。
3. 接口先校验登录会话，再按附件所属活动执行完整可见性校验，然后读取文件并校验 SHA-256。
4. 返回图片字节，`Cache-Control` 为 `private, no-store`。
5. 请求成功则显示；失败则浏览器显示破图，页面没有后续动作。

### 2.3 已核实的事实

- 截图对应活动已发布，附件文件在服务器上存在，大小与数据库记录一致，绑定关系正确。
- 图片接口按当前代码对“能打开活动详情的学生”应返回 200；无法从服务器日志确定本次浏览器端失败的具体原因。
- 现有页面没有任何加载占位、错误文案、重试入口或原图入口，失败后只能整页刷新。
- 接口 `no-store` 使浏览器不保留副本，重复进入都重新下载，弱网时每次都暴露在失败风险里。

## 3. 设计目标与原则

1. 不再出现无法恢复的破图：失败后必须有明确说明和重试入口。
2. 有界重试，不无限加载：自动重试次数、单次超时和最终失败态都要有明确上限。
3. 加载过程中保留稳定占位，减少页面跳动。
4. 只修当前页面和公共图片组件，不改模板整体布局，不改全局页签组件。
5. 不削弱鉴权、不泄露文件、不改变审核与审计语义；证明材料接口继续保持 `no-store`。

## 4. 方案一：活动详情单页签栏

### 4.1 目标视觉

- 只有 1 个可见页签时，不显示页签栏，也不显示那根选中线和上下边框；正文直接从“活动介绍 / 活动信息”开始。
- 2 个及以上可见页签时，保持现有模板页签栏、等宽标签、选中下划线和上下边框不变。
- 页面头部、右栏、对话框和按钮位置均不变。

### 4.2 实现方式

1. 在 `activity-detail.tsx` 内根据现有权限条件计算 `visibleTabs` 数组，而不是在 JSX 中分散写 `canSeeParticipation` 等条件。
2. 可见页签为 1 时，直接渲染该页签的内容容器，不渲染 `Tabs` / `TabsList` / `TabsTrigger`，避免单个 Tab 被 `flex-1` 拉满以及 `tabpanel` 语义悬空。
3. 可见页签大于等于 2 时，沿用当前 `Tabs` 结构和 `variant="line"` 样式。
4. 不修改 `src/components/ui/tabs.tsx`，避免影响成绩、扣分、设置、组织等现有页面。
5. 不新增标题；活动名称已经是页面主标题，“活动详情”在这里是导航标签，不是内容标题，单页签下删掉比再放一个重复标题更干净。

### 4.3 边界

- 学生有参与记录：显示“活动详情 / 我的参与”，页签栏保留。
- 学生有活动证明：至少两个页签，页签栏保留。
- 辅导员、学院、管理员：仍然 3–4 个页签，页签栏保留。
- 页签深链 `?tab=participation`、`?tab=participants`、`?tab=evidence` 的初始化逻辑保持不变。

### 4.4 不采用的方案

- 只把 `border-y` 去掉：单页签仍会被拉满并居中，问题只解决一半。
- 给单个 Tab 设置 `flex-none`：会改变所有使用 line 变体页签页面的宽度分配，影响面大于问题本身。
- 保留页签但把它做成“普通标题 + 分隔线”：语义重复，且需要新增视觉结构，不符合只改必要部分的原则。

## 5. 方案二：容错图片组件

### 5.1 组件

新增 `src/components/dashboard/resilient-image.tsx`，仅服务活动介绍等 Markdown 图片；品牌资源使用单独的兜底逻辑。

组件输入：

```ts
type ResilientImageProps = {
  src?: string;
  alt?: string;
};
```

### 5.2 状态机

| 状态 | 触发 | 界面 | 用户动作 |
| --- | --- | --- | --- |
| 加载中 | 挂载或重试 | 稳定高度的浅色占位，不显示破图；超过 3 秒补充“图片加载中…” | 无 |
| 已加载 | `onLoad` | 图片淡入，占位消失 | 可点击“查看原图” |
| 自动重试 | `onError` 且自动重试次数 < 2 | 占位继续保留，显示“正在重试” | 无 |
| 失败 | 自动重试 2 次仍失败，或确认 401/403/404 | 紧凑错误块：原因文案 + “重新加载” + “查看原图” | 手动重试或查看原图 |
| 地址无效 | `src` 为空或不是 http(s)/站内路径 | 错误块：“图片地址无效” | 无 |

参数建议：

- 单次请求超时 15 秒；`onload` 或 `onerror` 任一到达即清除计时器。
- 自动重试 2 次，间隔约 1 秒、3 秒；第 3 次仍失败后进入明确失败态，不再自动请求。
- 重试 URL 在当前 URL 后追加 `retry=N` 查询参数，绕过可能存在的失败缓存；接口忽略该参数。
- 图片源变化时重置重试计数和全部计时器。

### 5.3 失败原因分类

自动重试耗尽后，用一次 `HEAD` 请求区分失败原因：

| 结果 | 文案 | 后续动作 |
| --- | --- | --- |
| 401 / 403 | 登录状态可能已过期，或已无权查看这张图片 | 提供“重新登录”链接（跳 `/login`） |
| 404 | 图片已被移除或暂不可用 | 提供“重新加载”；仍失败则建议联系活动主办方 |
| 5xx / 网络失败 / HEAD 也失败 | 网络不稳定或服务暂时不可用 | 提供“重新加载” |
| 超时 | 图片加载超时，请检查网络后重试 | 提供“重新加载” |

`HEAD` 只在最终失败时执行一次，不参与自动重试，避免额外放大请求量。

### 5.4 结构与可访问性

- Markdown 图片通常位于 `<p>` 内，组件必须只返回行内元素（`span`、`button`、`a`），不能用 `div` / `figure` 包裹，否则会产生非法的 `<p><div>` 嵌套并引发水合问题。
- 占位使用 `span` 加块级显示和固定最小高度，不使用会渲染 `div` 的 `Skeleton`。
- 保留原始 `alt`；错误块使用 `role="status"`，重试按钮具备明确 `aria-label`。
- “查看原图”使用按钮打开新窗口，避免在 Markdown 图片本身已被链接包裹时产生嵌套 `<a>`。
- 不执行 Markdown 中的 HTML，继续沿用现有 `rehype-sanitize`；只对 `src` 做 http(s) 或站内路径校验。

### 5.5 接入点

`markdown-content.tsx` 的自定义 `img` 渲染改为 `<ResilientImage src={src} alt={alt} />`，删除原来的裸 `<img>`。图片容器样式（圆角、边框、最大宽度、上下间距）迁移到新组件，视觉效果保持现状。

## 6. 方案三：活动附件图片接口缓存

### 6.1 现状问题

`Cache-Control: private, no-store` 让每次进入活动详情都重新请求所有图片，既增加等待和失败概率，也让浏览器无法在弱网下直接复用已下载内容。

### 6.2 建议响应头

对 `GET /api/activity-attachments/[id]` 的图片和 PDF：

```text
Cache-Control: private, max-age=300
ETag: "<文件 sha256>"
```

- 请求带 `If-None-Match` 且与 ETag 一致时返回 `304 Not Modified`，不再传输文件内容。
- 保留 `Content-Type`、`Content-Disposition`、`X-Content-Type-Options: nosniff`。
- 删除操作仍为 `no-store`，不影响。
- 证明材料接口 `/api/evidence/[id]` 保持现状，不纳入本次缓存改造。

### 6.3 安全边界

- 响应是 `private`，只允许浏览器私有缓存，不允许 CDN 或共享代理缓存。
- 缓存时长 5 分钟，用于弱网重进和重试；活动撤回、学生被移出名单等权限变化最多延迟 5 分钟在这个浏览器上生效。
- 共享电脑上同一浏览器配置在 5 分钟内可能复用已缓存图片；如果需要更严格的即时失效，把 `max-age` 缩短到 60 秒即可，代价是更频繁回源。
- 不改变接口鉴权：命中缓存之前或回源时仍按当前会话和活动可见性判断；不同用户、不同会话不会命中服务端共享缓存。
- 员工每次回源下载仍会写现有附件下载审计；浏览器命中的重复展示不再产生新的服务端下载记录，这是缓存带来的正常语义变化。

## 7. 方案四：品牌图片与设置预览兜底

### 7.1 品牌 Logo

`BrandLogo` 目前是裸 `<img>`（`brand-logo.tsx:22-50`），出现在侧栏、登录页头部和设置预览中。改造为客户端组件，加载失败时：

- 立即用一个文本兜底替代破图，显示 `alt`（通常是站点名称），沿用父容器的最大宽度和截断规则。
- 不做自动重试；品牌资源是 `public, max-age=31536000, immutable` 的公开资源，失败多为瞬时网络问题，刷新或下次导航会重新请求。
- 不改变 Logo 的宽高比、高度预算和明暗主题双图逻辑。

### 7.2 设置页预览

设置页的登录背景图、网站图标和 Logo 预览目前只有成功态。增加失败占位：

- 显示“图片无法显示，请重新上传或刷新后再试”，保持原预览框尺寸，不出现破图。
- 提供一次“重新加载”操作；管理员的预览失败通常是文件被删除或资源尚未保存，提示重新上传比无限重试更有效。

## 8. 暂缓项（P2）

以下问题真实存在，但不放进本轮，避免把一次视觉与加载修复扩大成全局重构：

1. 附件/证明文件链接的失败提示与统一预览：图片和 PDF 可以直接使用现有 `EvidenceViewer` 的模板结构做对话框预览；非预览格式继续下载。涉及所有附件入口，另立设计。
2. 编辑态图片兜底：TipTap 内图片需要自定义 NodeView 才能接管失败态，收益低于学生阅读态。
3. 请求超时：`useRemote` 和 `requestJson` 增加统一超时与重试，需要评估上传、导出和长任务接口，不能一刀切。
4. 上传进度：活动附件最大 50MB，弱网下只有“上传中…”文本；需要改成可取消、可显示百分比的上传实现，另立设计。

- 在隔离数据库（55433）和本地应用上执行，不触碰真实开发库。

### 10.2 用户视觉验收

- 学生视角进入活动详情：没有“活动详情”页签条和粗横线，页面从活动介绍开始。
- 有参与记录的学生、辅导员、学院、管理员：页签栏和原来一致。
- 弱网或断网时图片区域保持占位，最终显示明确失败原因和重试按钮；网络恢复后重试成功。
- 二次进入活动详情，浏览器网络面板中图片来自缓存。
- Logo 资源失败时侧栏/登录页显示站点名称，而不是破图。

## 11. 风险与回滚

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 缓存延迟权限失效 | 活动撤回/移除参与后，图片最多还能在当前浏览器显示 5 分钟 | `private` 缓存；必要时缩短为 60 秒；证明材料仍 `no-store` |
| 自动重试放大请求 | 每张图最多 3 次请求 | 仅自动重试 2 次并退避；最终失败后不再自动请求 |
| 单页签改造影响多页签 | 页签顺序或深链失效 | 页签定义集中计算；保留 `?tab=` 初始化；覆盖不同角色 e2e |
| 图片组件破坏 Markdown 排版 | 非法嵌套、间距变化 | 只使用行内元素；保持原圆角、边框、最大宽度和间距 |
| 品牌 Logo 改客户端组件 | 服务端/客户端边界变化 | 仅在有交互的图片兜底中使用；保持原样式与明暗图逻辑 |
| 缓存与审计语义 | 浏览器缓存命中不产生新下载审计 | 只影响重复展示；回源仍写审计；接受该语义并在文档记录 |

回滚：本轮改动可按文件独立回滚；不涉及迁移，回滚后原页面和接口即可恢复。单页签和多页签、图片成功和失败态都应同时覆盖，避免只验证学生无参与这一种情况。

## 12. 待批准决策

1. 单页签时**不显示页签栏**（推荐），而不是保留一个改过样式的单页签。
2. 图片失败采用**自动重试 2 次（1 秒、3 秒）+ 手动重试 + 查看原图**，单次超时 15 秒；不无限加载。
3. 活动附件图片改为 `private, max-age=300` + ETag/304（推荐）；如果更看重即时失效，可改为 60 秒。
4. 本轮一并处理品牌 Logo 与设置页预览的失败兜底（推荐），但不改登录背景和证明材料预览的既有实现。
5. P2 项（附件预览、请求超时、上传进度、编辑态图片）本轮暂缓，另行设计。
6. 实现通过质量门禁后升 0.5.1；是否推送到服务器另行确认。

批准后按第 9 节顺序实施：先单页签和图片组件，再接口缓存，最后品牌兜底与测试、文档。

### 13.2 与设计的差异

1. 自动重试等待期间只显示“网络较慢，正在重新加载图片…”和骨架，不显示操作按钮；连续自动重试耗尽后才显示“再次加载”，避免并发重试。
2. 认证失效只提供“重新登录”；资源不存在只显示原因，不提供无效重试或原图入口。
3. 缓存和 ETag 对全部活动附件生效（图片与 PDF 内联、其他类型下载），不只图片；证明材料仍使用原 `no-store` 策略，不在本轮范围。
4. Next.js 会合并 `Vary`，实际响应为 `rsc, next-router-state-tree, next-router-prefetch, next-router-segment-prefetch, Cookie`；测试按“包含 Cookie”断言，不锁定合并后的完整顺序。
5. “查看原图”和“重新登录”使用按钮触发 `window.open` / 路由跳转，避免在 Markdown 段落内嵌套链接导致非法 HTML。
6. 设置页预览失败不提供原地重试；重新进入或更换资源后恢复，避免预览区增加与业务无关的控件。
7. 首张图片判定基于 Markdown AST 位置；无位置信息的图片按普通延迟加载处理。
8. 自动重试计数在手动重试、网络恢复时清零，允许新一轮两次自动重试；每轮最多 3 次请求。
9. 编辑器内图片、证明材料预览、上传进度及非图片附件链接错误提示仍按批准范围暂缓，不在 0.5.1 交付。
