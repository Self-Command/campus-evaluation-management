# 技术方案讨论

更新：2026-10-19。记录 `/grill-with-docs` 已确认的技术与交付方向，供后续正式规格使用；具体实现与运行验证尚待开发完成。

## 已确认

| 选择 | 当前结论 |
| --- | --- |
| 开发语言与框架 | TypeScript＋Next.js，页面与服务端业务放在同一个项目 |
| 运行时与框架主版本 | 目标采用 Node 24 LTS、Next.js 16、React 19，实施时验证并锁定补丁版本 |
| 页面复用 | 使用 shadcn/ui 的组件与后台布局，按业务组合页面 |
| 首版运行目标 | 本机／局域网答辩演示 |
| 账号来源 | 管理员统一创建／批量导入 |
| 学生登录标识 | 学号＋密码 |
| 交付质量 | 按上线标准开发的生产版本 |
| 数据库 | PostgreSQL |
| 数据访问 | Prisma ORM 7 |
| 认证实现 | NextAuth.js v4 Credentials＋应用用户表，学号密码登录 |
| 证明文件 | 本地受控目录持久化保存，通过鉴权接口访问 |
| 部署方式 | Docker Compose 运行 Next.js 生产构建与数据库 |
| 运维交付 | 环境配置、数据库迁移、持久化、备份与恢复流程 |
| 初始密码与找回 | 管理员建号时生成初始密码，首次登录要求修改，忘记密码由管理员重置 |

架构选择见 [ADR-0001](../adr/0001-nextjs-application.md)，部署选择见 [ADR-0002](../adr/0002-local-production-deployment.md)，官方能力核查见 [技术选型核查](../research/Next.js技术选型-官方资料核查.md)。

## 质量验收

本机／局域网演示使用生产构建及持久化数据。业务权限、密码与会话、输入校验、附件访问、事务去重、学期锁定、精确计分、备份恢复和自动化检查，统一按[现行需求第9节](../requirements/高校综合测评系统-毕设精简方案.md#9-生产交付质量与本地部署)作为交付要求。

## 本地环境检查

已检测到 Node 与 Docker Desktop 命令。检查时 Docker 引擎尚未运行；这不影响需求与规格整理，实施验证前需启动引擎并检查 Compose 服务。当前尚未创建应用容器或数据库。

## 实施选型建议

- 数据访问采用 Prisma ORM 7 的正式版本组合与 PostgreSQL，实施时读取对应版本文档。
- 认证采用 NextAuth.js v4 Credentials，账号由应用保存，以学号查询并校验密码。它使用 JWT 会话，服务端检查账号状态、角色及密码变更后的登录有效性。
- 官方包元数据已确认 NextAuth.js v4 的声明依赖范围覆盖 Next.js 16 与 React 19；Prisma ORM 7 的系统要求覆盖 Node 24。实际生产构建与登录行为仍在实施阶段验证，通过后固定补丁版本并保留锁文件。
