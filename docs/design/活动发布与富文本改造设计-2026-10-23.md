# 活动发布与富文本改造设计

日期：2026-10-23。状态：**已实施（2026-10-23）**。实施与验证证据见[活动发布与富文本改造实施记录](../audit/活动发布与富文本改造实施-2026-10-23.md)。范围：活动发布流程、分值文案、活动介绍富文本与附件、学生活动页。依据现有代码与数据库核查，不改变学期、成绩、申报审核规则。

## 1. 决策摘要

| 需求 | 决策 |
|---|---|
| 学院发布活动 | 学院管理员保存后点「发布」即公开，**取消管理员确认分值环节**；发布时服务端自动置 `confirmed=true` |
| 管理员职责 | 不再做活动审核；保留紧急下架（撤回发布）能力，不进入日常流程 |
| 分数文案 | 所有页面只显示「N 分」，删除「统一」「统一分值」「（统一）」等前缀/后缀 |
| 参加要求 | 删除字段、表单、详情页签、信息流文案、接口与测试；迁移前导出备份后删列 |
| 活动介绍 | 改为富文本，内容以 Markdown 存储；Tiptap 3 + 官方 `@tiptap/markdown` |
| 附件 | 新增活动附件模型与上传/下载接口；系统设置新增 3 项，默认 5 个 / 10MB / 15 种后缀 |
| 学生页签 | 「最新活动」放最左、默认选中；「我参加的活动」保留 |
| 进行中筛选 | 服务端过滤：已发布 + 学期 ACTIVE + `startsAt ≤ 现在 ≤ endsAt` + 学院班级命中 |

## 2. 现状核查（代码事实）

- `src/server/activities.ts` `publishActivity`：要求 `activity.confirmed`，否则报「请先由管理员确认活动分值」；还要求范围预检 token。
- `confirmActivity`：仅 `ADMIN` 可调用；`src/app/api/activities/route.ts` 有 `confirm` 动作。
- `saveActivity` 第 88 行：`confirmed` 后禁止改 `points`/`nodeId`，报「已确认分值变更须通过影响预览与统一更正」，而该更正流程尚未实现。
- `Activity.requirements` 存在于 schema、`activitySchema`、表单、详情页签、信息流卡片、11 处测试。
- 学生页 `my-activities/page.tsx`：页签顺序为「我参加的活动」在前，默认 `joined`；feed 无时间过滤，只要求 `publishedAt + confirmed + 范围`。
- 项目当前没有任何 Markdown/富文本依赖。

## 3. 发布流程改造

### 3.1 目标状态

| 状态 | 条件 | 学生可见 |
|---|---|---|
| 草稿 | `publishedAt = null` | 否 |
| 已发布（进行中） | `publishedAt != null`、学期 ACTIVE、当前时间在起止内 | 是 |
| 已发布（已结束） | `publishedAt != null`、`endsAt < 现在` | 否（信息流不展示，参与记录仍可查） |
| 已撤回 | 曾发布后被撤回，`publishedAt = null` | 否 |

### 3.2 发布

- 权限：`ADMIN`、`COLLEGE`（本院活动）；`PUBLISHER` 仅历史存量。
- 一次点击完成：服务端重新执行范围校验（所选方式非空、学院或班级存在、有符合学生），通过后同一事务写入：
  - `confirmed = true`（保留字段，兼容旧数据）
  - `publishedAt = now()`、`publishRevision + 1`、`revision + 1`
  - `AuditEvent: ACTIVITY_PUBLISHED`，记录分值、计分项、范围人数
- **移除范围预检 token 强制要求**：发布时服务端直接 `inspectAudience`，有错即拒绝；预检接口保留给表单实时提示。
- 撤回：需填理由（现有规则保留），`publishedAt = null`、`publishRevision + 1`，审计 `ACTIVITY_UNPUBLISHED`。

### 3.3 编辑已发布活动

- 学期 `ACTIVE` 阶段，主办学院可编辑全部字段。
- 修改分值、计分项或范围时：自动撤回发布（`publishedAt = null`、`publishRevision + 1`），提示「已修改计分信息，需重新发布」，审计记录前后值与撤回原因。
- 只改名称/时间/介绍/附件时：保持发布状态，不撤回。
- `CHECKING`/`LOCKED` 阶段仍禁止写活动（沿用现有学期锁）。

### 3.4 移除确认环节

- 删除 `confirmActivity` 服务、`/api/activities` 的 `confirm` 动作、活动详情的「确认分值」按钮。
- 活动列表删除「分值状态」列，只保留「发布状态」。
- 活动详情状态文案改为：未发布 / 进行中 / 已结束 / 已撤回；下一步提示相应调整。
- 工作台统计：
  - 管理员：`unconfirmedActivities` → `ongoingActivities`（已发布且进行中），入口「查看活动」。
  - 学院/历史发布者：`unconfirmedActivities` → `unpublishedActivities`（草稿数），文案「未发布活动」。
- 名单导入：可选活动条件由 `confirmed` 改为 `publishedAt != null`，未发布活动不能导入名单。

## 6. 富文本与附件

### 6.2 存储与渲染

- 正文以 **Markdown** 存储，字段沿用 `Activity.content`，长度上限从 5000 提高到 20000 字符。
- 旧纯文本内容天然是合法 Markdown，渲染时加 `remark-breaks` 保留换行。
- 详情页渲染：`react-markdown` + `remark-gfm` + `remark-breaks` + `rehype-sanitize`；禁用原始 HTML，外链 `target="_blank" rel="noopener noreferrer"`。
- 列表/信息流不渲染整篇 Markdown，服务端生成纯文本摘要（`contentText`，去标记、截断 160 字）。
- 支持语法：标题、粗体/斜体/删除线、行内代码、代码块、引用、有序/无序/任务列表、表格、链接、图片、分割线。不支持脚注、定义列表、数学公式（报告中明确，不宣称全语法）。

### 6.3 附件模型

```prisma
model ActivityAttachment {
  id         String   @id @default(cuid())
  activityId String?
  activity   Activity? @relation(fields: [activityId], references: [id], onDelete: Cascade)
  uploaderId String
  name       String
  mime       String
  size       Int
  sha256     String
  storageKey String   @unique
  kind       String   @default("FILE") // IMAGE / FILE
  createdAt  DateTime @default(now())
  @@index([activityId])
  @@index([uploaderId, createdAt])
}
```

- 图片插入正文：使用标准图片语法，地址指向 `/api/activity-attachments/{id}`，详情页内联显示。
- PDF/Office/压缩包等：进入正文下方「附件」列表，显示名称、大小、下载按钮，不塞进 Markdown。
- 存储：`.local/activity-attachments/<yyyy>/<mm>/<随机>.<后缀>`，可用 `ACTIVITY_ATTACHMENT_DIR` 覆盖；数据库只存元数据与哈希。

### 6.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/activity-attachments` | 原始二进制请求体；文件名放 `x-file-name`（URL 编码），可选 `x-activity-id`；返回 id/name/mime/size/url |
| GET | `/api/activity-attachments/{id}` | 鉴权读取；图片/PDF `inline`，其余 `attachment`；`nosniff`、`no-store` |
| DELETE | `/api/activity-attachments/{id}` | 上传者或活动管理者；同时删除文件与记录 |

保存活动时新增 `attachmentIds: string[]`：校验归属（本人上传或该活动已有）、未绑定或属于本活动，事务内绑定；未提交的旧附件保留 24 小时后由清理脚本删除。

### 6.5 系统设置

设置页新增「活动附件」分组，字段与默认值：

| 字段 | 类型 | 默认 | 范围 |
|---|---|---|---|
| `activityAttachmentMaxFiles` | 整数 | 5 | 1–20 |
| `activityAttachmentMaxSizeMb` | 整数 | 10 | 1–50 |
| `activityAttachmentAllowedExtensions` | 字符串数组 | `png,jpg,jpeg,webp,gif,pdf,doc,docx,xls,xlsx,ppt,pptx,zip,txt,md` | 1–20 项，小写、无点 |

- 沿用 `settingsSchema` 严格校验与 `revision` 冲突检查；旧记录缺字段时读取默认值，无需数据迁移。
- 上传接口服务端读取设置执行限制；活动表单服务端读取后把上限传给编辑器显示提示。
- 校验：扩展名白名单 + 真实签名（图片/PDF 魔数、Office/ZIP 的 `PK` 头、文本 UTF-8），不一致拒绝；文件名去路径、随机存储键；单请求体上限 = 单文件上限 + 1MB。

### 6.6 编辑器交互

- 工具栏：撤销/重做、标题、粗体/斜体/删除线、列表、任务列表、引用、代码块、链接、表格、图片、附件。
- 支持拖拽与粘贴上传；上传中显示进度，失败可重试；图片可删除，附件在列表中删除。
- Next.js 下 `immediatelyRender: false`，避免 hydration 不一致；编辑器样式用现有主题 token，不引入新的 UI 框架。

## 7. 学生活动页

- 页签顺序：`最新活动`（feed，默认、最左）→ `我参加的活动`（joined）。
- 默认视图：无 `view` 参数时取 `feed`；`view=joined` 才显示参与记录。
- 标题与说明：页面标题「活动」，说明改为「查看正在进行、面向你所属范围的活动，以及学院已登记的参与记录」。
- 信息流标题「最新活动 · N 项」；空态「当前没有正在进行的活动」。
- 卡片删除「参加要求」行与「统一」前缀；保留分值、时间、主办学院、发布时间。
- 学生工作台入口文案「面向我发布的活动」→「最新活动」，链接仍为 `/my-activities`（默认即最新活动）。

### 7.1 进行中判定（服务端）

信息流查询条件：

1. `publishedAt != null` 且 `confirmed = true`；
2. 学期 `phase = ACTIVE` 且 `disposition = NORMAL`；
3. `startsAt <= now` 且 `endsAt >= now`（含边界，数据库时间为 UTC，展示按 Asia/Shanghai）；
4. 学院命中 `audienceColleges`，班级键命中 `audienceClasses`。

实现上拆成两个条件函数：

- `studentEligibleWhere`：1 + 4，用于活动详情可见性（已结束活动仍可从「我参加的活动」打开）。
- `studentFeedWhere`：1 + 3 + 4，仅用于信息流列表与计数。

`pageDirectory(feed=true)` 先判断学期状态，非 ACTIVE 直接返回空列表，不做前端过滤，保证分页与总数一致。

## 10. 验收要点

1. 学院账号保存活动 → 点发布 → 学生端「最新活动」立即出现，管理员未做任何确认。
2. 已发布活动改分值 → 自动撤回并提示重新发布；审计有前后值。
3. 全站检索「统一」：分数语境为 0 处；「统一账号」「统一登记」等保留。
4. 活动表单无「参加要求」；详情页无该页签；数据库无该列；旧链接不报错。
5. 富文本：标题、列表、表格、代码块、链接、图片、附件上传/下载/删除均可用；刷新后内容不丢。
6. 上传超数量/超大小/非白名单后缀被拒绝，提示具体原因；改设置后立即生效。
7. 学生页默认「最新活动」且在最左；未开始、已结束、已撤回、未发布活动都不出现；已结束活动仍可从「我参加的活动」打开详情。
8. 学期切到 `CHECKING` 后信息流为空；切回 `ACTIVE` 恢复。

## 11. 风险与取舍

- **删除 `requirements` 不可逆**：先导出备份，迁移脚本保留恢复说明。
- **Tiptap Markdown 扩展仍是 early release**：只暴露已验证语法，保存前做 Markdown 往返测试；异常时回退社区版 `tiptap-markdown`。
- **附件存储增长**：本期只做上传/删除与 24 小时草稿清理，不做全量垃圾回收；运维文档补充附件目录备份。
- **只显示进行中**：未开始活动也不展示（按你的要求）。如果以后要展示“即将开始”，把条件改为 `endsAt >= now` 即可。
- **管理员仍有撤回发布权限**：用于违规内容下架，不属于日常审核。
