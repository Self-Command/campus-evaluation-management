# 序衡：界面基线

用户指定 Linear 风格。目标为清晰、克制、可持续扩展的企业级后台；不是复制品牌资产。

## 正式页面交付要求（2026-10-20，后续强制执行）

- 开发时直接实现正式产品页面，开发与生产使用同一套页面、交互和业务文案，不另做测试版或开发占位页。
- 页面不出现“开发预览”“功能开发中”“测试说明”、技术实现说明、开发进度或其他非业务文字。环境信息与测试结果仅放在文档、任务记录或沟通中。
- 以完整页面和真实业务交互交付；不以假按钮、虚构数据、占位功能或说明卡片代替实际功能。未实现功能不包装成可用入口。
- 正常业务空状态、加载、错误、权限和表单校验提示必须保留，文案只说明业务状态及用户下一步操作。
- 用户明确本次不改已完成页面；新页面和后续修改执行本规范。

## 视觉与交互基线

- 白色内容面、浅灰侧栏、细分割线；紫色主操作使用语义化 `primary` 变量。
- 桌面固定侧栏与紧凑顶栏；正文限制宽度，标题、说明、操作和状态层次明确。
- 常规正文12–14px，页面标题24px，登录主标题适度放大；本地系统字体，无外部字体请求阻塞启动。
- 基础控件优先使用官方 shadcn/ui Base UI 组件，配置见 `components.json`；已安装官方技能，遵循 FieldGroup/Field、Alert、Badge、Empty 等组合规则。
- 表单有真实标签、浏览器自动填充、必填校验、密码输入、提交等待与可读错误；键盘焦点使用统一 ring。
- 页面权限不依赖隐藏按钮。导航按角色显示；后续未实现功能不提供假入口，不展示开发进度标签，不伪造数据。
- 移动端折叠侧栏、表单保持可用，避免横向滚动。后续完整业务导航仍需补充移动端菜单的可访问名称和交互。
- 业务状态变化通过文本解释，不只依赖颜色；不加入无意义动画、图表或 KPI。

开发中的控件与布局要以浏览器观察和用户反馈验证；这份基线不等同已完成全站可访问性审计。
