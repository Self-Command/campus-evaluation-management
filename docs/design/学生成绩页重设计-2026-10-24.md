# 学生成绩页重设计

日期：2026-10-24。范围：`/results` 学生本人视图；管理员查询同一学生时沿用结构，保留查询、返回名单和导出入口。本文是实施前的界面与文案契约，实施与验收结果另见审计记录。

## 1. 目标

学生打开页面后，先得到四个结论：这次多少分、算不算最终成绩、班里排第几、现在要不要做什么。分数依据按需展开，默认不铺满整页。

原页面的具体问题：

- 总分在概览、根卡片、说明卡和结论句里重复出现。
- 每个计分节点一张卡，桌面高度超过三个视口，移动端超过四个视口，零分项同样占篇幅。
- 解释区不跟随滚动；移动端位于整棵树之后，点击节点后看不到任何反馈。
- 活动名称是裸下划线链接，申报记录直接显示内部字段 `factKey`。
- 成绩版本、发布批次和更新时间进入主信息流，但没有对应动作。
- 确认按钮不判断发布时是否要求确认，也不判断核对是否已截止。

## 2. 信息架构

单页滚动，不设页签。四个区块依次回答七类问题：

| 区块 | 回答 | 主要内容 |
| --- | --- | --- |
| 成绩概览 | 多少分、是否最终、排名、确认、截止、下一步 | 总分一次、状态徽标、四项指标、与状态匹配的操作 |
| 得分构成 | 分是怎么来的 | 单层分隔列表、按需展开的层级、选中项说明 |
| 计分依据 | 凭什么给我这个分 | 活动与成果、成绩录入、扣分三组记录，详情内查看材料与变更 |
| 成绩说明 | 这是哪一版、找谁 | 方案版次、发布批次、截止与确认时间、职责说明 |

### 2.1 成绩概览

- 顶部一行：`综合测评成绩`、周期名、姓名、学号、学院、班级。
- 徽标：`最终成绩` / `暂计成绩` / `当前成绩`，以及发布批次 `第 N 版`。
- 大号数字只出现一次：完整时为总分，未完整时为暂计分。单位固定为「分」，数字使用 `tabular-nums`。
- 未完整时显示一条警告，列出未录入项名称，并说明当前是暂计成绩。
- 四项指标：班级排名、成绩状态、确认状态、核对截止。
- 操作按状态出现：
  - 核对中、要求确认、未确认、未截止：`确认成绩`。
  - 核对中、未截止：`提出异议`。
  - 其他情况：`查看计分依据` 锚点。
  - 始终提供 `导出我的成绩单` 与 `成绩说明`。
  - 无发布版本时不显示异议入口；已锁定或已截止不显示确认、异议等不可执行按钮。
- 确认使用确认对话框，不再使用浏览器原生 `confirm`。
- `成绩说明` 对话框承载方案版次、成绩更新次数、发布批次、发布时间、核对截止、确认要求、确认时间和职责说明；发布过结果时提供 `查看我的异议` 入口。

### 2.2 得分构成

- 不显示根节点「综合测评成绩」行，直接展示根节点下的顶级模块。
- 使用一个分隔列表，不再为每个节点套 Card；层级用缩进和左侧竖线表示，最多缩进两级。
- 每行只有三部分：名称、一句说明、分数（未录入显示「未录入」）。
- 顶级模块默认展开，直接子项可见；更深层级默认折叠。展开状态通过行尾箭头和 `aria-expanded` 同时表达。
- 完整且整枝为零的节点合并为 `未得分项` 行，显示项数，默认折叠；未录入项不进入零分分组。
- 点击任意行选中该项：桌面端在右侧固定说明卡显示，窄屏在选中行下方就地显示。
- 说明卡先说明这项是什么，再列直接组成项和真正发生的计算步骤；没有封顶、折算、扣分或最低分时不生成对应句子，不在解释里重复总分。
- 不出现「子模块」「本模块」「计入上级」「下限前」「汇总模块」「权重系数」等实现术语。

### 2.3 计分依据

三组清单，每组显示条数：

1. **活动与成果**：名称、计分模块、分值、通过或发生时间、状态。详情包含审核说明、证明材料、活动入口（有活动时）。
2. **成绩录入**：计分项、分值、更新时间，详情包含变更历史入口。
3. **扣分**：扣分项目、实际扣分、计分模块、事由、更新时间，详情包含扣分变更历史。

- 每行只保留一个 `查看` 按钮；证明预览和变更历史收进详情对话框。
- 文件名称在列表中截断，详情中可完整查看或下载。
- 不显示 `factKey`、记录 ID、接口地址等内部字段。
- 活动名称不再作为裸链接；需要跳转时使用带文字的按钮。
- 空组显示明确的「暂无」说明，不生成占位记录。

### 2.4 成绩说明

页面底部保留小字说明：辅导员负责录入与更正，学院负责审核，学校负责发布；导出表格用于留存，系统显示为准。

## 3. 文案规则

1. 句子短，先说结论，再说原因；不使用系统内部词汇。
2. 数字统一两位小数并带「分」；缺失写「未录入」。
3. 状态词统一：录入中、核对中、已锁定、已发布、已确认、待确认、无需确认、已截止、未发布。
4. 比例用「占「基础性素质」的 80%，折合 60.72 分」表达，不写权重系数。
5. 每个操作名称说明结果，例如 `导出我的成绩单`、`查看计分依据`，不出现「点击这里」。

## 4. 模板与组件来源

| 区块 | 模板来源 | 适配方式 |
| --- | --- | --- |
| 页面骨架 | `D/profile/page.tsx` | 保留页头、分段和响应式网格；移除页签 |
| 成绩概览 | `D/profile/_components/profile-header.tsx`、`profile-overview.tsx`、`D/users/_components/users.tsx` | 页头信息、状态徽标、指标 `dl` 和 Card 头部组合 |
| 得分构成 | `D/profile/_components/profile-personal-details.tsx`、`D/users` 的 Card 列表 | 分段标题、分隔列表、右侧说明卡；不新增视觉体系 |
| 计分依据 | `profile-personal-details.tsx` 的属性分组、`D/invoice/_components/invoice-preview.tsx` | 三组清单、详情对话框、证明预览 |
| 成绩说明 | `profile` 详情分段与 `D/invoice` 预览容器 | 小字说明区和版本对话框 |

仅使用项目已安装的 Base UI / shadcn 组件；不新增第三方视觉依赖。

## 5. 状态与边界

| 状态 | 展示 |
| --- | --- |
| 录入中、未发布 | 显示当前成绩；排名「发布后可查」；确认「未发布」；隐藏确认与异议 |
| 未完整 | 显示暂计分和缺失项；不把缺失当 0 分展示 |
| 核对中、要求确认、未确认 | 显示待确认和截止时间；提供确认、异议 |
| 核对中、无需确认 | 确认状态「无需确认」；不显示确认按钮 |
| 核对中、已确认 | 显示确认时间；仍可在截止前提异议 |
| 核对中、已截止 | 不显示确认、异议；提示联系辅导员更正 |
| 已锁定 | 只读；保留依据、版本和导出 |

学生没有改分入口；更正由辅导员提交、学院审核。

## 6. 响应式与可访问性

- ≥1280px：得分构成左列表、右固定说明卡；说明卡在滚动时保持可见。
- 768–1279px：列表在上，说明随选中行就地显示。
- <768px：全部单列，无横向滚动；主操作和行按钮触控高度不小于 44px。
- 行使用按钮语义，展开状态写入 `aria-expanded`；选中状态同时用背景和文字表达，不只靠颜色。
- 数字使用 `tabular-nums`；不在悬停时才显示关键信息。

## 7. 验收标准

1. 首屏能回答总分、最终性、排名、确认状态、核对截止和下一步。
2. 总分在页面中只出现一次。
3. 零分项默认折叠；默认页面高度桌面约 2–2.5 个视口，移动端不超过 4 个视口。
4. 点击任意计分行，桌面右侧或移动端行下出现对应说明。
5. 页面无 `factKey`、无下划线裸链接、无内部 ID。
6. 三组计分依据均有真实空态；详情可查看材料和变更历史。
7. 核对中、已截止、已锁定状态下操作按钮与规则一致。
8. 移动端无横向滚动，主操作可触控。
9. 类型检查、lint、集成测试和浏览器结构断言通过；截图由用户最终验收。

## 8. 实施状态

2026-10-24 已按本方案实施并通过类型检查、lint、集成测试和浏览器结构断言。实施细节、截图路径、页面高度和状态边界见[学生成绩页重设计实施与验证](../audit/学生成绩页重设计实施与验证-2026-10-24.md)。

一处文案调整：周期进行中、分数已录齐时，总分下方改为“各项分数已全部算出，发布后可确认”。原拟“成绩已完整录入”与指标“成绩状态：录入中”并列时，容易被理解为周期已结束，故按用户视角改为描述个人分数状态。其余结构与状态规则不变。
