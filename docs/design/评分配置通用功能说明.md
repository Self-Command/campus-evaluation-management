# 独立通用评分功能与学校首版模板

2026-10-19。当前属于设计、配置与计算验证，尚未完成Web应用开发。

## 一、独立功能的职责

评分功能接收三类数据：一棵已校验的评分模块树、每个输入节点的已认定原始数值、显示精度配置。返回总分以及每个节点的原始汇总、封顶、折算、扣分和最终结果。

它不负责登录、活动发布、审核、读取Excel或按学校名称选择计算分支。活动认定及成绩导入先提供原始分，评分功能只按配置计算。导入列、导出列和学校模块名称都是模板数据。

同一个计算功能可使用本校模板，也可使用另一所学校创建的模板。首版一个学期全体学生使用同一套生效配置，角色仍为学生、活动发布者、管理员。

## 二、最小通用能力

| 能力 | 管理员设置 | 用途 |
|---|---|---|
| 任意实际层级 | 添加子模块 | 模块、子模块、子子模块……不固定业务层数 |
| 原始分直接相加 | 汇总方式选“直接累加” | 多个活动板块原分相加，不强制填比例 |
| 按比例汇总 | 汇总方式选“按比例”，为直接子模块填比例 | 同一父模块下的比例合计100% |
| 节点上限 | 在任意节点填上限，可留空 | 先合计本节点，再封顶；不限于最底层 |
| 可选百分制折算 | 需要时启用，填写原始满分与目标满分 | 不默认把所有模块归一化；本校模板关闭 |
| 扣分 | 管理员录入正数扣分额，绑定要扣减的节点 | 本校在加权总分之后按100%扣减 |
| 可选下限 | 需要时填最低分，可留空 | 本校原表没有0分下限公式，模板不擅自添加 |

“30分上限”和“30%权重”是不同参数。直接累加模式的下级不要求比例合计100%；只有按比例模式才检查该约束。

## 三、统一计算顺序

对每个节点自底向上执行：

```text
1. 输入节点取已认定原始数值；汇总节点按直接累加或比例汇总取得数值。
2. 若配置了上限，则在该节点封顶。
3. 若明确启用满分折算，再按配置进行折算。
4. 减去挂在该节点的扣分额；扣分可配系数。
5. 若配置了下限，再应用下限。
6. 将本节点结果交给父模块，父模块根据自身汇总方式处理。
```

每个父模块只取直接下级的结果，不再把其原始明细、小计和展示用比例分重复相加。仅最底层接收活动或成绩，汇总节点不再录入额外分数。

如果别的学校要求不同的封顶或扣减位置，通过把上限或扣分放到对应中间节点表达，不按学校写特殊判断。需要超过这组操作的制度时再扩展明确的通用运算，不让管理员写任意代码。

模块以父子关系保存，计算采用迭代后序遍历，不固定业务层数；实际容量受资源限制，不承诺真正无限的数据。禁止循环、重复节点标识、跨方案关联、空汇总节点和未配置来源的输入节点。新增子模块时，原有输入数据必须明确迁移，不能丢失。

## 四、本校首版预置配置

具体配置保存在[学校评分模板](../examples/学校评分模板.json)。管理员可直接套用、查看和修改；不需要自己写公式。

```text
总评：按比例汇总以下两项，再减纪律扣分
├─ 基础性素质：80%
│  ├─ 红色文化引领工程：10%
│  │  ├─ 思想引领活动
│  │  ├─ 培训学习经历
│  │  ├─ 学生入党
│  │  └─ 道德品质
│  │  以上四项原分直接相加，封顶100分
│  ├─ 学业成绩：80%
│  └─ 体育素质：10%
└─ 发展性素质：20%
   ├─ 志愿服务实践工程：三个子项原分相加，封顶30分
   ├─ 人文素质提升工程：三个子项原分相加，封顶30分
   └─ 卓越工匠培养工程：三个子项原分相加，封顶40分
   三个工程的封顶后原分直接相加
```

表达式如下，表达式用于说明，后台由上面的配置自动生成：

```text
红色文化 = min(思想引领 + 培训学习 + 学生入党 + 道德品质, 100)
基础贡献 = (红色文化×10% + 学业×80% + 体育×10%)×80%

志愿工程 = min(社会实践 + 劳动实践 + 社会公益, 30)
人文工程 = min(基础素养 + 文体素养 + 心理素养, 30)
工匠工程 = min(职业素养 + 双创精神 + 管理能力, 40)
发展贡献 = (志愿工程 + 人文工程 + 工匠工程)×20%

总评 = 基础贡献 + 发展贡献 - 法制与校规校纪扣分
```

红色文化封顶100来自原表表头；总分扣减及其100%位置来自已读取的AI列公式。发展性不再加一遍T、Y、AD等展示用比例分。学校模板不默认开启百分制归一化，不把30／30／40自动当成三个内部百分比。

本校参考列映射作为独立导入／导出配置保存，不参与评分算法。导出H、S、X、AC等小计和I、T、Y、AD等比例分时，读取相应节点的结果或乘展示系数；展示列不会反向成为重复计分输入。

## 五、管理员实际使用

首版先提供“套用本校模板”。管理员检查模块树、分值上限、比例和扣分位置后开启学期，再配置具体活动的所属最底层模块及统一分值。

日常只需发布活动、导入参与名单与共享证明、审核个人申报、导入学业体育成绩、登记纪律扣分。活动对所有被认定参与学生使用同一分值，不恢复多套学生方案和复杂角色。

如学校以后修改某个工程上限或比例，只修改配置，预览差异后全体统一重算。修改已结算学期需管理员填写理由并重新发布锁定，保留日志和锁定结果备份。

具体活动每次加几分、哪些证书加几分、违纪单次扣几分不在该汇总表中。系统提供可配置加分项目与扣分记录，不编造这些具体制度值。

## 六、已完成的验证及其边界

- 只读提取原XLS的566条公式记录，并展开22组共享公式；全部566个数值缓存与独立公式重算一致，原文件未改动。
- 用当前51行输入对学校配置计算结果与原表AI列缓存对账一致；其中只有1行存在非零输入，不能只靠这次对账证明边界正确。
- 补充封顶、加权、独立扣分、满分等固定样例，以及1000组模拟输入，与独立控制公式核对一致。
- 使用另一套模块和折算配置验证可复用；计算验证脚本在1500层模拟树上也完成迭代求值。这是算法样例，不是实际界面容量承诺。
- 原表存在部分行重复汇总、漏小计公式和未执行表头封顶的问题，见[学校评分模板-公式核查](../research/学校评分模板-公式核查.md)。学校模板按表头与一致的汇总结构表达，不复制行号相关错误。

这些验证证明当前配置模型可以表达该表所需的汇总机制，不等于整个Web系统已经实现或已经通过真实学校业务验收。具体制度与模板仍需在正式投用前由学校核准。
