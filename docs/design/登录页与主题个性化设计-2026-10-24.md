# 登录页全屏背景、主题个性化与设置补齐设计

日期：2026-10-24。状态：**已实施，本地视觉与逻辑验收通过**。用户已批准设计与实施顺序；本文保留设计依据，实施结果、验证证据和部署状态见第 8 节及[验收记录](../audit/登录页与主题个性化实施与验证-2026-10-24.md)。批准前查看的静态原型保存在[原型目录](../prototypes/index.html)，仅用于视觉评审，不代表真实表单交互。

关联文档：[管理员设置中心](../features/15-管理员设置中心.md)、[管理员配置矩阵](管理员配置矩阵.md)、[界面设计规范](界面设计规范.md)、[模板来源与适配清单](模板来源与适配清单.md)。

## 1. 结论

1. 登录页改为**全屏背景图 + 居中登录卡片**，保留项目真实的登录能力：登录身份、学号/账号、密码、五位字母验证码、错误与等待状态。不添加手机登录、第三方登录、注册、记住账号、忘记密码等未实现入口。
2. 登录页与强制改密页共用同一套认证页外壳，品牌、背景、主题控件只实现一次。
3. 主题改为**站点默认 + 个人偏好**两层：
   - 管理员设置全站默认主题风格与默认深浅模式；
   - 所有角色都可以在登录页和登录后的顶栏直接切换深浅模式与主题风格；
   - 个人选择只影响当前浏览器，不改变站点默认，不影响权限、数据和计分。
4. 管理员可以在设置页上传、预览、移除登录页背景图；登录页与改密页同步生效。
5. 本轮同时补齐已经实现的 Logo 显示尺寸设置（不小于 16 像素，不设上限，按高度预算保持原始宽高比）并纳入同一版本；修复公开设置接口直接返回完整设置对象的问题，改为显式白名单。
6. 证明上传限额、维护模式、页脚备案等属于下一批或运维配置，本报告单列原因，不在本轮用“可配置”弱化安全边界。

## 2. 参考图取舍

参考图提供的是视觉方向：全屏校园背景、品牌标识、右侧/居中半透明登录卡、顶部主题入口、底部学校信息。实际实现只采用这些视觉原则，不复制参考图中的插画、校名、菜单、公告、二维码、第三方登录或“记住账号”。

| 参考图元素 | 本项目处理 |
|---|---|
| 全屏背景与校园氛围 | 保留；背景可由管理员上传，未上传时使用主题化渐变背景 |
| 居中/右侧半透明卡片 | 采用**居中卡片**，桌面与移动端一致；卡片使用 shadcn Card 与主题语义 token |
| 顶部品牌与天气/菜单 | 保留品牌标识与站点名称；不添加天气、校园导航等无数据入口 |
| 账号/手机/验证码页签 | 只保留真实登录方式，不做假页签 |
| 记住账号、忘记密码 | 不添加；保留“账号由学校统一分配，忘记密码请联系管理员”的真实说明 |
| 第三方登录 | 不添加 |
| 底部公告/版权 | 本轮增加可选的管理员登录公告；不伪造公告内容，不写虚假版权 |

## 3. 登录页与改密页

### 3.1 布局

桌面与移动端使用同一结构，移动端只压缩间距和品牌文字，不改变信息顺序。

```text
┌────────────────────────────────────────────────────┐
│ [Logo] 站点名称                         [外观调整] │
│                                                    │
│                ┌──────────────────────┐            │
│                │ 欢迎登录              │            │
│                │ 站点名称 · 综合测评   │            │
│                │ ┌──────────────────┐ │            │
│                │ │ 登录公告（可选）  │ │            │
│                │ └──────────────────┘ │            │
│                │ 登录身份  [学生 ▼]   │            │
│                │ 学号或账号 [______]  │            │
│                │ 密码       [______]  │            │
│                │ 图片验证码 [______]  │            │
│                │ [验证码图片] [换一张]│            │
│                │ [        登录        ]│            │
│                │ 账号由学校统一分配…  │            │
│                └──────────────────────┘            │
│                                                    │
│ 站点说明                                           │
└────────────────────────────────────────────────────┘
```

- 外层：`min-h-dvh`，背景层固定铺满，内容层可滚动；小屏不横向溢出。
- 卡片：`w-full max-w-[27rem]`，`rounded-2xl`，半透明卡色，高斯模糊、不透明度、饱和度和外发光由站点设置控制（默认 24px / 80% / 145% / 65）；使用遮罩渐变描边与柔和极光层，`shadow` 保留但移除额外 ring；沿用模板 CardHeader/CardContent 结构。
- 品牌区：左上角只显示已上传的 Logo；未上传 Logo 时显示默认图标、站点名称和说明，避免图案与文字重复挤压。
- 主题入口：右上角，按钮始终可见；弹层使用 shadcn Popover，不遮挡表单输入。
- 底部：显示站点说明，不写虚构版权、备案号或开发信息。
- 登录卡片标题使用“欢迎登录”，副标题为“输入学校分配的学号或账号及密码，进入综合测评工作台。”；底部说明为“账号由学校统一分配。如忘记密码，请联系管理员重置。”，不使用参考图的“统一身份认证平台”等不实描述。

### 3.2 背景

- 管理员上传背景后：`next/image` 填充容器，`object-cover`，优先加载；上方叠加渐变遮罩，保证品牌文字与卡片对比度。
- 未上传背景时：使用主题语义色生成深色渐变 + 细网格的默认背景，不请求外部图片，不依赖第三方图库。
- 背景变更只影响登录页与改密页；不改变后台页面背景。
- 上传图片会公开可见，设置页明确提示不要上传含学生姓名、成绩、证件等敏感信息的图片。

### 3.3 表单与交互

保留现有真实能力：

- 登录身份：学生、辅导员、二级学院、管理员；
- 学号/账号、密码；
- 五位英文字母验证码、点击验证码或“换一张”刷新；
- 提交等待、字段校验、验证码过期、登录锁定、凭据错误、网络错误；
- 修改密码后的成功提示；
- 登录成功跳转工作台；首次登录或重置后强制进入改密页。

明确不做：

- 手机号登录、二维码登录、第三方登录；
- 注册、忘记密码自助流程；
- “记住账号/记住我”；
- 演示账号、测试说明、开发标记；
- 任何不经过真实 API 的假按钮或假公告。

### 3.4 改密页

- 复用同一认证外壳、背景、品牌和主题控件。
- 标题按状态显示“设置新密码”或“修改密码”；说明保持现有业务文案。
- 保留返回工作台入口（非强制改密时）。

## 4. 主题个性化

### 4.1 双层模型

| 层 | 谁设置 | 存储 | 作用范围 |
|---|---|---|---|
| 站点默认主题风格 | 管理员 | `SiteSettings.themePreset` | 未选择个人主题的访客与用户 |
| 站点默认深浅模式 | 管理员 | 新增 `SiteSettings.defaultThemeMode` | 未选择个人模式的访客与用户 |
| 个人主题风格 | 所有角色 | 浏览器 cookie `theme_preset` | 当前浏览器 |
| 个人深浅模式 | 所有角色 | 浏览器 cookie `theme_mode` | 当前浏览器 |

个人选择不写入账号、不跨设备同步、不影响站点默认。管理员要改变全站默认，仍需在设置页保存；管理员自己的个人选择也只影响自己的浏览器。

### 4.2 生效链路

```text
管理员保存默认值
        ↓
服务端 <html data-theme-preset data-theme-mode> 输出默认值
        ↓
ThemeBootScript 在 hydration 前读取个人 cookie
        ↓
有合法个人值 → 覆盖；无 → 使用服务端默认值
        ↓
PreferencesStore 同步按钮与弹层状态
        ↓
用户切换 → 立即应用 + 写 cookie（主题偏好保留 365 天）
```

关键改动：

- `theme_preset` 的持久化方式从 `none` 改为 `client-cookie`；
- `ThemeBootScript` 不再无条件忽略个人主题，改为“个人 cookie 优先，服务端默认兜底”；
- 移除 `PreferencesStoreProvider` 在 hydration 后强制写回管理员默认主题的逻辑；
- 根布局的 `data-theme-mode` 改为读取 `defaultThemeMode`，不再固定 `light`；
- 保留 `suppressHydrationWarning`，避免服务端默认与个人偏好不同造成水合告警；
- 主题 cookie 过期时间从默认 7 天延长到 365 天，其他界面偏好维持现状。

### 4.3 控件

**登录页/改密页**

- 右上角“外观”按钮，打开 Popover。
- 深浅模式：浅色 / 深色 / 跟随系统，使用 ToggleGroup 或等价按钮组。
- 主题风格：九个预设的色块 + 名称，当前项有 `aria-pressed`/选中态。
- “恢复站点默认”：清除个人主题 cookie，恢复管理员默认值并刷新。

**登录后顶栏**

- 所有角色在现有“界面外观”弹层中增加：
  - 深浅模式；
  - 主题风格；
  - 恢复站点默认；
  - 原有内容布局、导航样式保持不变。
- 不新增独立设置页，不把主题选择放入只有管理员可见的页面。

### 4.4 可访问性与视觉

- 按钮有可读名称，弹层可用键盘打开/关闭，焦点返回触发器。
- 主题色块不只靠颜色表达选中，附文字和选中标记。
- 切换深浅模式不改变布局尺寸；登录卡片在两种模式下均保持对比度。
- 不支持任意 CSS、外部主题包或用户上传主题；只接受预设枚举。

## 5. 管理员登录背景与登录公告

### 5.1 新增字段

| 字段 | 类型与范围 | 默认值 | 公开 | 说明 |
|---|---|---|---|---|
| `loginBackgroundAssetId` | 可空字符串 ≤100 | `null` | 是（仅资源 ID） | 登录页/改密页背景图；必须是已存在的品牌资源 |
| `defaultThemeMode` | `light` / `dark` / `system` | `light` | 是 | 站点默认深浅模式；个人 cookie 可覆盖 |
| `loginNotice` | 字符串 0–200 | 空 | 是 | 登录卡片内公告，纯文本，不支持 HTML/链接 |
| `loginCardBlur` | 整数 0–40（px） | `24` | 是 | 高斯模糊强度；0 为清晰，卡片仍保持半透明 |
| `loginCardOpacity` | 整数 20–95（%） | `80` | 是 | 卡片底色不透明度；越低越透出背景，需保证文字对比度 |
| `loginCardSaturation` | 整数 100–200（%） | `145` | 是 | 玻璃后方背景的饱和度增强 |
| `loginCardGlow` | 整数 0–100 | `65` | 是 | 渐变描边与外发光强度；0 仅保留细描边 |
| `loginCardGlowTone` | `theme` / `aurora` / `sunset` / `ocean` | `theme` | 是 | 光晕色调；`theme` 跟随当前主题色，其余为固定色相 |

`logoSize`（整数 ≥16，默认 28，旧设置缺失按 28 读取）按**高度预算**生效：Logo 保持原始宽高比，宽度受容器约束；不再设置 128 像素上限。登录页还叠加 18vh 高度保护，侧栏折叠时按 32×32 裁切显示。

### 5.2 背景上传约束

- 文件类型：PNG、JPEG、WebP；真实文件签名校验；**不接受 SVG、HTML、外链或脚本**。
- 体积：≤5MB（Logo/favicon 仍为 ≤1MB）。
- 尺寸：建议横版 1920×1080 以上；服务端对可解析格式限制最大边不超过 8192 像素，避免异常大图。
- 存储：复用 `BrandAsset` 表，不新增表、不做数据库迁移；保存字节、MIME、大小、SHA-256。
- 读取：`GET /api/brand-assets/[id]`；只有被站点设置引用的资源才允许匿名读取，其他资源仍需管理员会话。
- 响应头：`X-Content-Type-Options: nosniff`、受限 CSP；不返回原始文件名或存储路径。
- 审计：上传写入 `BRAND_ASSET_UPLOADED`，记录用途、MIME、大小、资源 ID，不记录字节内容。
- 替换/移除：只改设置引用，不物理删除旧资源；避免历史审计断链。资源数量上限沿用 200。
- 上传后仍需“保存并生效”；上传回调不覆盖其他页签的草稿，保存失败保留输入。

### 5.3 登录公告

- 纯文本，最多 200 字符，保留换行，不支持 Markdown、HTML、链接和脚本。
- 为空时登录卡片不显示公告区域，不出现“暂无公告”等噪音。
- 设置页说明其公开可见，不得填写学生个人信息。

### 5.4 登录玻璃卡片与渐变光晕

- 管理员在“登录页”页签调整四个滑杆：高斯模糊 0–40px（默认 24）、不透明度 20–95%（默认 80）、饱和度 100–200%（默认 145）、光晕强度 0–100（默认 65），并从主题色/极光/日落/深海中选择光晕色调。
- 卡片使用 `color-mix` 生成半透明卡色，`backdrop-filter: blur(...) saturate(...)` 实现真实背景模糊；所有参数与色调写入 CSS 自定义属性，登录页、首次改密页和设置预览共用同一实现。
- 渐变描边通过双层遮罩（`mask-composite: exclude`）实现，只保留 1px 边缘；外发光由独立的 `conic-gradient` 极光层加模糊生成，强度随光晕参数变化，0 时关闭外发光但保留细描边。
- 主题色随当前深浅模式与主题预设变化，三种固定色调在深浅模式下保持稳定；边框亮部与暗部均使用当前色调混合白色，避免高饱和描边显得廉价。
- 设置页右侧预览与真实登录卡使用相同参数和色调，保存后同步生效；个人浏览器主题不改变站点玻璃参数。
- 四个数值字段和色调均进入公开设置白名单；旧设置缺失时按默认值读取，无需数据库迁移。

### 5.5 设置页结构

在现有“品牌与标题 / 标识与主题 / 登录安全 / 活动附件”基础上增加“登录页”页签：

| 页签 | 内容 |
|---|---|
| 品牌与标题 | 站点名称、站点说明、页面标题（现有） |
| 标识与主题 | Logo、favicon、Logo 显示尺寸（≥16，不设上限）、默认主题风格、默认深浅模式 |
| 登录页 | 背景图上传/替换/移除、16:9 预览、玻璃卡片四项参数、光晕色调、登录公告 |
| 登录安全 | 登录失败限制（现有） |
| 活动附件 | 数量/大小/后缀（现有） |

- 背景预览使用与登录页相同的背景裁切方式、遮罩和卡片轮廓，显示当前草稿的站名、Logo、公告与主题；表单区域使用静态骨架，不提交真实登录。
- 默认主题与默认模式的说明明确写“用户仍可在登录页或顶栏自行选择”。
- 校验失败时定位到对应页签和字段；保存继续携带 `revision` 与 2–500 字理由。
- 设置页顶部的“有未保存修改”和离开确认继续覆盖上传中状态。

## 6. 数据、接口与安全

### 6.1 公开设置白名单

当前 `GET /api/settings/public` 直接返回完整设置对象，包含登录失败策略和活动附件策略；这与设置文档中“公开只返回品牌必要字段”的约定不一致。本轮改为显式投影，只返回：

```text
siteName, siteDescription, pageTitle, themePreset, defaultThemeMode,
logoAssetId, logoSize, faviconAssetId, loginBackgroundAssetId, loginNotice,
loginCardBlur, loginCardOpacity, loginCardSaturation, loginCardGlow,
loginCardGlowTone
```

管理员接口继续返回完整设置与 `revision`；服务端内部读取活动附件、登录策略时使用完整设置读取函数。

### 6.2 接口

| 接口 | 变更 |
|---|---|
| `GET /api/settings/public` | 白名单投影，新增三个公开字段 |
| `GET /api/admin/settings` | 返回新增字段与完整设置 |
| `PUT /api/admin/settings` | 严格 schema；校验背景资源存在；revision 冲突 409；审计 |
| `POST /api/admin/brand-assets` | 支持 `x-asset-kind: login-background`；按用途限制 5MB/1MB 与格式；默认 `brand` |
| `GET /api/brand-assets/[id]` | 公开资源集合加入登录背景；其他仍限管理员 |

- 不新增数据库表；设置仍存 `SiteSettings.content` JSON。
- 旧设置缺失新字段时读取默认值；非法旧主题值继续回退 `default`。
- 背景资源引用在保存事务内复核；资源被删除或不存在时拒绝保存。
- 公开接口不返回登录失败次数、锁定分钟数、附件策略、审计信息或任何密钥。
- 登录公告以 React 文本节点渲染，不使用 `dangerouslySetInnerHTML`。

### 6.3 审计

- `SETTINGS_CHANGED` 的 before/after 包含新增字段；只记录资源 ID，不记录图片字节。
- `BRAND_ASSET_UPLOADED` 增加用途字段，便于区分 Logo、favicon 与登录背景。
- 不把密码、会话、数据库连接、SMTP/短信凭据写入设置或审计。

## 7. 缺失设置盘点

### 7.1 本轮补齐

| 能力 | 现状 | 本轮 |
|---|---|---|
| 登录页背景 | 无 | 新增上传/预览/移除 |
| 站点默认深浅模式 | 固定 light | 新增 `defaultThemeMode` |
| 个人主题选择 | 主题风格被服务端默认强制覆盖，顶栏只有深浅循环 | 登录页与顶栏均可选深浅 + 风格；个人优先 |

### 7.3 明确不开放为管理员设置

| 项 | 当前值/位置 | 原因 |
|---|---|---|
| 会话时长 | 8 小时，`src/server/auth.ts` | 安全边界；缩短/延长需结合部署策略，不能由业务页面随意改 |
