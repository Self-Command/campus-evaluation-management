# 我的成绩页重设计（用户视角）

日期：2026-10-22。范围：`/results` 学生本人视图（管理员查询同一学生时沿用同一结构，多一个返回名单入口）。本文件是设计与文案契约，实施与验证另行记录；当前页面尚未按本设计改写。

## 一、问题复盘

现有页面按「系统实现」而不是「学生要办的事」组织：

1. 首屏先给学号、头像、版本号，学生最想看的「我这次多少分、排第几」被压在下面。
2. 模块得分页签里，左侧把所有层级平铺成一列按钮，右侧再列「汇总 → 封顶 → 折算 → 扣分 → 最低计入分 → 计入上级」，都是实现术语。
3. 文案出现「子模块」「本模块」「计入上级」「下限前」等内部叫法，学生需要先学一套系统词汇。
4. 总分、排名、完整性、发布状态、核对确认、异议入口分散在不同页签和不同页面。

参考做法（不照搬视觉）：Moodle 的成绩报告把「总分 → 各分项 → 每项怎么算」按同一顺序展开，学生先看结果再看依据（[Moodle grader report](https://help.jamk.fi/moodle/en/new-moodle-user/grader-report-basics-in-moodle/#site-content)）；后台仪表盘把「关键数字卡片 + 明细区」作为固定结构（[satnaing/shadcn-admin 仪表盘结构](https://deepwiki.com/satnaing/shadcn-admin/7.4-dashboard-and-analytics#1)）。本项目模板同属这一族，故结构沿用 Card 组合，只重排信息与文案。

## 二、用户要回答的问题（按优先级）

| 优先级 | 学生会问 | 页面必须一眼给出 |
|---|---|---|
| 1 | 我这次总分多少？ | 大号总分 + 单位「分」+ 是否最终 |
| 2 | 算完了吗？ | 已完整 / 还差哪几项没录 |
| 3 | 我在班里什么水平？ | 名次 / 参评人数（发布后才有） |
| 4 | 分是怎么来的？ | 每个得分项的数值 + 一句话算理 |
| 5 | 凭什么给我这个分？ | 活动、成果、成绩、扣分的依据与材料 |
| 6 | 我有疑问怎么办？ | 核对确认 / 提异议的按钮与状态 |
| 7 | 这是哪一版？ | 周期、发布批次、更新时间 |

## 三、页面结构（单页滚动，四个区块）

不使用页签套页签。整页从上到下四块，任何一块都能单独看懂：

1. **成绩概览（首屏）**
   - 左侧大字：`综合测评成绩`，`86.00 分`；未完成时显示 `暂不计分` 并列出缺哪几项。
   - 右侧一行三个小指标：`班级名次 3 / 42`（未发布显示「发布后可查」）、`成绩状态 已发布/核对中`、`确认状态 已确认/待确认`。
   - 下面一行次要信息：周期名、发布批次、评分方案版本、成绩更新时间，用小字，不与主数字争视觉。
   - 主操作按钮：核对有异议时「提出异议」；核对期未确认时「确认成绩」；其余情况给出「查看计分依据」锚点。

2. **得分构成（核心）**
   - 卡片树：总分卡在最上，下面每一项一张卡，层级用缩进 + 左侧竖线表示，最多缩进两级后不再加深。
   - 每张卡只放三样东西：**名称**、**这项多少分**、**一句话说明这项是什么**（如「辅导员录入的学业成绩」「已通过的活动和成果」「下面 3 项加起来」）。
   - 点任意一张卡，右侧（窄屏为下方）出现「这一项怎么算」：先一句结论（`这一项是 86 分`），再列真正发生过的步骤，每步一句白话；没有封顶/折算/扣分就不出现对应句子。
   - 卡片上不再出现「计入上级」「权重」「子模块」等词；比例只在解释区用「占综合测评成绩的 40%，也就是 34.4 分」这类说法。

3. **计分依据**
   - 三组清单：成绩（哪门课/哪个项、多少分、谁录入）、活动与成果（名称、分数、通过时间、材料预览）、扣分（事由、扣多少、依据）。
   - 每条都能展开看到材料；没有记录时说明「暂无」，不放假数据。

4. **成绩说明（页脚）**
   - 这版成绩何时发布、何时截止核对、依据哪一版评分方案；本地导出的表格与系统成绩的区别提醒。
   - 学生能做什么、找谁：辅导员负责录入与更正，学院负责审核，学校负责发布。

## 四、文案规则（硬约束）

1. 不出现实现术语：子模块、本模块、计入上级、下限前、汇总模块、权重系数、revision、快照。
2. 一个句子只说一件事，句末给数字或结论；「因为…所以…」不超过一层。
3. 数字统一两位小数并带「分」；缺失写「未录入」，不写 0。
4. 状态词统一：已发布 / 核对中 / 已锁定 / 未完成 / 已确认 / 待确认。
5. 每处说明都回答「这对学生意味着什么」，例如「学院通过后才会算进总分」。

## 五、组件与模板来源

沿用指定完整模板，不新增视觉体系：

| 区块 | 模板结构来源 | 复用方式 |
|---|---|---|
| 成绩概览 | `D/profile/page.tsx` 页头 + `profile-overview.tsx` 指标分区；`D/users` 的 Card 头部 | 大数字 + 指标行 + 次要信息行 |
| 得分构成 | `D/users/_components/users.tsx` Card 列表；已在结果页验证的嵌套卡片结构 | 卡片树 + 右侧说明卡 |
| 计分依据 | `D/profile/_components/profile-personal-details.tsx` 分段 `dl`；`D/invoice/_components/invoice-preview.tsx` 预览容器 | 三组清单 + 附件预览 |
| 成绩说明 | `D/profile` 详情分段 | 小字说明区 |

## 六、状态与边界

- 无周期：给出真实空态与「联系管理员」说明，不留空白页。
- 配置中：显示「成绩尚未开始录入」，不显示 0 分。
- 未完成：总分位显示「暂不计分」，并列出缺的项名。
- 核对中：显示发布批次、截止时间、确认按钮；超期未确认按现有规则处理。
- 已锁定：只读，保留依据与版本信息。
- 学生本人无改分入口；更正由辅导员提交、学院审核（第 4 批已实现）。

## 七、响应式与可访问性

- ≥1280：概览一行，得分构成左树右说明；768–1279：树在上、说明在下；<768：全部单列，卡片不横向滚动。
- 卡片整块可点，`aria-expanded` 表示说明区状态；数字使用 `tabular-nums`；颜色不作为唯一状态载体（同时给文字）。
- 触控目标 ≥44px；不做仅在悬停时可见的信息。

## 八、实施顺序与验收

1. 概览区重排 + 文案改写（不动数据接口）。
2. 得分构成卡片树 + 白话解释（`explain` 输出句子而非术语）。
3. 计分依据与成绩说明合并整理。
4. 移除旧页签结构，保留「返回学生名单」的管理员入口。

验收：学生视角走查七问全部能在首屏或一次滚动内回答；页面无实现术语；未完成/核对中/已锁定三种状态文案正确；移动端无横向滚动；类型、lint、构建、隔离测试通过，浏览器由用户验收。
