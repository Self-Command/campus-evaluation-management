# 活动附件图片压缩与存量回填设计（2026-10-27）

状态：已实施并上线（0.5.2，生产回填已完成）。

## 1. 背景与根因

0.5.1 上线后，生产环境一张 871,664 字节的 PNG 活动附件（2559×1167 截图）反复加载失败。逐层实测排因：

- 文件本身完好：PNG 19 个数据块 CRC 全部通过，数据库 sha256 与磁盘文件一致。
- 应用与服务器正常：本地隔离环境用该真实文件完整复现——接口完整返回 891,664 字节且浏览器正常渲染；服务器环回（经 nginx 与直连应用）拉取 230KB 静态文件仅 0.017s。
- 真正根因在访问链路：用户浏览器经代理隧道访问站点（fake-ip DNS + nginx 日志中来源 IP 为服务器自身），隧道传输启动 1~4 秒即中断。nginx 访问日志中每次 GET 仅收到 14.6万~56.5万字节（从未完整），小图 121KB 可在断流窗口内完成，871KB 大图永远无法完成；每次重试均从 0 字节重传。

产品侧结论：上传无压缩（字节原样存储），871KB 级别的截图在弱链路上不可用。治本手段是服务端压缩。

## 2. 企业实现检索（gh，按项目检索规范）

- Ghost `packages/image-transform`（MIT）：sharp.cache(false)、concurrency(1)、`.rotate()` EXIF 自动转向、`withoutEnlargement`、处理超时、跳过 svg/ico/gif（无收益或丢动画）、结果不比原图小则保留原图。
- Strapi upload `image-manipulation.ts`：sizeOptimization 默认质量 80、可优化格式 jpeg/png/webp/tiff/avif、`limitInputPixels` 防解压炸弹。
- Directus `transformations.ts`：服务时按预设转换，`withoutEnlargement` 钳制。

采用参数：WebP 质量 80、最长边 1920、触发条件（字节数 > 300KB 或最长边 > 1920px）、Ghost 的资源纪律与“取更小结果”原则。

与 Ghost 的差异：Ghost 重编码同时保留 `_o` 原图副本；本系统附件为证明/展示用途截图，保留原图会使存储翻倍并与压缩目标相悖，故不保留原图（原始字节数与 MIME 记入审计）。

## 3. 实现

- 新增 `src/server/image-normalize.ts`：`normalizeUploadedImage(bytes, mime)`。可重编码格式 jpeg/png/webp/avif/tiff；动图（pages>1）与解码失败一律保留原字节；重编码结果不小于原图时保留原图；sharp 操作 10 秒超时。
- `uploadActivityAttachment` 接入：压缩发生在 MIME 识别与大小校验之后；存储 MIME/size/sha256/storageKey 以最终字节为准（webp 存储键后缀 .webp），原文件名不变；审计 `ACTIVITY_ATTACHMENT_UPLOADED` details 增加 `normalized/originalMime/originalSize`。
- 新增审计动作 `ACTIVITY_ATTACHMENT_RECOMPRESSED`（category ACTIVITY，targetType ActivityAttachment，label 压缩活动附件图片）。
- `src/components/dashboard/resilient-image.tsx`：HEAD 返回 200 但图片仍失败（unknown）时，文案由“图片内容无法显示。”改为“网络传输中断，图片没有完整加载。”，与真实故障模式一致。

依赖：`sharp@^0.35.5`（常规依赖，Docker 多架构构建取对应平台二进制；standalone 产物已验证包含 sharp）。

## 4. 存量回填

`scripts/recompress-image-attachments.mjs`（纯 JS，在应用容器内运行，参数与线上服务一致）：

- 扫描 `kind='IMAGE'` 附件，跳过不可解码、动图、大小与记录不符、无需压缩项；dry-run 输出清单与合计，`--apply` 才写库。
- apply 逐条事务：写新 .webp 文件 → 更新 mime/size/sha256/storageKey → 写入审计（actorName=system，details 含前后对比）→ 删除旧文件；失败回滚并清理新文件。
- 幂等：已压缩项自然满足跳过条件。

## 5. 测试与证据

- 集成（隔离库）：新增“大图上传自动重编码为 WebP 并保留原始文件名”（sharp 生成 2400×1400 带噪声纹理 PNG，约 1.2MB，断言 webp、≤1920、sha256 一致）与“小图上传不做重编码保持原样”。全套 34 文件 / 162 用例通过。
- e2e（隔离验收环境）：新增“大图经上传接口自动压缩后学生端正常显示”——学院管理员经真实上传 API 传大图，学生端 naturalWidth > 0；全套 4/4 通过。
- 压缩实测：合成 UI 图 1,205,894B → 123,518B（10%）；生产故障截图 871KB → 89~91KB（约 10%），2559×1167 → 1920×876。
- 回填脚本隔离库实测：dry-run 清单正确；apply 后行/文件/审计/旧文件清理全部正确，二次扫描无可压缩项。
- typecheck、lint（0/0）、build（standalone 含 sharp）全部通过。
