# 本地开发与在线测试

## 当前交付范围

本文件只保留运行方法。功能范围、各批完成情况与未完成项以[项目说明](../README.md)的当前状态和[缺口台账](audit/现状与功能缺口.md)为准，不以本文件的命令可运行推断业务已全部交付。

根据2026-10-20用户调整，Docker 部署暂缓，不以当前开发预览代表任务01全部生产验收完成。

## 首次运行（Windows）

要求 Node 24 LTS、npm 11；本地启动器不依赖 Docker，也不会安装 Windows 服务或改动系统 PostgreSQL。

```bash
npm ci
npm run dev:setup
npm run db:local
```

等待 PostgreSQL 就绪后，在另一个终端执行：

```bash
npx prisma generate
npm run db:migrate
npm run db:seed
npm run dev
```

浏览器打开 **http://localhost:3000** 或 **http://127.0.0.1:3000**。两种本机地址同协议同端口均可写入；会话 cookie 按主机隔离，切换地址后请重新登录。开发服务器只监听本机，未开放局域网。保存源文件后 Next.js 自动热更新。

已有 `.env` 时不再运行 `dev:setup`；脚本拒绝覆盖现有密钥。后续启动只需 `db:local` 和 `dev`。不要同时启动多个数据库进程或开发服务器。

## 本地账号

当前开发库共 53 个账号：1 个学校管理员、1 个学院管理员、1 个辅导员、50 名学生。账号、密码、学院与班级清单见根目录 `测试账号（仅本地）.md`（已忽略，仅限本机）。数据库只存 bcrypt 哈希，原密码不可还原；2026-10-23 已统一重置并逐个校验，旧会话已失效。

`npm run db:seed` 另建 `admin.dev`、`publisher.dev`、`20260001` 三个旧三角色账号，密码随机生成并写入 `.local/dev-accounts-<时间戳>.json`；仅在 `127.0.0.1`、库名以 `_dev` 结尾且 `DEV_SEED_ENABLED=true` 时创建，重复执行跳过已有账号，绝不重置密码。

正式首个管理员使用 `npm run db:init-admin`，必须在交互终端执行；安全生成一次性初始密码并强制首次改密。已存在任何管理员时拒绝初始化，不绕过已有账户。

## 学生账号导入

管理员进入「账号与档案 → 导入学生账号」。支持 UTF-8 CSV 和单工作表 XLSX，文件最多1MB、30列、100名学生；字段为学号、姓名、学院、专业、班级，支持手动列映射。XLSX 学号必须为文本单元格，公式、宏和外部链接不受支持，并限制 ZIP 条目及解压总量。

预览保存在服务端，15分钟有效且仅原管理员可提交。任意错误行阻止整批写入；完全相同的重复记录跳过，不重置已有密码；账号信息冲突需要先核对。提交前复核账号快照、权限、会话与有效期，账号、档案、批次状态和审计在同一事务中写入。重复提交不会重复创建或再次返回密码。

新增账号的初始凭据仅在成功响应中交付，可保存为文本文件；数据库与审计不保存明文密码。关闭页面或丢失响应后不能恢复初始密码，应在账号管理中受控重置。不要将凭据文件上传到仓库或公开共享。

2026-10-20最新验证：类型检查、ESLint、26项真实 PostgreSQL 测试通过（包含评分固定样例、1000组对照与1500层配置测试）；10项 Edge 浏览器测试和当前版本生产构建通过。三角色业务链路涵盖活动→共享证明名单→审核→3分→手工成绩83分→扣分78分→撤销恢复83分→批量覆盖93分。一次全量运行中账号改密后的重新登录曾在5秒内未跳转；该用例单独重跑及其后两次全量均通过，尚未定位偶发时序根因，不视为已经修复。构建曾报告附件动态路径导致全项目文件追踪，现已将运行时附件目录排除构建输入并重新构建，无该项警告。Docker 和生产运行验收仍暂缓；开发工具链已知依赖告警尚未全部消除，不代表安全审计完成。

## 学期、活动与当前成绩

管理员在「学期与方案」创建学期，编辑节点、扣分项目并试算，保存后开启。进行中的学期禁止直接改写生效方案，统一更正入口仍在计划内。计算使用精确有理数，中间不按展示位数舍入；必需成绩缺失不会作为零分形成完整总分。

学院或管理员在「活动」维护活动，保存后点发布即公开，无需管理员确认分值；发布后学生信息流可见，即可提交参与证明或导入CSV/XLSX名单。名单沿用1MB、100行和文本学号限制，15分钟服务端预览；有错误整批拒绝，复核活动/学生/参与快照后事务提交。重复学号、已有有效认定及本人待审来源跳过；同一活动与学生共用唯一参与事实。共享证明通过独立引用授权，学生只能读取本人参与记录及所关联材料。活动介绍使用 Markdown，附件默认存于 `.local/activity-attachments`（可用 `ACTIVITY_ATTACHMENT_DIR` 指定），`npm run cleanup:attachments` 清理超过24小时未绑定的草稿附件。

证明放在非公开的 `.local/evidence`（可用 `EVIDENCE_DIR` 指定），仅支持基本签名可识别的PNG/JPEG/PDF，每份5MB、每次提交1—5份。随机存储标识、授权下载及哈希校验已接入；完整格式解码、恶意内容扫描和未引用文件清理尚未完成，不声称已具备这些能力。

「测评成绩」目前按同一学期事务边界读取有效参与：同一事实即使有多份通过来源也只贡献一次，待审或驳回不计入；学生仅本人，管理员按学号查询。此为进行期当前结果，尚不是已发布结果集或结算快照。必需成绩未录入时如实显示缺失。

## 成绩和扣分

管理员进入「成绩录入」，按学号查询后逐模块保存，必须填写理由；新建使用空修订，覆盖校验当前修订。成绩只允许写入GRADE模块且范围在封顶前校验。相同数值不累加、不增加修订，零分保留为真实输入。

同页支持CSV/XLSX批量成绩导入，选择成绩模块、学号列与成绩列，填写理由，预览新增/相同/覆盖/错误后确认。服务端保存15分钟预览，事务提交前重查学生、配置、当前成绩快照；任一错误整批拒绝，同批重试不重复写入。覆盖保存前后值、操作者、理由和批次。

「扣分登记」按方案已有项目维护当前正数扣分额，节点和系数来自服务端方案，客户端不能替换；更正和撤销必须填写理由并匹配修订，历史保存在审计中。有效扣分进入相应节点封顶/折算之后、下限之前；未配置下限允许负分。学生结果展示本人扣分项目、归属、系数与理由。尚未提供审计历史查询页面。

## 数据目录与停止

- `.env`：本地数据库随机密码和会话密钥，已忽略。
- `.local/`：测试账号凭据、浏览器截图，已忽略。
- `%USERPROFILE%\.campus-evaluation-dev\postgres`：持久化 PostgreSQL 数据。
- `%USERPROFILE%\.campus-evaluation-dev\postgres-18.4`：由锁定依赖复制的本地数据库二进制。

中文项目路径导致 Windows PostgreSQL 初始化编码失败，因此二进制和数据使用独立英文路径；应用代码仍保留原目录。不要手动删除数据目录。先停止 Next.js，再在数据库终端 Ctrl+C 停止 PostgreSQL。重启复用原数据，不重新初始化或清空。

其他操作系统应自行配置本机 PostgreSQL；当前 `db:local` 启动器明确仅支持 Windows。

## 检查命令

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

- `npm test` 自动创建随机命名的独立 `campus_test_*` 数据库、部署迁移、执行集成测试并清理该测试库；不会清理开发库。
- `test:e2e` 需要运行中的应用，默认连接 localhost:3000，使用已安装的 Microsoft Edge。只运行当前页面的用例；`tests/e2e/legacy/` 是前端重建前的旧用例（旧登录页、已删除的逐人计分），配置已忽略，不得作为当前验收证据。浏览器上下文不会复用你日常浏览器登录信息。
- 浏览器截图输出在 `.local/`；失败 trace 在 `test-results/`，可能包含测试会话，请勿公开。
- 构建输出 `.next-production/`，与热更新 `.next/` 隔离。`npm run build` 完成后会自动执行 `postbuild`，把静态资源同步到 standalone 目录；不要跳过该步骤，否则页面 HTML 可打开但 JS/CSS 会返回 404。
- `GET /api/health/live` 检查进程；`GET /api/health/ready` 检查数据库及初始迁移结构，不向匿名调用返回数据库诊断信息。

## 安全与当前限制

服务端读取当前账号状态、角色、认证修订和会话撤销信息；JWT 不作为永久角色凭证。退出撤销当前会话，改密撤销全部会话。写密码接口检查来源及限流。登录提供通用错误，密码只保存 bcrypt 哈希。

当前登录限流采用持久化账号桶和本机全局桶，不信任客户端提供的代理 IP 头。这适用于仅监听回环地址的开发预览；公网或局域网发布前须按可信反向代理配置来源限流、HTTPS、Cookie、安全响应头并单独验收。当前不承诺公网安全、完整业务容量或 Docker 部署已通过。

正式部署、迁移失败就绪拦截、备份恢复及生产账号维护仍按后续任务继续落实。当前健康检查只覆盖初始版本，新增数据库迁移时应同步扩展迁移版本验证。
