# 数据模型与迁移设计

更新：2026-10-23。来源：`prisma/schema.prisma` 与 `prisma/migrations/`（当前 23 项迁移）。本文件描述现状；目标设计已落地的部分在 §4 标注，未落地部分不得当作现有能力。

约定：未标注的 String 为 PostgreSQL text，`?` 为可空；ID 除特别说明外为应用生成 cuid，无数据库业务顺序语义；Decimal 除注明外为 (22,12)；`@updatedAt` 是 Prisma 客户端行为，不是数据库触发器。

## 7. 枚举与状态

- Role：ADMIN、PUBLISHER（仅历史保留，不再新建）、STUDENT、COLLEGE、COUNSELOR。
- TermPhase：CONFIGURATION→ACTIVE→CHECKING→LOCKED；重开回到前一阶段并留痕。
- TermDisposition：NORMAL、ARCHIVED、VOID、DELETED（软删除，回收站可恢复）。
- RecognitionStatus：PENDING_COUNSELOR、PENDING_COLLEGE、RETURNED、APPROVED、SUPERSEDED、WITHDRAWN、REVOKED、REJECTED。
- ClaimStatus：PENDING_COUNSELOR、PENDING_COLLEGE、RETURNED、RESCORING、APPROVED、ABANDONED、REVOKED、REJECTED。
- InputChangeStatus（成绩/扣分变更）：PENDING_COLLEGE、RETURNED、APPROVED、ABANDONED。
- AppealStatus：OPEN、PROCESSING、RESOLVED、REJECTED、WITHDRAWN。
- ReviewStatus：PENDING、APPROVED、REJECTED、NEEDS_CHANGES、WITHDRAWN、REVOKED（历史枚举，活动认定已改用 RecognitionStatus）。

## 8. 跨实体不变量

- Participation 唯一业务键 (activityId, studentId) 不变；文件哈希不作为参与事实身份。
- GradeInput 保存当前生效值，更正历史独立在 GradeChange，不把更正变成累加输入。
- 节点仍在版本化 JSON 中，数据库无法用普通 FK 保证 nodeId 有效；服务必须按绑定版本校验。
- 已发布结果、确认、结算快照不可变；更正通过新发布版本表达，不原地改写历史。
- Activity 不存在“已发布但未确认分值”的合法组合：发布事务同时写 confirmed=true；修改分值、计分项或参与范围会撤回发布并递增 publishRevision。
- ActivityAttachment 下载必须经过鉴权接口并复核 SHA-256；数据库只有元数据和随机存储键，不保存可公开访问的路径。
- 业务人员停用而非物理删除；重复身份通过 mergedIntoId 合并并保留原记录。
- 分数写入前校验精度与范围，不依赖 Decimal 四舍五入吞掉错误。

## 9. 历史目标对象与落地情况

2026-10-20 的目标草案中，以下已落地或改名实现，不再属于“尚未实现”：

| 原目标对象 | 当前实现 |
|---|---|
| Organization | College / Major / SchoolClass 三级，加 StudentAffiliation、ClassCounselorAssignment |
| StudentMembership | StudentAffiliation（含身份快照与有效期） |
| ResultSet/StudentResult | ResultPublication / PublishedResult |
| PersonalProject/Claim | RecognitionProject / PersonalClaim |
| ResultConfirmation | ResultConfirmation |
| Appeal | ResultAppeal / AppealEvidence |
| SettlementSnapshot | SettlementSnapshot / TermReopen |
| SiteSettingsRevision | SiteSettings（单行 + revision，无草稿/发布分离） |
| BrandAsset | BrandAsset（bytes 内联） |

仍未建立独立模型、以 JSON 或服务约束承载的部分：Scheme/SchemeVersion（现为 Term.scheme JSON）、CalculationRun（同步计算，无运行表）、通用 ReviewEvent（分散在各业务 history）、ImportTemplate（模板由代码生成）、ScopeSnapshot（发布时写入 payload）。这些不得在文档或验收中描述为已有表。

## 10. 增量迁移步骤

1. 只读统计孤立人员引用、重复/非法组织名、scheme 节点引用和状态字符串；报告异常，不自动删记录。
2. 新增可空关系或新表，保留旧字段，部署兼容读写。
3. 有界回填并记录映射；无法确定的关系进入人工处理清单，禁止猜测匹配。
4. 校验计数、唯一性、精确总分、附件引用/哈希及旧 API 行为，再添加 NOT NULL/FK/索引。
5. 切换读路径并观察；最后独立版本移除旧字段。Term.scheme 等数据不能在第一阶段直接丢弃。
6. 回退先停止受影响写入，回退应用需兼容新增表；破坏性 contract 前必须验证备份及隔离恢复。不得在开发数据库验证破坏性恢复。

## 11. 保留与隐私

密码哈希只在认证边界读取，API/审计不返回；会话标识不进入普通日志。证明、申报与成绩属敏感业务数据，按对象授权访问。具体保留期限、匿名化政策及法定要求待组织确认；未确认前不自动永久删除业务历史，但必须设置临时文件/预览批次的清理流程与审计。
