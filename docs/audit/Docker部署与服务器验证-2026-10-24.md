### 宿主机 Nginx 主进程问题

服务器上 `/run/nginx.pid` 指向 `56504`，该进程是 sing-box 使用的另一个 Nginx 主进程（`-c /etc/sing-box/nginx.conf`）；实际监听 80/443 的是主机 Nginx 主进程 `1086`。因此 `systemctl reload nginx` 会重载错误的配置，新增站点不会生效，ACME HTTP 校验也会失败。

处理方式与边界：

- 未停止或重启任何 Nginx 主进程，未修改其他项目配置；`nginx -t` 全量配置检查通过后，向实际监听主进程 `1086` 发送 `HUP` 完成平滑重载。
- 新增 `/etc/letsencrypt/renewal-hooks/deploy/campus-evaluation-reload.sh`：续期后自动查找 80 端口监听主进程，配置检查通过后发送 `HUP`，不依赖错误的 PID 文件。
- 该问题属于服务器既有环境，不是本项目配置缺陷；后续在此服务器上重载 Nginx 时应继续使用实际监听主进程或该钩子。

## 2026-10-25 上传接口 HTML 500 的 Nginx 临时目录修复

服务器上传登录背景时返回 `操作未完成 Unexpected token '<', "<html> <h"... is not valid JSON`。实际是 Nginx 在缓冲请求体阶段返回 HTML 500，应用没有收到请求。

- 根因：请求体超过 `client_body_buffer_size`（常见 8–16 KB）后，Nginx 写入 `client_body_temp_path`；原临时目录 `/var/lib/nginx/body` 对 worker 用户不可写，错误日志为 `open() "/var/lib/nginx/body/0000000542" failed (13: Permission denied)`。`client_max_body_size` 只控制大小上限，不控制临时目录权限，因此不会返回 413。
- 修复：只在 `/etc/nginx/conf.d/campus-evaluation.conf` 中设置 `client_max_body_size 70m;` 与独立临时目录 `client_body_temp_path /var/lib/campus-evaluation/nginx-body 1 2;`；创建 `www-data:www-data 0700` 目录；`nginx -t` 通过后仅对实际监听主进程 `1086` 执行 `kill -HUP`。
- 配置备份：`/etc/nginx/conf.d/campus-evaluation.conf.bak-20261025-upload-temp`；其他站点、容器和其他 Nginx 主进程未改动。
- 验证：`/api/health/live`、`/api/health/ready`、`/login` 均返回 200；64 KB 与 5 MB 的未认证 POST 到 `/api/admin/brand-assets` 返回 `403 application/json`（应用同源校验），不再返回 HTML 500。
- 部署手册已补充该配置、目录授权命令和“上传返回 HTML 500 / JSON 解析失败”故障排查条目。

## 2026-10-25 v0.3.3 主题覆盖修复更新

设置页出现“选中站点主题但页面仍是柔和主题，重新保存后样式短暂变化，刷新又跳回”的问题。本轮完成根因修复、真实登录回归与服务器更新。

根因：

- 管理员浏览器保留了旧版主题 cookie `theme_preset=soft-pop`。服务端在 `<html data-theme-preset>` 输出数据库中的站点默认值，但 `ThemeBootScript` 在 hydration 前优先应用个人 cookie，导致设置页选中项与实际渲染样式不一致。
- 保存设置后的 `router.refresh()` 会按服务端站点默认重新渲染根布局，于是页面短暂变成选中主题；下一次整页加载又读回旧个人 cookie，形成“保存后变一下、刷新又跳回”的假象。服务器审计记录在 08:04–08:08 UTC 连续出现多次 `SETTINGS_CHANGED`，其中一次主题值未变化但样式发生变化，与该链路一致。
- 旧版读取 cookie 使用首个匹配项，路径作用域不同的同名旧 cookie 可能命中旧个人值；保存站点设置也不会清除当前管理员的个人覆盖。

修复：

- 主题 cookie 改为独立命名空间 `campus_theme_*`；旧 `theme_*` 一律不读取、不迁移，同名 cookie 取最后一个，`site` 哨兵表示跟随服务端站点默认。
- 管理员保存系统设置成功后，当前浏览器立即应用保存后的站点主题并写入 `site` 哨兵，之后整页刷新仍保持；设置页检测到个人主题覆盖时显示说明与“恢复站点默认”按钮。
- 其他角色与访客的个人主题仍只影响本人浏览器，不写入账号、不跨设备同步、不改变站点默认。
