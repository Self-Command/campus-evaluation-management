# 移动端弹窗无法滚动问题分析

日期：2026-10-25

状态：已修复，随 v0.3.5 发布。

范围：全站业务弹窗（`DialogContent`）；侧栏/详情使用的 `Sheet` 单独说明。

## 结论

这不是“新增/编辑班级”单个页面的问题，而是共享弹窗组件的系统性问题：弹窗只限制了宽度，没有限制高度，也没有内部滚动。内容一旦超过手机可视区域，顶部和底部都会被裁掉，而 Base UI 的模态弹窗会锁住页面滚动，用户无法通过滑动页面看到剩余字段或底部按钮。

统计结果：

- 全站共 48 个 `DialogContent`。
- 23 个各自手写了 `max-h-[90dvh] overflow-y-auto` 等约束，因此可以滚动。
- 25 个没有任何高度或滚动约束，是本次问题的直接来源。
- 25 个缺少滚动的弹窗中，18 个包含较长表单或动态内容，至少 9 个在手机上基本无法完整操作。
- 侧栏和详情用的 10 个 `SheetContent` 都已带 `overflow-y-auto` 且本身为全高侧栏，不受本问题影响。

用户举的“新增/编辑班级”位于 `src/app/(workspace)/organizations/_components/organizations.tsx:645`，属于这 25 个之一。弹窗包含所属专业、班级编码、班级名称、责任辅导员、状态、修改理由和统计信息，在手机上明显超过一屏。

## 根本原因

1. 共享组件 `src/components/ui/dialog.tsx:56` 使用 `fixed top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2` 居中，但没有 `max-height`，也没有 `overflow-y-auto`。弹窗高度由内容决定，内容超过视口时上下同时溢出。
2. Base UI 的模态弹窗会锁定页面滚动（`useDialogRoot` 调用 `useScrollLock`）。弹窗内部又没有滚动容器，因此被裁掉的字段、说明和底部“保存/取消”按钮无法通过滑动到达。
3. 移动端 `src/app/globals.css:256-258` 强制输入框、按钮和选择器最小高度 44px，表单比桌面更高，进一步放大了溢出。
4. `src/app/globals.css:266` 只对手机端弹窗补了最大宽度，没有补最大高度或滚动。
5. 现有 23 个弹窗各自复制 `max-h-[90dvh] overflow-y-auto`，形成“有的能滚、有的不能滚”的不一致；以后新增弹窗仍会遗漏。另有 2 个导入历史弹窗使用 `90vh`，在移动端浏览器地址栏伸缩时也可能超出可视区。

影响不仅是“看不到底部按钮”：部分弹窗顶部标题和关闭按钮同样会被裁掉；用户点遮罩关闭时，带未保存修改的弹窗还会弹出“放弃修改？”确认，容易造成误操作或数据丢失。

## 已实施的修复

采用共享组件方案，不逐页打补丁。

### 共享约束

`src/components/ui/dialog.tsx:56` 的 `DialogContent` 基础类增加：

```text
max-h-[calc(100dvh-2rem)] overflow-y-auto overscroll-contain
```

- 48 个现有弹窗和以后新增的弹窗自动获得高度上限与内部滚动，不再依赖页面手写。
- 桌面端短弹窗外观不变；只有超过视口的长弹窗出现内部滚动。
- 使用 `dvh` 跟随移动端浏览器地址栏和软键盘引起的可视高度变化。
- `overscroll-contain` 避免滚到边界后带动被锁定的背景页面。

### 清理重复约束

移除 16 个文件中 23 个 `DialogContent` 手写的 `max-h-[90dvh]`、`max-h-[92dvh]`、`max-h-[90vh]`、`max-h-[95dvh]` 与 `overflow-y-auto`，统一交给共享组件，避免同一属性由不同 arbitrary class 竞争：

`accounts.tsx`、`activity-detail.tsx`、`activity-list.tsx`、`audit-logs.tsx`、`backups.tsx`、`claims.tsx`、`account-import-history.tsx`、`publication.tsx`、`result-view.tsx`、`source-records.tsx`、`scheme-editor.tsx`、`terms.tsx`、`evidence-viewer.tsx`、`input-history.tsx`、`scoring-correction.tsx`。

清理后全站不再有弹窗单独设置最大高度或滚动方向，也没有残留的 `90vh` 写法。字段、校验、提交、权限、审计和关闭确认逻辑均未改动。

### 未采用的方案

- **逐页补类**：工作量大且以后新增弹窗仍会遗漏，已由共享组件取代。
- **手机端改底部抽屉**：属于明显结构和视觉改动，需要单独授权；本次只修复可滚动性，不改变弹窗形态。
- **标题吸顶/按钮吸底**：需要新增背景、边框和滚动边界处理，属于视觉调整，本次不做。

## 验证结果

使用隔离 PostgreSQL 55433 与本地生产构建（3100），以 ADMIN 真实登录执行 Playwright 检查，脚本和截图保存在 `.local/`（不入库）：

| 场景 | 结果 |
| --- | --- |
| 390×844 新增/编辑班级 | 弹窗 745px 高，完整位于视口内，无横向溢出，取消/保存可达 |
| 390×844 新增学院或专业 | 559px 高，完整显示，底部操作可达 |
| 390×844 新建测评周期 | 451px 高，完整显示 |
| 390×844 导出成绩明细表 | 694px 高，完整显示，学院多选未撑破 |
| 390×500 班级弹窗（模拟软键盘压缩） | 高度限制为 468px，`scrollHeight` 745px，实际可滚动，底部按钮滚动后可达 |
| 1440×900 班级弹窗 | 625px 高，桌面尺寸与间距无回归 |

所有场景 `scrollWidth <= clientWidth`，无横向溢出；浏览器控制台无错误。质量门禁：`npm run typecheck`、`npm run lint`、`npm test`（33 文件/152 项）和 `npm run build` 均通过。

## 后续可选增强

- 让 `DialogHeader` 和 `DialogFooter` 在弹窗内部吸顶/吸底，长表单滚动时仍能看到标题和保存按钮；需要背景、边框和滚动边界处理，属于视觉调整，另行确认。
- 在根布局 viewport 中评估 `interactive-widget=resizes-content`，让安卓软键盘改变布局视口；不同浏览器行为不同，需实机验证后再启用。
- 手机端长表单是否改为底部抽屉；属于结构和视觉改动，需单独授权。

## 边界

- 本轮只修改共享弹窗布局和移除重复约束，未改动业务逻辑、数据、接口、权限和审计。
- 用户负责浏览器视觉验收；上述结果为本地自动化尺寸、滚动、页脚可达性和控制台检查。
- 已发布的 v0.3.4 解决长文件名造成的横向撑破；本次 v0.3.5 解决纵向高度和滚动，两者是同一共享组件的不同缺陷。
