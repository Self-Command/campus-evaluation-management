# 登录背景回退与品牌资源缓存修复（2026-10-25）

## 结论

版本 `0.3.1`。登录页背景图加载失败或无法解码时，不再显示浏览器破图图标，也不再让深色遮罩压住空白背景；页面始终先显示默认渐变背景，图片成功加载后再淡入替换。公开品牌资源改为长缓存，未引用资源保持管理员权限且不缓存。

本版本同时是 `0.3.0` 功能的实际发布版本：操作日志、数据库备份恢复、附件管理随 `0.3.1` 镜像上线。`0.3.0` 镜像已构建但未更新服务器。

## 根因

| 问题 | 根因 |
| --- | --- |
| 背景失败时出现破图与错误对比度 | `AuthShell` 是服务端组件，只按“是否配置背景 ID”渲染图片和黑色遮罩，无法感知浏览器实际加载结果 |
| 图片加载完成前白屏或跳变 | 背景图加载期间没有底层渐变；文字与主题控件直接按“已配置背景”切到白色 |
| 公开品牌资源重复下载 | `GET /api/brand-assets/[id]` 未设置缓存头，浏览器每次进入登录页都会重新请求背景与 Logo |
| 公开资源多余会话查询 | 路由先解析登录会话，再判断资源是否为公开设置引用；未登录访问登录页也触发一次会话数据库查询 |

## 实施

| 文件 | 变更 |
| --- | --- |
| `src/components/auth/auth-shell.tsx` | 改为客户端组件；背景状态为 `none/loading/loaded/failed`；始终渲染 `auth-default-background`；图片加载成功后 500ms 淡入，遮罩同步淡入；失败时卸载图片；回调 ref 读取 `complete/naturalWidth`，覆盖 hydration 前已完成加载或失败的情况；文字与主题控件按实际加载状态切换对比度 |
| `src/server/settings.ts` | 先按站点设置的公开白名单判断资源；仅私有资源才通过可选回调惰性解析会话 |
| `src/app/api/brand-assets/[id]/route.ts` | 公开资源返回 `public, max-age=31536000, immutable`；私有资源返回 `private, no-store`；保留 `nosniff` 与严格 CSP；会话改为惰性解析 |
| `tests/integration/lifecycle.test.ts` | 覆盖公开资源不触发会话查询、私有资源匿名不可读、管理员会话可读且 `publicAsset=false` |
| 版本与部署配置 | `package.json`、`package-lock.json`、备份清单回退版本、`compose.yaml` 默认版本与 `.env.docker.example` 更新为 `0.3.1`；部署文档示例同步 |

缓存策略依赖现有品牌资源模型：每次上传创建新 ID，站点设置只引用 ID，因此公开资源可安全使用一年不可变缓存；替换图片不会命中旧缓存。

### 浏览器验收

按项目约定，agent 不操作浏览器。请用户在本机 `http://127.0.0.1:3101/login` 验收：

1. 正常网络下，渐变背景先出现，背景图加载后平滑淡入，文字保持可读。
2. 在浏览器开发者工具中把背景图请求改为失败或离线后刷新，页面应显示完整渐变背景，无破图图标、无黑色错误遮罩，文字与主题控件保持深色可读。
3. 恢复网络刷新，背景图重新加载并淡入。

## 边界

- 不做服务端图片转码、压缩或格式转换，不新增依赖。
- 图片加载失败时不再自动重试；刷新或重新进入页面可重新请求。
- 公开资源一年缓存只适用于当前“上传生成新 ID”的资源模型；若未来允许覆盖同一资源 ID，必须同步调整缓存策略。
- 生产恢复、备份和附件功能沿用 `0.3.0` 实施与演练结论，本版本不改变数据库结构。
