## 6. 缺陷、修复与回归

### D1 成绩/扣分提交被严格校验误拒绝

- 现象：辅导员通过页面提交成绩或扣分时，请求体同时携带路由用 `termId`，服务端严格 schema 将其当作伪造字段拒绝，提交流程报校验错误。
- 根因：`submitGradeChange` / `submitDeductionChange` 直接将整个请求体交给 `.strict()` schema。
- 修复：在严格校验前仅剥离 `termId`，其余未知字段仍被拒绝；涉及 [grade-changes.ts:44](file:///C:/Users/by970/Desktop/综合测评管理/src/server/grade-changes.ts#L44)、[deduction-changes.ts:48](file:///C:/Users/by970/Desktop/综合测评管理/src/server/deduction-changes.ts#L48)。
- 回归：C09、C10、C14、C16、C17 及成绩/扣分审核链路全部 PASS。

### D2 扣分表单提交后重置触发空引用

- 现象：新增扣分提交成功后，服务端日志出现 `unhandledRejection: Cannot read properties of null (reading 'reset')`，表单状态未正确重置。
- 根因：`form.reset()` 在 `await submit(...)` 之后调用 React 合成事件的 `event.currentTarget`，此时已为 `null`。
- 修复：提交前捕获表单元素，提交成功后仅在使用成功结果时重置，并刷新项目下拉；涉及 [deduction-workspace.tsx:111](<file:///C:/Users/by970/Desktop/综合测评管理/src/app/(workspace)/deductions/_components/deduction-workspace.tsx#L111>) 与 [deduction-workspace.tsx:391](<file:///C:/Users/by970/Desktop/综合测评管理/src/app/(workspace)/deductions/_components/deduction-workspace.tsx#L391>)。
- 回归：类型检查、lint、集成测试、生产构建全部通过。因验收周期已进入 `CHECKING`，辅导员新增扣分表单不再显示，无法再通过 UI 重放该提交；该限制在第 9 节明确披露。

### D3 学生已确认成绩仍显示“不要求确认”

- 现象：学生完成成绩确认后，结果页底部仍显示“本版不要求确认”，与页面顶部的已确认状态矛盾。
- 根因：底部说明未按确认记录区分已确认版本与确实无需确认的版本。
- 修复：按确认记录返回“本版已确认，如有疑问可在截止前提出异议。”，无确认要求时返回“本版不要求确认，如有疑问可在截止前提出异议。”；涉及 [result-summary.tsx:57](file:///C:/Users/by970/Desktop/综合测评管理/src/app/(workspace)/results/_components/result-summary.tsx#L57)。
- 回归：类型检查、lint、构建通过；因验收周期处于 `CHECKING` 且确认状态已固定，未再单独重放 UI 文案切换，仅做代码核对与静态验证。
