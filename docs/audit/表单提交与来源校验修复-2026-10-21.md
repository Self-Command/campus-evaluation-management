# 表单提交、写入来源与静态资源修复记录

日期：2026-10-21

## 复检结论

管理员在测评周期页无法创建、移入回收站或作废周期，后续又出现多个页面显示“暂时无法加载此页面”。先后确认三个独立问题：

1. 项目使用的 Base UI `Button` 默认渲染为 `type="button"`。测评周期页及另外多个页面的表单提交按钮没有显式声明 `type="submit"`，点击后不会触发表单提交，请求根本没有发出。
2. 业务写入接口只接受与 `NEXTAUTH_URL` 完全一致的 Origin。服务监听并显示 `127.0.0.1:3000`，而配置为 `http://localhost:3000` 时，通过 `127.0.0.1` 打开页面会产生 `403 请求来源无效`，影响全部写接口。
3. 正式 3000 服务在构建后直接启动，没有把 `.next-production/static` 同步到 standalone 的嵌套静态目录。页面 HTML 可以返回 200，但引用的 JS/CSS 全部 404，浏览器客户端渲染或导航时触发 `error.tsx`，显示“暂时无法加载此页面”。

服务层创建、删除、作废逻辑本身正常；问题分别位于前端提交按钮、来源校验边界和 standalone 启动准备。

## 已实施修复

### 1. 补齐表单提交按钮

扫描 `src/**/*.tsx` 的全部 JSX 表单，确认 19 个表单提交/筛选按钮缺少 `type`，已全部显式改为 `type="submit"`，涉及：

- 测评周期：创建、管理动作（改名/回收站/作废/恢复/归档）
- 学生档案：筛选、保存档案更正
- 学生名录公共组件：搜索学生
- 账号管理：筛选账号
- 活动详情：确认移交、确认撤回发布
- 活动参与：筛选、保存活动分数
- 结果异议、申报管理、认定管理：筛选
- 组织管理：保存组织
- 结果发布：延长核对期限、保存政策并重新预检
- 排名：筛选范围
- 结果查询：查询测评
- 评分配置：移动并保留草稿

没有修改 `Button` 组件默认行为。Base UI 默认 `type="button"` 是有意设计，统一改为提交会误伤弹窗取消和普通操作按钮；本次按表单单据显式声明。

新增 `tests/integration/form-buttons.test.ts`，用 TypeScript AST 扫描所有表单内的 `Button`/`button`，要求必须显式声明 `type`。以后新增漏写 `type` 的按钮会直接使测试失败。

### 2. 改造同源写入校验

`src/server/http.ts` 的 `sameOrigin` 现在按以下顺序校验：

1. 解析 `Origin`，只接受完整的 `http:`/`https:` 来源，拒绝 `null`、文件协议、带路径或带凭据的值。
2. 接受 `NEXTAUTH_URL` 配置的来源。
3. 接受 `APP_TRUSTED_ORIGINS` 中逗号分隔的额外部署来源，供反向代理或备用域名使用。
4. 当配置来源为本机回环地址时，自动互认同协议、同端口的 `localhost`、`127.0.0.1` 和 `[::1]`。
5. 接受与请求 URL 同源的浏览器请求，用于实际公开主机与 `NEXTAUTH_URL` 不同但请求 URL 正确的部署。
6. 其余跨站来源继续拒绝。

`src/app/api/password/route.ts` 原先重复实现来源判断，已改为复用 `sameOrigin`。

新增 `tests/integration/http-origin.test.ts`，覆盖配置来源、回环别名、额外可信来源、跨站来源、端口不一致、缺失 Origin、`null`、带路径和文件协议。

- `docs/api/接口约定.md` 和 `docs/api/openapi.current.yaml` 更新来源校验规则。

### 4. 修复 standalone 静态资源部署

根因是构建完成后直接启动 `.next-production/standalone/server.js`，而 Next.js standalone 输出不会自动把构建静态资源放到服务器读取的位置。此前独立 HTTP 脚本会在启动前自行复制静态资源，因此隔离检查通过，但正式 3000 服务的启动顺序没有覆盖。

已新增 `scripts/prepare-standalone.mjs`，并在 `package.json` 增加 `postbuild`：每次 `npm run build` 完成后自动把 `.next-production/static` 同步到 `.next-production/standalone/.next-production/static`，同时处理 `public` 目录。构建和启动顺序已写入 `docs/development.md`，避免再次出现 HTML 正常但 JS/CSS 404。
