# 活动详情页签与图片加载韧性实施记录

版本：`0.5.1`  
日期：2026-10-27  
设计：[活动详情页签与图片加载韧性设计](../design/活动详情页签与图片加载韧性设计-2026-10-27.md)  
模板来源：[模板来源与适配清单](../design/模板来源与适配清单.md)

## 1. 问题与范围

学生反馈活动详情标题下出现无意义横线，图片在弱网或资源异常时直接显示破图，且缺少持续加载与恢复手段。经复核，横线来自单页签仍渲染页签栏及选中下划线；破图来自 Markdown 图片直接使用原生 `<img>`，没有加载状态、超时、重试和错误分类，附件接口也没有缓存与条件请求支持。

本轮按已批准设计完成：

- 可见页签只有 1 个时隐藏页签栏；多页签角色保持原样。
- Markdown 图片统一使用 ResilientImage：骨架占位、首图优先、延迟加载、超时、自动/手动重试、错误分类、断网恢复、原图入口。
- 活动附件接口增加 ETag、私有缓存、304 条件请求与 HEAD。
- 品牌 Logo、设置页登录背景与网站图标增加失败兜底。
- 补充集成测试与 Playwright 端到端测试。

不在本轮范围：TipTap 编辑器内图片、证明材料预览、上传进度、非图片附件链接错误提示。

## 2. 实现

| 文件 | 变更 |
| --- | --- |
| `src/app/(workspace)/activities/_components/activity-detail.tsx` | 计算可见页签数；仅 1 个时不渲染页签栏；`?tab=` 与多页签行为不变 |
| `src/components/dashboard/resilient-image.tsx`（新增） | 首图 `eager`/高优先级，其余 IntersectionObserver 提前 600px 加载；最小高度骨架；单次 15 秒超时；HEAD 8 秒分类；自动重试 2 次（1 秒、3 秒）；手动重试、查看原图、重新登录、断网提示 |
| `src/components/dashboard/markdown-content.tsx` | 图片改由 ResilientImage 渲染；按 AST 位置标记首图；移除旧图片间距规则 |
| `src/server/activity-attachments.ts` | 新增下载响应头构造（Content-Type、Content-Disposition、nosniff、`private, max-age=300`、`Vary: Cookie`、强 ETag、Content-Length）、ETag 匹配、仅元数据鉴权 |
| `src/app/api/activity-attachments/[id]/route.ts` | GET 支持 `If-None-Match` 304；新增 HEAD；304/HEAD 不读文件、不写审计 |
| `src/components/brand-logo.tsx` | 资源失败时显示站点名称文本；明暗 Logo 分别记录失败 ID；更换资源自动恢复 |
| `src/app/(workspace)/settings/_components/settings.tsx` | 背景预览失败显示主题渐变与说明；网站图标失败显示“无”与说明 |
| `tests/integration/activities.test.ts` | 断言 ETag、缓存头、Content-Length、弱标签/通配匹配，以及无权限角色无法获取元数据或下载 |
| `tests/e2e/activity-detail-images.spec.ts`（新增） | 单页签、图片成功/缺失、缓存与条件请求、学院页签、断网自动重试 |

关键行为：

- 自动重试等待期间只显示骨架和“网络较慢，正在重新加载图片…”，避免并发重试；自动重试耗尽后才出现“再次加载”。
- 401 只提供“重新登录”并跳转登录页；403 提示“你没有查看这张图片的权限”；404 只说明“图片已被删除，或你没有查看权限”；三者都不提供无效重试。
- 每次尝试的 URL 追加 `_retry=N`，避免浏览器复用失败缓存；服务端忽略该参数。
- 304 与 HEAD 不产生下载审计；实际回源下载仍校验 SHA-256，非学生角色写 `ACTIVITY_ATTACHMENT_DOWNLOADED`。
- 缓存策略为 `private, max-age=300` 且 `Vary: Cookie`，权限变化最多在当前浏览器延迟 5 分钟生效；证明材料仍 `no-store`。
- 组件只使用行内元素和按钮，Markdown 段落内 HTML 合法，不嵌套链接。
