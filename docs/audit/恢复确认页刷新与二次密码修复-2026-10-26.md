# 恢复确认页反复刷新与二次密码失效修复（2026-10-26）

## 结论

线上备份恢复已通过预检并进入 READY 后，确认区每 4 秒重新挂载，输入密码和“替换数据库”时页面像在持续刷新；输错一次当前密码还会整页跳转登录，并使已通过的预检失效。根因分别在前端轮询/刷新数据保留、401 处理和服务端预检指纹三处。本轮完成修复，并在隔离应用与数据库上跑通“创建备份 → 预检 READY → 页面轮询 → 错误密码 → 正确密码 → 恢复完成 → 重新登录”全流程。

## 根因

1. `READY` 被当成恢复执行中：备份页每 4 秒请求列表；旧 `useRemote` 每次请求都把 `data` 置空，`activeRestore` 短暂变成 `null`，确认区随 `canConfirm` 反复卸载/挂载，页面整体出现骨架和滚动位置跳动。
2. 前端把所有 401 都当成会话失效：恢复确认接口在“当前密码不正确”时返回 401，页面直接跳 `/login`，已输入的恢复理由、密码和确认短语随之丢失。
3. 错误密码会污染预检指纹：服务端 `verifyAdminPassword` 失败时写入 `AUTH_ADMIN_REAUTH_FAILED` 审计；旧指纹包含审计总条数、最新审计和数据库物理大小，因此一次输错就会让 READY 预检永久失效，正确密码也会得到 `RESTORE_FINGERPRINT_MISMATCH`。

## 修复

| 文件 | 修改 |
| --- | --- |
| `src/app/(workspace)/backups/_components/backups.tsx` | 仅在实际执行阶段（`confirmed/snapshot/exported/swapping/swapped`）轮询；READY 不再轮询；确认区只在当前备份预检为 `ready` 时显示；刷新期间保留已有列表数据，不再让骨架替换整页 |
| `src/components/dashboard/use-remote.ts` | 重新请求时保留上一次成功数据；只有当前 URL 没有数据时才显示 loading；同 URL 请求失败保留旧数据和错误提示 |
| `src/components/dashboard/feedback.tsx` | 仅当 401 带 `SESSION_REQUIRED` 时跳登录；密码校验失败的 401 原样显示错误 |
| `src/server/route-handler.ts` | 统一鉴权失败的 401 返回 `code: "SESSION_REQUIRED"` |
| `src/app/api/password/route.ts` | 改密接口的会话失效 401 同样返回 `SESSION_REQUIRED`，保持原有跳转语义 |
| `src/server/restore.ts` | 预检指纹不再包含数据库物理大小和 `AuditEvent` 总数；最新审计只取非 `AUTH` 分类，登录、退出和管理员二次认证失败不再使预检失效 |
