# 活动发布与富文本改造实施记录

日期：2026-10-23。依据：[活动发布与富文本改造设计](../design/活动发布与富文本改造设计-2026-10-23.md)。状态：已实施并通过命令行验证；未由 agent 操作浏览器验收，页面交互与视觉效果由用户自行验收。

## 1. 实施结果摘要

| 设计项 | 实施情况 |
|---|---|
| 发布即公开 | 学院或管理员保存后点「发布」，服务端在同一事务内重新校验参与范围，写入 `publishedAt`、`confirmed=true`、`publishRevision+1`、`revision+1`，并记录 `ACTIVITY_PUBLISHED` 审计；不再要求管理员确认分值 |
| 管理员职责 | `confirmActivity` 服务与 `confirm` 动作已删除；管理员只保留发布、撤回发布与主办学院移交等管理能力 |
| 分数文案 | 活动相关页面统一为「N 分」；源码检索「统一分值」「（统一）」「参加要求」「确认分值」为 0 处（发布弹窗中解释「无需管理员确认分值」的一句提示保留） |
| 参加要求 | `Activity.requirements` 已从数据库、Prisma schema、接口与页面删除；删除前备份见 §3 |
| 富文本 | 活动介绍以 Markdown 存储，编辑端 Tiptap 3.32，详情端 `react-markdown` + GFM + breaks + sanitize；列表使用服务端纯文本摘要 `contentText` |
| 附件 | 新增 `ActivityAttachment`、上传/下载/删除接口、系统设置三项限制与 24 小时草稿清理脚本 |
| 学生页 | 「最新活动」为最左且默认视图；信息流只返回已发布、学期 ACTIVE 且 NORMAL、当前处于起止时间内、命中学院与班级范围的活动；「我参加的活动」保留 |
| 发布变更联动 | 已发布活动修改分值、计分项或参与范围时自动撤回发布，更新 `publishRevision`，审计记录前后值；只改名称、时间、介绍或附件不撤回 |
| 名单导入 | 可选活动条件由 `confirmed` 改为 `publishedAt != null`，未发布活动不能导入名单 |

## 2. 发布与撤回流程

- `src/server/activities.ts` 的 `publishActivity`：
  - 权限为 `ADMIN`、`COLLEGE`、历史 `PUBLISHER`，且活动须由当前账号可管理。
  - 发布前直接调用 `inspectAudience` 校验学院/班级存在且有符合学生，不再依赖范围预检 token；预检接口仍保留，用于表单实时提示与人数预览。
  - 发布写 `confirmed=true`；撤回要求填写不少于 2 字的理由，并写 `ACTIVITY_UNPUBLISHED` 审计。
- `saveActivity`：
  - 已发布活动修改参与范围或分值/计分项时，自动置 `publishedAt=null`、`publishRevision+1`，审计 `publicationWithdrawn` 及 `beforeAudience/afterAudience`、`beforeNodeId/afterNodeId`、`beforePoints/afterPoints`。
  - 保存时通过 `attachmentIds` 绑定本次编辑提交的附件，校验附件归属、未绑定或属于本活动、数量上限。
- `src/app/api/activities/route.ts` 的动作集合已不含 `confirm`；发布与撤回统一走 `publish` / `unpublish`。
- 迁移 `20261023130000_activity_publish_consistency` 仅修正“已发布但 `confirmed=false`”的异常存量，不改草稿。

## 4. 富文本与 Markdown

- 依赖：`@tiptap/react`、`@tiptap/starter-kit`、`@tiptap/markdown`、`@tiptap/extension-image`、`@tiptap/extension-table`、`@tiptap/extension-list`、`@tiptap/extensions` 均为 3.32.x；渲染端 `react-markdown` 10.1、`remark-gfm` 4、`remark-breaks` 4、`rehype-sanitize` 6。
- `Activity.content` 上限从 5,000 提高到 20,000 字符，数据库仍为 text。
- `src/components/dashboard/rich-text-editor.tsx`：
  - 支持标题、粗体/斜体/删除线、行内代码、代码块、引用、有序/无序/任务列表、表格、链接、图片、分割线、撤销/重做。
  - 支持工具栏选择图片、拖拽与粘贴上传；图片插入 `/api/activity-attachments/{id}` 的 Markdown 图片语法。
  - 上传前读取服务端限制，显示数量、单文件大小与允许后缀；附件在编辑器中可移除。
  - Next.js 下使用 `immediatelyRender: false`，避免 hydration 不一致。
- `src/components/dashboard/markdown-content.tsx`：禁用原始 HTML，外链 `target="_blank" rel="noopener noreferrer"`；图片经鉴权接口读取，不能交给 Next 图片优化器缓存或改写 URL。
- `src/lib/markdown.ts` 的 `markdownExcerpt` 生成最多 160 字的纯文本摘要，去除代码块、图片、链接地址与 Markdown 标记，用于列表与信息流卡片。

## 5. 活动附件

- 模型：`ActivityAttachment`，字段 `id, activityId?, uploaderId, name, mime, size, sha256, storageKey, kind, createdAt`；`activityId` 可空以支持保存活动前上传；`storageKey` 唯一；索引 `activityId` 与 `(uploaderId, createdAt)`。
- 存储：默认 `.local/activity-attachments/`，可用 `ACTIVITY_ATTACHMENT_DIR` 覆盖；文件名为 24 字节随机十六进制加后缀，数据库只保存元数据、SHA-256 与随机键。
- 校验：
  - 扩展名必须在系统设置白名单内，且真实签名匹配：PNG/JPEG/GIF/WEBP/PDF 魔数、DOC 的 OLE 头、DOCX/XLSX/PPTX/ZIP 的 `PK` 头、TXT/MD 的 UTF-8 文本。
  - 文件名去路径与控制字符；单文件大小、每活动数量由设置读取；上传限流每分钟 60 次；上传接口要求同源。
  - 下载按活动可见性鉴权，未绑定附件仅上传者或 ADMIN 可读；读取时复核 SHA-256；响应带 `X-Content-Type-Options: nosniff` 与 `Cache-Control: private, no-store`，图片/PDF 内联，其余作为附件下载。
  - 删除允许上传者、ADMIN 或活动管理者，同时删除文件与记录，要求同源。
- 接口实现与设计稿的差异：上传采用原始二进制请求体加 `x-file-name`、可选 `x-activity-id` 请求头，与既有证明上传保持一致，不使用 multipart；活动详情页的附件列表直接内联在介绍下方，未单独创建 `attachment-list.tsx`。
- 清理：`npm run cleanup:attachments` 删除超过 24 小时仍未绑定活动的附件文件与记录；不做全量垃圾回收。

测试覆盖的关键行为：

- 发布不需要 token，服务端重新校验范围；无符合学生时拒绝发布。
- 发布后 `confirmed=true`、`publishRevision=1`，学生信息流出现；未开始、已结束、未发布活动不出现。
- 修改分值自动撤回并写前后值审计；改名不撤回。
- 附件上传、下载、删除、类型/大小/数量限制与重复绑定校验。
- 学生页默认最新活动；参与记录仍可打开已结束活动详情。
- 名单导入只接受已发布活动；发布者/学院/辅导员权限矩阵保持。
