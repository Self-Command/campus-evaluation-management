# 成绩与扣分页分栏实施与验证

日期：2026-10-22。范围：按[角色视角UI规范与页面改造分析](角色视角UI规范与页面改造分析-2026-10-22.md) 4.1「成绩页的队列 + 名册」「扣分页的队列 + 名册」与 P1 第 3 项。本文只记录本轮实际改动与命令行证据，不代替用户浏览器验收。

## 1. 改动前的问题

`/grades` 与 `/deductions` 都把「处理队列」和「学生名册」上下堆叠：

- 辅导员想录入成绩，要先滚过整张成绩修改队列表；
- 学院想审核，要先滚过整张本院学生名册；
- 两个表都在同一页各自带标题、说明、筛选和分页，页面很长，首屏只能看到统计卡和队列前几行。

## 2. 实施结果

| 文件 | 改动 |
| --- | --- |
| `src/app/(workspace)/grades/_components/grade-workspace.tsx` | 用官方 `Tabs` 把队列与名册改为同页两栏切换：`queue`（待我处理/我的成绩修改/成绩修改与审核）与 `roster`（负责班级学生/本院学生/全校学生），标签带真实计数；默认按角色设定——辅导员默认名册（录入），学院与管理员默认队列（审核） |
| `src/app/(workspace)/deductions/_components/deduction-workspace.tsx` | 同上，标签为「我的扣分申请 / 待我审核 / 扣分记录审核」与「负责班级学生 / 本院学生 / 全校学生」 |

- 顶部三项统计卡保留在两栏之上，切栏不丢失当前周期、筛选、搜索词与分页状态（状态都在父组件，两栏共用同一份请求）。
- 两栏各自保留原有的标题、说明、筛选、分页、移动端卡片和真实操作；没有新增接口、没有改权限、没有改审核链。
- 之所以用切换而不是左右并排：队列 7 列、名册 6 列，并排后每侧只剩 5～7 栏宽，表格会强制横向滚动，反而不如分栏切换可读。此取舍已在此记录，供后续调整。

## 3. 验证证据

- `npx tsc --noEmit` 通过（0 错误）。
- `npx eslint grade-workspace.tsx deduction-workspace.tsx --max-warnings=0` 通过。
- 本机开发服务 HTTP 检查（未操作浏览器）：
  - 辅导员 `/grades`、`/deductions` 200，渲染「负责班级学生」与「我的成绩修改/我的扣分申请」两个栏目标签；
  - 学院 `/grades`、`/deductions` 200，渲染「待我审核」与「本院学生」；
  - 管理员 `/grades`、`/deductions` 200，渲染「成绩修改与审核 / 扣分记录审核」与「全校学生」；
  - 三页均无错误页标记。
- 表格数据由客户端 `useRemote` 在挂载后请求，首屏 HTML 只含统计卡与栏目标签；因此本轮 HTTP 检查无法验证“默认展开哪一栏”，该项以代码默认值和用户浏览器验收为准，不声称已通过自动化验证。
