## 表头与文案规则

表头由评分树生成，同名字段在不同层级下通过模块名区分，避免“×80%”无法判断是谁的比例。

| 位置 | 生成规则 | 示例 |
| --- | --- | --- |
| 实际分列 | 最底层模块只写 `模块名`，不写“实际分”也不写权重；有封顶/最低分/换算时在括号内追加说明 | `思想引领活动`、`活动与成果（不超过50分，原始满分100分折算为20分）` |
| 分组表头 | `模块名`，仅在有约束时标注模块合计口径，不写权重 | `红色文化引领工程（模块合计不超过100分）` |
| 比例列 | 只有被乘的列才出现，写成 `模块名×乘数`；乘数为 100% 时写成 `模块名比例分` | `学业成绩×80%`、`基础性素质×80%`、`红色文化引领工程×10%`、`发展性素质×20%` |
| 比例分合计 | `模块名比例分合计` | `基础性素质比例分合计` |
| 实际分合计 | `模块名实际分合计` | `发展性素质实际分合计` |
| 扣分前结果 | `扣分前总分` | `扣分前总分` |
| 扣分登记 | `扣分项`；具体项目写成 `名称（登记值）` | `法制与校规校纪扣分（登记值）` |
| 扣分合计 | `扣分合计`；存在非 1 扣分系数时写成 `扣分合计（已乘扣分系数）` | `扣分合计（已乘扣分系数）` |
| 必填状态 | `必填项状态`；值为 `必填齐全` / `必填缺项` | `必填缺项` |
| 最终结果 | `综合测评总分（扣分后）` | `综合测评总分（扣分后）` |

权重只出现在真正执行乘法的比例列上：

- 学业成绩的 80% 写在基础性素质内部的 `学业成绩×80%`，基础性素质进入总分的 80% 写在 `基础性素质×80%`，两者不混淆。
- 发展性素质下各模块的 20% 写在模块比例列，发展性素质进入总分的 20% 写在 `发展性素质×20%`。
- “合计项”直接相加下级，不执行直接下级权重；其下级旁的比例列只展示上级占比的分配，不重复计入总分，规则表备注中已说明。
- 成绩项、活动项只显示实际分；比例分只出现在需要乘权重或展示上级占比的列上。

“评分规则”工作表固定为 10 列：`名称`、`项目类型`、`所属上级`、`合计上限（封顶）`、`原始满分`、`折算满分`、`合计最低分`、`权重（乘数）`、`扣分系数`、`必填项`。项目类型取值为 `成绩项` / `活动项` / `合计项` / `权重汇总项` / `扣分项`，不适用项显示 `—`。该表只说明参数，不声称包含公式；公式仅存在于“成绩明细”表。权重只对“权重汇总项”的直接下级生效，同一“权重汇总项”下直接下级权重合计必须为 100%。

文件名和标题同步区分阶段：

- 文件名使用 `..._正式发布_日期.xlsx` 或 `..._当前阶段_日期.xlsx`。
- 发布数据统一称 `正式发布快照`，当前录入称 `当前周期`。
- 单班级标题使用 `学院·专业·班级`，避免括号中出现半个层级；多班级标题写明范围和班级数。

## 公式结构

以当前官方口径评分配置为例：

| 单元格 | 公式逻辑 |
| --- | --- |
| 红色文化实际分 | `MIN(SUM(四个活动输入), 规则表配置上限)` |
| 红色文化比例分 | `实际分 × 规则表红色文化权重` |
| 学业成绩比例分 | `学业成绩 × 规则表学业成绩权重` |
| 体育素质比例分 | `体育素质 × 规则表体育素质权重` |
| 基础性素质比例分合计 | `SUM(红色比例, 学业比例, 体育比例)` |
| 基础性素质贡献 | `比例分合计 × 规则表基础性素质权重` |
| 志愿服务/人文/卓越实际分 | `MIN(SUM(子项输入), 规则表各自上限)` |
| 三个发展模块比例分 | `实际分 × 规则表对应模块权重` |
| 发展性素质实际分合计 | `SUM(三个模块实际分)` |
| 发展性素质贡献 | `实际分合计 × 规则表发展性素质权重` |
| 扣分前总分 | `SUM(基础性素质贡献, 发展性素质贡献)` |
| 扣分合计 | `SUM(登记值 × 规则表扣分系数)` |
| 综合测评总分（扣分后） | `扣分前总分 − 根节点扣分合计`；配置根节点最低分时再取 `MAX` |

关键约束：

- 比例值来自“评分规则”工作表，不写死 0.8/0.2；修改配置后层级、表头、比例列和公式同步变化。
- 叶子节点位于“权重汇总项”下时同样生成比例列，模块名和乘数来自当前配置。
- 父节点为“合计项”时直接相加，不乘直接下级权重；为“权重汇总项”时按直接下级权重汇总。
- 缺失必填录入按 0 参与公式并标记 `必填缺项`；明确填写 0 是真实零值，状态仍为 `必填齐全`。
- 子模块扣分计入该模块实际分，因此 `扣分前总分` 已包含模块级扣分；最终总分只再减根节点扣分，避免重复扣分。`扣分合计` 会列出全部扣分项，当前官方口径只在根节点配置扣分，未出现对账差异。

## 与官方模板逐项对照

对照文件：`需上交——附件1：上交—2024-2025学年上期综合素质测评成绩细则总表(自动汇总）.xls`

- 基础性素质：红色比例 + 学业比例 + 体育比例，再乘 80%，一致。
- 发展性素质：三个模块分别封顶 30/30/40，分别乘 20%，再合计乘 20%，一致。
- 扣分：扣分前总分减扣分，一致。
- 唯一有意差异：模板红色文化表头写“不超过100分”但公式未封顶；系统按评分配置的上限执行 `MIN`，与表头含义一致。
- 统一明细表额外包含学院、专业、班级和必填项状态（仅当前周期），以满足全校/学院/辅导员/学生同一表头、不同范围的要求。

## 发布模式

正式发布导出使用同一构建器，读取发布版本评分方案和冻结学生数据：

- 计算单元格仍为公式，保留完整计算链；“评分规则”表保留发布时的参数快照。
- 明细表和规则表均启用保护，录入单元格和规则参数为白色只读，黄色录入标识只存在于当前周期。
- 发布快照不显示 `必填项状态`：发布前置条件已要求无缺失必填项、无待审记录且存在有效数据，发布结果必然齐全，保留该列只会造成重复信息。列数由当前周期的 41 列变为 40 列。
- 发布后评分方案不可变，公式按锁定参数重算仍得到发布时结果；缓存值同时写入文件，未重算的查看器也能直接显示结果。

## 后续约束

- 任何评分配置变更都必须由同一构建器重新推导表头、比例列和公式，不得恢复固定表头或写死比例。
