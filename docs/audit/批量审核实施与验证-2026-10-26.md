# 批量审核实施与验证记录（2026-10-26）

版本：`0.5.0`  
设计依据：[批量审核设计](../design/批量审核设计-2026-10-26.md)  
范围：活动参与认定、个人申报、成绩修改、扣分修改、结果异议的批量处理；不扩大审批权限

## 1. 实施结果

### 1.1 公共契约与批次审计

- 新增 `src/server/batch-context.ts`：`BatchContext { batchId; index; total }`，仅写入审计详情与记录历史，不参与权限判断。
- 新增 `src/server/batch-review.ts`：共享批量处理器。解析并严格校验整批请求（动作白名单、理由规则、1–100 条、ID 去重、revision 非负、全部属于当前周期），随后**按顺序**逐条调用现有单条服务，每条独立 `termTransaction`；逐条捕获 `AccountError` 记为失败并继续，非预期异常立即停止并把剩余项标记为未执行；整批 45 秒时间预算。
- 单条服务 `reviewParticipation`、`changeClaim`、`changeGradeChange`、`changeDeductionChange`、`changeAppeal` 增加可选批次上下文参数；单条调用不传时行为不变。
- 新增 5 个批次汇总审计动作：`PARTICIPATION_BATCH_REVIEWED`、`CLAIM_BATCH_CHANGED`、`GRADE_BATCH_CHANGED`、`DEDUCTION_BATCH_CHANGED`、`APPEAL_BATCH_CHANGED`，记录 `batchId`、动作、请求数、成功数、失败数、未执行数与失败代码分布，`result` 为 `SUCCESS`/`PARTIAL`/`FAILURE`。
- 成功条目照常写单条审计，详情与历史带 `batchId`/`batchIndex`/`batchTotal`；失败条目只进入汇总审计，不产生单条审计事件。

### 1.2 批量接口

按业务域新增，路由层角色白名单与该域单条接口一致，全部走 `authenticatedApi`：

- `POST /api/recognitions/batch`：辅导员初审通过/退回、学院终审通过/退回、管理员撤销。
- `POST /api/claims/batch`：辅导员退回、学院终审通过/退回/退回重评、管理员撤销。
- `POST /api/grade-changes/batch`：学院通过/退回、辅导员放弃本人修订。
- `POST /api/deduction-changes/batch`：学院通过/退回、辅导员放弃本人申请。
- `POST /api/appeals/batch`：管理员开始处理（`OPEN`，无需理由）。

整体错误返回 400（缺参、超限、重复 ID、非法动作）、401 未登录、403 无角色；逐条越权/状态变化在 `results` 中按条返回，不泄露对象信息。

### 1.3 页面与批量控件

- 新增 `src/components/dashboard/batch-review.tsx`：`useBatchReview` 提供选择状态、表头全选（仅本页可处理记录）、批量工具栏、确认对话框（共用理由必填校验、处理中禁用）与结果对话框（成功/失败/未执行汇总 + 失败表 + “关闭并刷新”）。
- `src/components/dashboard/template-directory.tsx` 增加 `selectionBar` 插槽，批量工具栏在表格上方出现/消失，不改动模板原有筛选、分页与表格结构。
- 接入五个队列页：`/recognitions`、`/claims`、`/grades` 队列页签、`/deductions` 队列页签、`/appeals`。工作台、学生视角、名册页签不加批量入口。
- 刷新、翻页、筛选、切换周期与批量完成后清空选择；关闭结果框后刷新并保留周期、筛选和页码。
