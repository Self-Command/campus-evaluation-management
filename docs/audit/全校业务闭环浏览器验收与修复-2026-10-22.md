# 全校业务闭环浏览器验收与修复

日期：2026-10-22。方式：按用户要求，在真实页面用 Playwright + Microsoft Edge 模拟各角色人工操作，覆盖管理员建库配置、活动范围、名单与证明、三级申报退回、发布确认异议、锁定和四角色导出；发现的问题当轮修复并复验。本文是本轮本地验收记录，不是生产部署或真实学校数据验收。

## 1. 数据与环境边界

- 保留重要文档；只重置本地开发库 `campus_dev`：`npx prisma migrate reset --force --skip-seed` 后部署 21 个迁移，再通过 `npm run db:init-admin` 初始化本地管理员。未连接或修改正式数据库，未改动历史附件和 `更新星智智能体平台配置审计报告.md`。
- 本地凭据、验收脚本、状态与下载文件只保存在 `.local/`（已由 `.gitignore` 忽略）；本文不记录密码、Cookie 或数据库连接串。
- 环境：Next.js 16.4.2、Prisma 7.10.1、本地 PostgreSQL 18.4（127.0.0.1:55432）、开发服务 127.0.0.1:3000、Playwright 1.58.2（Edge，串行，1 worker）。
- 验收脚本为 `.local/runtime/e2e/school-acceptance.spec.ts`，进度状态在 `.local/runtime/acceptance-state.json`，下载文件在 `.local/runtime/downloads/`。脚本依赖本地账号和真实数据，不作为仓库内可重复测试。

## 3. 本轮发现与修复

| 问题 | 现象与原因 | 修复 | 复验 |
|---|---|---|---|
| 首次改密失败 | 改密页面提交 `oldPassword`，密码接口读取 `currentPassword`，首次登录用户无法完成强制改密 | `src/components/dashboard/auth-form.tsx` 改为提交 `currentPassword` | 管理员、辅导员、学院管理员、学生的首次改密流程全部走通 |
| 活动页残留逐人计分文案 | 活动列表仍显示“每人单独录分 · 最高X分”，并把受众描述为“学院、专业或班级” | `src/app/(workspace)/activity-feed/page.tsx` 统一为固定分值，受众改为“学院和班级” | 学生可见“统一 5 分”，页面无逐人录分入口 |
| 长列表下拉溢出 | 周期来源、扣分项目、扣分模块、扣分范围（学院/专业/班级）使用原生下拉，数据增长后难以选择 | 新增 `src/components/dashboard/searchable-select.tsx` 并替换上述选择器；保留隐藏原生 select 供 FormData 提交 | Playwright 分别搜索“校规”“搜索模块名称”“搜索周期名称”并成功选中 |
| 表单重置后搜索选择器不同步 | 原生 `form.reset()` 只重置隐藏 select，React 内部选中状态仍保留旧值 | 扣分登记提交并重置后递增 key，重新挂载选择器 | 连续登记扣分时项目选择恢复默认值 |
| 旧版 E2E 用例误导 | `tests/e2e/` 中登录、活动、账号、周期用例基于前端重建前页面，且包含已删除的逐人计分 | 移至 `tests/e2e/legacy/`，`playwright.config.ts` 增加 `testIgnore: ["legacy/**"]`，并在 `docs/development.md` 说明 | `npx playwright test --list` 当前只列出 `quick-scheme.spec.ts` |
| 本地数据库中断 | 验收中途嵌入式 PostgreSQL 停止监听，页面报无法连接数据库 | 用 `npm run db:local` 重启原数据目录，未重新初始化；恢复后继续验证 | 重启后数据完整，验收继续通过 |
| 核对截止未到导致无法锁定 | 首次发布把截止设为年末，检查锁定条件按业务规则拒绝；属于正确拦截 | 在已开始的本地验收中把该次 `checkingEndsAt` 调整为已到期；新脚本改为发布时填写约 2 分钟后的截止并等待 | 锁定检查通过并生成快照；阻断规则未被削弱 |

固定分值与受众收敛的数据库迁移为 `prisma/migrations/20261022150000_activity_fixed_score_only/`：删除 `Activity.scoreMode`、`Activity.audienceStudents`、`Participation.score`。活动只保留学院/班级受众和统一分值，不存在按学生指定参加或逐人录分的入口。

### 3.1 证据查看修复（当日追加）

用户反馈查看证明材料可能无法加载。逐入口核验后确认 `/api/evidence/[id]` 下载鉴权、文件签名与 SHA-256 校验、图片预览本身可用，但有三处会让入口“看起来打不开”：

| 问题 | 现象与原因 | 修复 | 复验 |
|---|---|---|---|
| 活动详情深链未生效 | 认定页与导入页的“查看活动详情与证明”链接携带 `?tab=evidence`，活动详情却只识别参与名单筛选参数，一律落到活动概览 | `src/app/(workspace)/activities/_components/activity-detail.tsx` 按 `tab` 计算初始页签，并校验当前角色可访问该页签 | 管理员直接访问 `?tab=evidence`、`?tab=participants` 均打开对应页签并加载名单；辅导员从认定页点击链接后落在活动证明页 |
| 成绩页缺少活动证明 | 结果数据只返回申报证据 ID，未带入参与记录关联的活动证明；成绩页因此只能看到申报材料 | `src/server/results.ts` 为已通过参与带入 `activityEvidence.evidence` 与来源附件文件名；`result-view.tsx` 渲染活动证明及真实文件名，申报材料保留旧快照的序号回退 | 在临时进行中周期内由学生账号查看成绩页：活动证明 PNG 正常显示，PDF 接口返回 200 `application/pdf`，均可下载；临时周期、活动、名单和附件已清理 |
| PDF 预览可能一直显示加载中 | 预览把 `<object onLoad>` 当作 PDF 就绪信号，部分浏览器不触发该事件，“正在打开PDF…”不会消失 | `src/components/dashboard/evidence-viewer.tsx` 对 PDF 不再等待 `onLoad`，就绪后直接显示文档并提供新窗口/下载说明 | PDF 对话框正常出现文档对象和下载入口，无“正在读取证明材料”残留，无页面脚本错误 |
| 旧发布快照不会自动补字段 | 核对/锁定阶段读取的是发布时冻结的 `PublishedResult.payload`，新增字段只存在于修复后的新发布 | 保持快照不可变，不回写历史结果；活动证明在之后的发布版本中进入成绩页 | 临时周期使用实时结果验证通过；本地已锁定周期未改动 |
