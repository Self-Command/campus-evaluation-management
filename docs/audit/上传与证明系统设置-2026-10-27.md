# 上传与证明系统设置实施记录（2026-10-27）

状态：已实施（0.6.0），待发布部署。

## 1. 背景与决策

0.5.2 为活动附件引入服务端图片压缩后，用户要求把上传相关参数纳入管理员系统设置。经调研（现状盘点：活动附件三项已可配置；证明上传 5MB/类型、品牌图上限、导入行数与压缩参数全部写死），用户批准方案：

1. 证明文件大小上限（1–50MB，默认 5）；
2. 图片自动压缩开关（默认开）；
3. WebP 压缩质量（50–95，默认 80）；
4. 证明允许类型复选（图片 / PDF，至少保留一种）。

配套决策：证明上传接入压缩管线（只放宽上限不压缩会复现大图传输失败）；压缩触发阈值（300KB / 最长边 1920）与处理超时保持工程内部参数不暴露；品牌图上限、导入行数、上传限流不纳入设置。设置页"活动附件"页签改名"附件与上传"。

## 2. 实现

- `src/lib/settings-schema.ts`：新增 `evidenceAllowImage`、`evidenceAllowPdf`、`evidenceMaxSizeMb`、`imageCompressionEnabled`、`imageCompressionQuality` 五个字段（含默认值与范围）。设置存于 `SiteSettings.content` JSON，无需数据库迁移，旧数据由默认值兜底。
- `src/server/settings.ts`：`saveSettings` 校验证明类型不能全部关闭。
- `src/server/image-normalize.ts`：`normalizeUploadedImage` 增加 `{ enabled, quality }` 选项，缺省行为不变。
- `src/server/evidence.ts`：大小上限、类型白名单（上传仅 PNG/JPEG/PDF 输入）与压缩参数全部读取设置；证明图片（非 PDF）走压缩管线，PDF 原样保留；下载完整性校验 `detectEvidenceMime` 兼容压缩产物 `image/webp`；新增 `evidenceLimits()` 供前端下发。
- `src/app/api/evidence/route.ts`：流式大小预检改为读取设置。
- `src/server/activity-attachments.ts`：`attachmentLimits()` 返回压缩参数，上传按设置压缩。
- `src/server/restore.ts`：恢复差异白名单同步五个新键。
- 前端 `evidence-upload.tsx` 新增必填 `limits` 属性（大小、类型、提示、accept 随设置渲染）；`/activities/[id]`、`/claims`、`/results` 三个服务端页面取数下传；设置页 UI 按既有字段模式新增五个控件与"至少一种证明类型"校验。

## 3. 测试与证据

- 集成（隔离库）：`settings-themes.test.ts` 新增"上传与证明设置可保存回读，证明类型不能全部关闭"（保存回读、全关拒绝、范围拒绝）；`evidence-preview.test.ts` 新增"证明大小上限与类型白名单按系统设置执行"（1MB 上限拒绝、PDF 关闭拒绝、图片关闭拒绝）与"证明图片超过阈值自动压缩为 WebP，开关关闭时保留原样"（压缩产物 RIFF/WEBP 魔数、关闭后原样、小图不受影响）。全套 34 文件 / 165 项通过。
- typecheck、lint（0/0）通过。

## 4. 交付边界

- 品牌图上限、导入行数/字节数、上传限流阈值仍为工程参数，未纳入设置。
- 压缩触发阈值与超时保持写死；关闭压缩开关后所有图片原样保存。
- 浏览器视觉验收由用户执行；发布部署待用户指示。
