# 界面体验与设置修复记录

日期：2026-10-22。本轮按用户直接反馈修复：结果页模块得分难懂、评分方案只能配两级、系统设置保存与主题不生效、登录验证码无法辨认。记录实际修改与实测证据；浏览器视觉与交互仍由用户亲自验收。

## 一、结果页「模块得分」改为嵌套卡片

原界面把全部模块平铺成一列按钮，右侧再列出「汇总 → 封顶 → 折算 → 扣分 → 最低计入分 → 计入上级」这类术语链，普通学生难以读懂。

- 左侧改为**按层级嵌套的卡片树**：根模块「综合测评成绩」内含大模块，大模块内含子模块，逐层缩进并以虚线左侧边标示层级；每张卡片显示模块名、类型、本模块计入分，以及「计入上级 X 分」或「占上级权重 w」。
- 卡片整块可点击，选中项高亮；右侧「这一项怎么算」只列出**本模块实际发生**的步骤，用业务语言说明：原始成绩/子模块合计 → 封顶 → 折算 → 扣分 → 最低计入分 → 本模块计入分 → 计入上级。没有封顶、折算、扣分或下限时不再显示对应行，也不再出现箭头术语链。
- 支撑改动：`calculate()` 在模块明细中补充 `kind`、`weight`、`order`，用于层级与顺序渲染；旧发布快照缺少这些字段时界面按「评分模块」降级显示，不报错。
- 默认选中根模块，进入页面即可先看到总分构成，而不是某个叶子节点。

## 二、评分方案允许多级子模块

- 校验层原本就支持任意层级（汇总模块必须有下级、输入模块不能有下级）。限制来自界面：只有当前计分方式为「汇总/比例」的模块才显示「添加下级」，二级模块默认是输入项，于是看起来只能配一级。
- 现在每个可编辑模块都显示「添加下级」。对仍是输入项的模块，确认后自动把它改为汇总模块并新增下级；提示明确说明「这一级不再直接录入分数」。
- 服务端仍按原有引用规则拦截：已有成绩的模块若被改成汇总模块，保存时会提示「已有成绩的模块…被删除或类型改变」，不会静默丢数据。

## 三、系统设置：保存与主题

- **保存不可达的问题**：修改理由原本在页签内容最底部，未填写时保存被拒并只把焦点移到一个可能不在视口内的字段，用户感觉「保存没反应」。现在修改理由固定在页头操作区，与「保存并生效」按钮同一行；按钮不再因为「没有改动」而禁用。
- **主题不生效的问题**：原「基础主题」只有默认/紫色/蓝色三项，其中默认与紫色的主色完全相同，切换后视觉没有变化。现在改为**完整主题**而非配色：默认、粗野、柔和、蜜橘四套，分别调整圆角、描边、阴影与主色，来自项目已引入的同源 `src/styles/presets/*.css`（含深色变体）。设置页以卡片列表展示每套主题的名称、说明与主色，选中后在右侧预览区即时按该主题渲染；保存后全站 `<html data-theme-preset>` 生效。
- **兼容旧数据**：历史记录中的 `violet`/`blue` 已不在可选范围。读取时容错回退为默认主题，避免旧记录导致全站设置解析失败；写入仍使用严格校验，非法值依旧拒绝。
- 服务层测试覆盖：保存并回读、并发冲突只有一个成功、越权拒绝、非法主题拒绝、历史配色值读取回退。

## 四、登录验证码

- 原实现把 5 个字母压缩在 178×54 画布里，使用 ±15° 旋转、随机纵向抖动和 **7 条深色干扰线**；干扰线与笔画混在一起会被看成额外的字母，用户"看到多个字母、怎么输入都错"。
- 现在画布扩大到 208×64，字母按 1.7 倍描边放大、间距 36、旋转收敛到 ±7°，干扰线减少为 3 条浅灰细线；答案仍以向量笔画绘制，响应中不含 `<text>` 或明文答案。
- 登录限流从全局 200 次/15 分钟提高到 1200 次/15 分钟（验证码 2000 次/15 分钟），避免正常使用或反复刷新时整体被拦；账号级失败锁定仍在「系统设置 → 登录安全」中按需启用。
- 实测：图片 208×64、5 个字母笔画、3 条干扰线；错误验证码返回 `CaptchaInvalid`；正确验证码可通过校验并进入真实密码校验（本次用本地账号夹具验证，密码不再匹配的账号只能验证到这一层，未改任何账号密码）。

## 七、后续补充（2026-10-22 同日）

### 拖动改造

- 原实现按下后移动超过 8px 即取消长按计时，导致正常鼠标拖拽永远无法开始；现在鼠标一移动即进入拖动，触屏保留约 0.2 秒长按以不干扰滚动。
- 拖动开始时对列表容器调用 `setPointerCapture`，拖到行外松手仍能落点并在结束时释放捕获。
- 落点规则最终定为：汇总/比例类模块都能接收移入（含尚无下级的空分组，便于任意嵌套）；输入类模块只接受上沿/下沿排序；根模块不可拖动。此前“落点必须已有下级”的临时限制已撤销。
- 已删除「移动到」按钮、「放到前面/后面/移入」按钮组与移动对话框，行内只保留「设置」「添加下级」。

### 主题来源

- 先按用户要求移除了本轮自查加入的 Catppuccin、Tokyo Night 两套手写映射（含 CSS 文件、`globals.css` 导入、`THEME_PRESET_OPTIONS` 与设置枚举），恢复为模板自带的默认/粗野/柔和/蜜橘四套。
- 下一批主题统一取自一个项目的成套主题，已选定 [tweakcn](https://deepwiki.com/jnsahaj/tweakcn/3.6-theme-presets-and-data#1)（jnsahaj/tweakcn）的 shadcn 主题注册表：其每套主题以 `cssVars` 形式给出 light/dark 两组变量，与 `src/styles/presets/*.css` 的变量名一致，可整套落盘并保留来源与署名；备选 [miketromba/shadcn-themer](https://github.com/miketromba/shadcn-themer)。不再手工近似配色。

### 构建环境注意

- 本地嵌入式 PostgreSQL 会被工作进程结束事件带走。构建前若出现 `Can't reach database server at 127.0.0.1:55432`，先 `npm run db:local` 再 `npm run build`；本次即因此失败一次，重启数据库后构建通过。
