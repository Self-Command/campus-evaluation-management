# 活动详情操作区与状态合并

日期：2026-10-22。范围：按[角色视角UI规范与页面改造分析](角色视角UI规范与页面改造分析-2026-10-22.md) 4.1「活动详情右侧操作区」与 P1 第 4 项。本文只记录本轮实际改动与命令行证据，不代替用户浏览器验收。

## 1. 改动前的问题

`/activities/[id]` 详情页右栏把 7～9 个同权重描边按钮竖排（上传证明、导入名单、确认分值、编辑活动、移交学院、确认范围并发布、撤回活动、预览得分更正），标题下还并排 5 个状态徽章（周期阶段、主办学院、分值确认、发布、名单）。结果是：

- 看不出“下一步该做什么”，主操作和低频操作混在一起；
- 五个徽章要读者自己拼装活动状态；
- 学院、辅导员、学生也会看到与自己无关的操作位（虽然后端会拒绝）。

## 2. 实施结果

| 位置 | 改动 |
| --- | --- |
| 标题区徽章 | 五个徽章合并为两个：周期阶段 + 当前活动状态（待确认分值 / 待发布 / 名单待提交 / 已发布），主办学院改为紧随其后的次要文字 |
| 右栏 | 新增“当前状态 + 一句下一步说明”信息块；其下只保留一个主按钮（下一步），其余收进“更多操作”菜单 |
| 主按钮判定 | 未确认分值且是管理员 → 确认分值；已确认未发布且可管理 → 确认范围并发布；已发布 → 导入参与名单 / 补录或更正名单；其余角色无主按钮，只读 |
| 更多操作菜单 | 上传或更换活动证明、编辑活动信息、移交主办学院（管理员）、预览得分更正（管理员且已确认）、撤回活动（可管理且已发布，红色分隔）；已确认未发布时额外提供名单导入入口 |
| 只读与角色文案 | 阶段或周期状态不可操作时，状态块补一句“当前阶段或周期状态只读，需管理员重开后才能操作”；学生看到的是本人视角说明（学院统一登记名单、到“我的参与”看审核进度与退回原因），不显示管理动作 |

- 未改任何接口、权限判断或审核链；按钮背后的动作仍是原来的 `confirm`、`publish`、`unpublish`、`reassign`、`correct`、证明上传和名单导入。
- 使用项目已装的 Base UI 版 `DropdownMenu`（`render` 用法），没有引入新依赖。

## 3. 验证证据

- `npx tsc --noEmit` 通过（0 错误）。
- `npx eslint activity-detail.tsx --max-warnings=0` 通过。
- 本机开发服务 HTTP 检查（未操作浏览器）：管理员、学院、辅导员、学生四种身份打开同一活动详情均 200、无错误页标记，且都渲染了“当前状态”信息块。
- 当前开发库的周期处于锁定状态（`active=false`），因此“更多操作”与主按钮在检查中按设计不渲染，只显示只读说明；可操作状态下的按钮行为需用户在浏览器按周期阶段验收。
