# 登录页与主题个性化实施与验证（2026-10-24）

## 结论

版本 `0.2.0`。登录页与强制改密页已统一为全屏背景 + 居中卡片；所有角色可在登录页和登录后顶栏切换深浅模式与九种主题；管理员可设置站点默认主题、默认深浅模式、登录背景和登录公告，并可配置 Logo 显示尺寸。公开设置改为显式白名单，登录背景下重复用品牌资源表，未新增数据库表或迁移。

按用户要求，agent 已在本机隔离环境完成生产构建、自动化测试、HTTP 检查和浏览器视觉/逻辑验收，之后才进入 GitHub 与服务器发布流程。

## 实施范围

| 层 | 变更 |
| --- | --- |
| 设置契约 | `settingsSchema` 新增 `defaultThemeMode`、`loginBackgroundAssetId`、`loginNotice`；`logoSize` 保持 16–128、默认 28；旧设置缺字段按默认值读取 |
| 公开接口 | `GET /api/settings/public` 只返回站点名称、说明、页面标题、主题、默认模式、Logo/favicon、Logo 尺寸、登录背景和公告，不含 revision、登录失败策略和附件策略 |
| 品牌资源 | `POST /api/admin/brand-assets` 支持 `x-asset-kind: login-background`；背景限 PNG/JPEG/WebP、≤5MB、≤8192px；默认品牌资源仍限 PNG/JPEG/ICO、≤1MB、≤4096px |
| 资源读取 | 只有被站点设置引用的品牌资源可匿名读取；未引用资源仍需管理员会话；读取时校验真实签名与 SHA-256 |
| 认证页 | 新增 `AuthShell`，登录页与改密页共用背景、品牌、公告、主题入口和站点说明；保留真实身份选择、验证码、错误与强制改密 |
| 主题偏好 | 服务端输出站点默认主题/模式；`ThemeBootScript` 在 hydration 前优先读取个人 cookie，缺省回退站点默认；移除 hydration 后强制写回默认主题；主题 cookie 保留 365 天 |
| 共享控件 | `ThemePicker` 提供浅色/深色/跟随系统、九个预设主题和“恢复站点默认”；登录页右上与后台顶栏共用 |
| 设置页 | 新增“登录页”页签：背景上传/替换/移除、当前草稿登录卡预览、纯文本公告；标识页签补 Logo 尺寸与默认深浅模式；保存仍携 revision 与 2–500 字理由 |
| Logo | 登录页、侧栏、改密页和设置预览统一读取配置尺寸；侧栏折叠时最多 32px |
| 回归修复 | 发布页“缺失成绩”成绩深链在客户端自动打开对应学生成绩详情并回填名单搜索，避免服务端首屏不渲染详情时链接失效 |

明确未加入：证明上传限额、维护模式、站点草稿/发布/历史恢复、公开分享与 SEO、导航定制、邮件/短信/对象存储。相关说明继续留在设计文档的下一批清单，设置页不提供假入口。

## 数据与安全边界

- 未连接、写入或清空 `127.0.0.1:55432/campus_dev`；全部测试使用本机 55433 上的随机临时库，结束后删除。
- 背景与 Logo 只接受可识别真实文件签名的位图；拒绝 SVG、HTML、外链与脚本；不接受任意 CSS 或自定义主题包。
- 登录公告按 React 文本节点渲染，不使用 HTML 注入；公告与背景在设置页明确提示公开可见、不得包含学生个人信息。
- 公开设置不返回 revision、登录失败策略、锁定分钟数、附件策略、审计或密钥。
- 设置保存和品牌上传继续在管理员事务内复核会话、角色、`authVersion`、资源存在性和 revision；审计只记录资源 ID、用途、MIME 与大小。
- 未新增数据库表，未修改真实数据库或生产附件目录。

## 视觉与逻辑复核要点

- 桌面端背景铺满、卡片居中，品牌区与主题按钮不遮挡表单；长站名截断，不挤压操作按钮。
- 有背景时文字使用白色层级并叠加渐变遮罩；无背景时使用主题渐变，不请求外部图片。
- 深浅模式切换不改变卡片尺寸和字段顺序；九个主题均可读，选中态不仅依赖颜色。
- 登录页、改密页、后台顶栏的个人主题一致；退出登录后个人偏好仍只作用于当前浏览器。
- 设置页保存失败保留输入并定位到对应页签/字段；上传回调不覆盖其他页签草稿；上传中阻止离开。
- 登录失败、验证码错误、强制改密、背景移除后的默认回退均走真实接口，无假操作。
