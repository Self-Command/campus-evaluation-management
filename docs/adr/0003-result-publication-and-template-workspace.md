# 固定发布结果与统一测评工作区

2026-10-20。后续用户已批准17项缺口修复，参评名录/活动范围/更正与延期条款以[ADR0004](0004-activity-scope-and-correction-governance.md)为准；下方原决策保留历史。按用户已确认的简化范围：三基础角色、每周期一套方案、有界同步处理，不先建设通用任务平台。

## 发布与结算

ACTIVE实时结果供录入核对，发布事务冻结完整结果、姓名及组织归属、评分规则、输入与计算依据，设置当前发布指针并进入CHECKING。发布请求携周期修订、输入修订和UUID；重放返回原版本，换参数复用键拒绝。参评范围明确为发布时全部有效且有档案的学生，上限2000，不静默截断。待审/待补充及必需成绩缺失阻断发布。

确认绑定publicationId与本人resultHash。更正先填写理由重开，清空当前指针后回ACTIVE，重新发布生成新版本，旧确认不迁移。结果hash使用排序键的规范JSON，避免PostgreSQL JSONB键顺序改变校验。认可异议须关联该学生实际改变的后续当前发布结果，不能只改状态为已解决。

核对截止、必要确认、未决异议、待审及发布基线共同决定锁定。15分钟HMAC预检绑定操作者和状态，锁定事务重检后生成完整不可变快照。旧结果及快照不被姓名、转班或下一轮更正覆盖。所有周期事务先取共享账号管理锁再取周期锁；账号维护取前者独占，避免发布过程中范围变化及反向锁死。

数据库增量迁移只增加表、字段和枚举，不修改原密码、评分输入或附件。迁移前逻辑备份在临时数据库恢复并对照16张原业务表行数。附件未改，本次不把数据库恢复记作数据库+附件全量恢复。

## 模板和页面结构

完整模板是唯一前端起点。用户最新授权一个UI agent直接开发；主负责人实施后端与接入核对，用户自行浏览器验收。侧栏按角色与任务分组，登录和后台共享站点主题，普通账号安全留在后台，首次强制改密在受限独立路由。

用户否决每页先选学期且无业务内容的碎片页，随后明确不要靠合并职责解决。最新要求为页面完整、单一职责、高信息密度。周期上下文在业务间延续并明确显示；结果、成绩、扣分、学生档案、账号各自独立，认定、个人申报和异议也保留独立名录/队列。管理员先看到真实学生或业务列表，筛选分页后进入完整详情/编辑及历史；不再只有搜索框。周期工作区限总览与评分制度，其余流程通过带周期上下文的真实入口衔接。导航按组呈现各职责。

共享布局不得让内层profile标记清除外层正文边距。正文统一padding，页签/双栏/名录可收缩，表格在自身容器水平滚动，禁止全局裁剪掩盖控件越界。CSS源码修复和HTTP检查不等于实际视觉验收。
