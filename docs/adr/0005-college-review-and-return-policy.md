# 学院归属审核、辅导员评分与统一退回

2026-10-20。状态：用户确认，待实施。正式规范见[学院职责与统一审核规范](../product/学院职责与统一审核规范.md)。

## 背景

用户要求取消独立活动发布者身份，引入辅导员及学院审核，并进一步确认学生不能自报分数、辅导员通过前必填分、所有申请统一退回到原发起人且必须说明理由。用户接受评分错误交辅导员重评的必要例外，以及删除表示放弃但保留审核历史。此前三角色、个人活动 owner、追加导入及管理员单级审核无法表达新职责；学院一律逐级退给辅导员也会让学生无法直接处理材料问题。

## 决策

1. 学校管理员、学院管理人员、辅导员、学生四类身份；学院为活动归属组织。学生归属决定审核和数据范围，主办学院只维护本活动参与事实，跨院开放不授予外院学生管理或导出权。
2. 个人申报由学生提供事实与证明，辅导员针对当前修订评分并初审，学院只终审。空分不能初审通过，退回不要求评分；学院批准后计分。
3. 普通退回统一交原发起人，理由必填，修正后新修订重新办理必要审核；材料不变、仅评分错误时内部退回辅导员重评，学生只查看进度。
4. 退回申请可修改重提或逻辑删除放弃；审核、材料引用和原有效事实保留。已经生效的数据通过有理由更正/撤销处理。
5. 名单严格核对完整必需身份、任一错误零写入；一活动一份正式名单，后续走受控补录更正。证明在活动详情独立上传，不放入名单列。
6. 辅导员看到班级学生的全部参与记录。辅导员班级详细成绩及学生本人详细成绩使用模块树动态 XLSX，只有原始输入和规则参数为数值，派生合计/比例/总分以公式计算。
7. 学生直接提交标题、日期、说明、证明，不关联活动、不依赖事先配置的认定项目；删除申报项目管理及专用配置写入口。辅导员初审时从生效制度确定模块与分数，旧项目和活动关联只作为历史解释保留。

## 覆盖与保留

- 覆盖产品基线中三角色、限域和两级审核延后的旧条款；不引入通用可编排审批平台或多套评分制度，每周期仍一套生效制度。
- 部分覆盖 ADR0004 中“个人 owner 维护活动”“普通导入可追加”“管理员单级审核及普通退回终结”等目标行为；其既有实现与测试作为历史事实保留。
- 继续保留 ADR0004 的后台参与和学生信息流区分、事实去重、旧发布/确认/快照不可变、名录更正、核对延期、事务并发及数据保护。
- 不把旧角色改名、改文案或文档确认当作权限迁移和业务完成；旧账号/活动归属须明确映射，历史审批不补造。

## 代价与验证

需增量补组织、责任关系、评分版本、审核记录和申请生命周期；逐层校验角色、对象、修订、窗口及周期。正式规范 REV-01～12 为待实施验收。当前尚未实现或执行这些新增断言，本次仅写规范，未迁移、改密码、删除附件或推送新提交。
