# 活动范围、参与事实与更正治理

2026-10-20。状态：用户已批准修复17项审查缺口；本决策覆盖ADR0003中“每次发布都取当前名录”的条款。实现与实际检查见[修复记录](../audit/缺口修复实施与验证-2026-10-20.md)。

## 活动与参与

活动保存、分值确认和发布独立。学院、完整学院/专业/班级、指定系统学生三组均非空、组内OR、组间AND。以完整路径识别班级，不能按同名班级串入其他学院或专业。发布前服务端预检真实交集，签名token绑定操作者、范围与学生当前身份，提交时重新检查；变更已发布范围先撤回为草稿并审计原/新范围，重新预检才能再发布。

学生信息流按当前有效身份、当前已发布范围查询。“我参加的活动”仅按有明确后台登记的Participation读取；单人后台登记及追加导入保存操作者、时间、批次和当时身份。学生自行提交材料不冒充后台登记。历史参与不随转班、撤回发布或审核撤销删除，也不授予新的申报资格。旧LEGACY来源不自动推断为后台导入，旧活动不自动发布。

ADMIN/PUBLISHER均仅能为自有活动导入和录分；管理员分值确认、审核和文案维护不产生代他人登记权。FIXED保留全员固定分；INDIVIDUAL由owner登记后逐人录入0至活动分值上限。缺分不得审核通过，改已通过个人分使来源回待审，审核通过才计分。导入追加、漏行不删除，重放不重复写入。

## 退出、更正与同一事实

本人待审/待补可撤回；管理员可对待审/待补填写理由终结为REJECTED并保留历史。重新提交按当前角色、对象归属、范围、项目启用状态及材料所有权授权；已撤销REVOKED来源保留为历史，新提交创建新来源。

ACTIVE生效规则、已确认活动计分和认定项目可经全量影响预览、签名token、当前revision与理由事务更正；检查既有活动/项目/成绩/有效扣分的引用，不允许删除或改变已引用节点类型。个人分已有记录不切换计分方式；降低上限不能小于已有个人分。CHECKING/LOCKED先理由重开，再更正和生成新发布；旧发布/确认/快照不改。

个人申报事实标识按学生+周期唯一。可明确关联活动；活动认定和同活动关联个人申报不能同时通过，两个审核方向均在同一周期事务内检查。没有明确关联的事实由审核人员核实，不按相似标题自动合并。成绩与扣分基于真实审计提供20条分页的前后值、操作者、时间及理由；历史查询不改已发布分数。

## 发布名录与核对

首次发布取当前全部有效有档案学生；最多2000，超过明确拒绝，不截断。预检token绑定完整身份名录、规则、输入及四类待审/待补计数，提交时重算；预检后新增、停用、转班或修改输入会要求重新预检。

重开默认PREVIOUS原发布参评名单和身份。管理员可查阅、更正其中已停用或转班学生的成绩/扣分，无需重启账号。新学生不会无提示加入；可填写理由显式改CURRENT，预检列新增/移除名单，然后重新发布。保留原名录仍检查完整当前名录差异，超容量时拒绝不冒称完整。

核对截止独立治理：CHECKING管理员可填写理由延长为未来且晚于当前有效截止的时间，通过PublicationExtension追加记录，不覆盖原发布截止、规则、分数、哈希和已完成确认。学生工作台、确认、异议和锁定使用有效截止。不会自动代确认或豁免确认；未完成必要确认仍阻断锁定。

## 迁移与验收

迁移只加字段、索引和PublicationExtension表；不清库、不seed、不改密码、不删附件。先备份，再在随机临时库恢复至最新迁移，逐字段核对原记录，最后部署并核对原库。Decimal备份及比对使用文本避免JSON数字精度损失。

前端只能由指定完整模板页面适配，逐页记录来源；一个获授权UI agent实施页面，主负责人实现后端并核对契约。用户自行浏览器验收，CLI测试、HTTP和构建分别记录，Docker暂缓。
