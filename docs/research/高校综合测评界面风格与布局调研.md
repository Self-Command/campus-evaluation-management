# 高校综合测评界面风格与布局调研

调研日期：2026-10-19。依据当前正式规格、术语表及两份 ADR，核查七份官方设计资料。本文是设计建议，不变更已发布规格或任务状态；尚未开展真实师生访谈和可用性测试。

## 结论与下一步

**适合采用浅色、克制的现代工作台：蓝灰文字、靛蓝主色、稳定侧栏，主体以表格和清晰的成绩解释为核心。学生端降低密度，管理员端按任务提高密度，沿用同一套视觉语言。** 学校身份可体现在标识、标题与少量品牌色中，不必把每页都做成校园宣传门户。

现在适合进行聚焦式界面原型验证。项目已经完成需求、技术选型、正式规格和任务拆分，无须重新从需求访谈起步。原型要解决三个可见问题：学生能否解释自己的分数；管理员能否一边看证明一边审核；评分树与批量导入是否清楚。颜色选择服务于这些任务。

项目依据：[README](../../README.md)、[正式规格](../../.scratch/comprehensive-evaluation/spec.md)、[术语表](../../GLOSSARY.md)、[Next.js 决策](../adr/0001-nextjs-application.md)、[部署决策](../adr/0002-local-production-deployment.md)。后文的配色、尺寸、布局和优先级均为结合这些约束作出的设计推断。

## 官方资料支持什么

1. **导航可组合。** shadcn/ui 的 Sidebar 提供分组、子菜单、展开与折叠、移动端状态以及主题变量。它支持现有技术方案搭建统一外壳，但不能代替本项目决定菜单和角色权限。[Sidebar 官方文档](https://ui.shadcn.com/docs/components/base/sidebar)
2. **业务表格需要组合。** shadcn/ui 的 Data Table 是基于 Table 与 TanStack Table 的构建指南，覆盖排序、筛选、分页、列显隐、行选择；官方明确没有把所有业务需求包装成单一通用表格。[Data Table 官方文档](https://ui.shadcn.com/docs/components/base/data-table)
3. **按信息结构选择容器。** Ant Design 将表格用于结构化数据的查询、分析与操作，树用于层级关联数据，卡片适合较轻、较个性化的信息分组。因此本项目的名单用表格、评分配置用树、学生待办用少量摘要卡更合理。[Data Display 设计规范](https://ant.design/docs/spec/data-display/)
4. **批量与单条操作应区分。** Carbon 的可选表格通过勾选进入批量操作，顶部出现操作条；工具栏承载筛选、导出等全表动作。它提供了审核名单与导入预览的交互依据。[Data table 官方指南](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)
5. **提交前给出核对机会。** GOV.UK 建议在中小型事务提交前提供答案检查页，按区块组织信息并允许返回修改；按钮应明确说明实际动作。本项目可借鉴到导入提交、规则变更和结算锁定，不必照搬其政府网站视觉。[Check answers 官方模式](https://design-system.service.gov.uk/patterns/check-answers/)
6. **表单布局有不同适用条件。** Ant Design Form 提供水平、垂直、行内布局，并在窄屏调整标签排列。本项目建议筛选区采用紧凑行内布局，申报和节点编辑采用标签在上的表单；只借鉴规范，不引入第二套组件库。[Form 官方文档](https://ant.design/components/form/)
7. **可读与可操作有可验证底线。** WCAG 2.2 要求普通文字通常至少 4.5:1 对比度、大字至少 3:1；信息不能只靠颜色表达；目标尺寸最低要求为 24×24 CSS 像素并有例外条件。错误要定位并用文字说明。设计建议关键按钮取更宽松尺寸，表格也保留键盘操作与清晰焦点。[WCAG 2.2 官方标准](https://www.w3.org/TR/WCAG22/)

## 三种方向的比较

以下是设计方向比较，不是对真实师生偏好的统计。

| 方向 | 视觉与布局 | 适合之处 | 代价与采用建议 |
| --- | --- | --- | --- |
| 克制现代工作台 | 灰白背景、蓝灰文字与靛蓝动作色；侧栏＋页面标题＋筛选表格＋按需详情 | 同时容纳学生查询、发布者提交和管理员处理；与已选 shadcn/ui 容易保持一致 | 容易显得通用，可用校名与少量品牌元素补足识别；推荐作为全站基础 |
| 校园服务门户 | 森林绿等校园品牌色、顶部导航、宽松任务卡和材料卡 | 学生首页、活动浏览、申报入口的亲切感较好 | 多记录比较、规则配置和批量操作占空间；借鉴气质与学生首页，避免全站卡片化 |
| 高密审核工作台 | 灰白与青色强调、窄导航、名单／证明／操作三栏 | 桌面连续审核时减少跳转，便于对照材料与认定依据 | 窄屏拥挤、注意力竞争较强；仅作为审核详情的场景布局 |

推荐组合为“现代工作台外壳＋学生端较宽松＋审核详情可切三栏”，三者共用字体、按钮、状态色和间距。无需为三种角色设计三套品牌。

## 建议的视觉基线

采用浅灰背景、白色内容面板、深蓝灰正文、靛蓝主按钮，分隔优先用细边框。圆角以 8—12px 为起点，阴影轻用。绿色保留给通过或完成，琥珀色表示待处理，红色表示错误、驳回或危险动作，始终同时显示文字。

正文使用清晰的中文无衬线字体，14—16px 为起点；数字采用等宽数字特性，成绩右对齐。少用装饰性大字、宋体数字和大面积渐变，以便比较姓名、学号、分数与状态。学号按文本呈现，保留前导零。

桌面原型可从约 224px 侧栏、56—64px 顶栏、24px 内容边距开始。普通表格行高约 44—48px，复杂证明列表可加高；这些是待验证参数。学生表单不必拉满宽屏，名单表格和评分配置则利用可用宽度。

窄屏将侧栏收进抽屉，详情与证明改为前后切换，表单单列。学生查询与申报优先保证手机可用；管理员复杂配置先保证桌面清晰，避免把桌面三栏等比例压缩。

## 角色与核心页面布局

| 页面／角色 | 主要布局 | 首屏要回答的问题 |
| --- | --- | --- |
| 学生首页／我的测评 | 学期与阶段提示，结果摘要、待办，下面为分项明细和认定记录 | 我现在能做什么？结果完整吗？分数从哪里来？ |
| 学生活动／申报 | 简洁列表或轻卡片；详情用正文＋固定项目信息；材料表单单列 | 活动要求、申报项目、统一原始分及材料要求是什么？ |
| 发布者工作台 | 我的活动表格，详情中分活动信息、参与名单、共享证明、处理结果 | 哪份名单有问题？哪些记录已处理？ |
| 管理员待办／审核 | 状态筛选＋结构化队列；进入详情后左名单、中证明、右认定信息与操作 | 当前审核谁、依据什么、归入哪一评分模块？ |
| 管理员评分配置 | 左侧可展开评分树；右侧当前节点表单；试算结果按需展开 | 当前节点位于哪里、怎样汇总、怎样影响上级？ |
| 管理员成绩／结算 | 筛选表格＋完整性与待办摘要；锁定前显示检查清单与结果范围 | 谁缺输入？谁有异议？锁定的究竟是哪批结果？ |

名单和成绩页采用“标题与动作—筛选—表格—分页”。不要把学院、专业、班级选择做成评分方案切换：它们影响名单与排名范围，同一学期仍然统一使用一套方案。首页摘要优先展示缺失成绩、待审核与异议等可行动事项，不用大量占位统计图。

评分树应显示完整父级路径，按需展开；比例只在父级采用比例汇总时显示为必要输入。封顶、满分折算、扣分、下限分别分组，关闭的能力不伪装成默认规则。深层结构提供路径和定位能力，避免无限横向缩进。

批量导入建议分为选择文件、列对应、预览校验、确认提交、处理结果。预览必须区分新增、相同值、已有成绩变更及错误行，并定位行号和字段；确认页说明覆盖范围。批量审核明确显示所选数量与记录，每条失败可追查。预览完成不等于已经入库，部分失败不显示整批成功。

## 原型必须守住的业务表达

- **分数链路：** 区分原始分、封顶后结果、可选折算、节点扣分与贡献解释，沿路径展开。某活动原始分乘比例，只能作为按比例的说明；实际总分增量须用相同规则的前后结果比较，父级封顶、下限或扣分可能改变增量。[正式规格 D-07](../../.scratch/comprehensive-evaluation/spec.md#d-07-独立评分输入输出与计算顺序)
- **上限与缺失：** 写“封顶30分”，不能把它自动写成“满分30分”或达成率分母。必需成绩缺失显示“待录入／结果不完整”，明确录入的零显示“0.00”；活动无有效认定可按零处理，三者语义不同。[正式规格 D-06、D-08](../../.scratch/comprehensive-evaluation/spec.md)
- **排名范围：** 名次旁同时展示学期、学院／专业／班级范围及结果状态。不完整结果单列，学生只看本人名次；同分按对外成绩并列，避免显示相同分数却给出不同名次。[正式规格 D-12](../../.scratch/comprehensive-evaluation/spec.md#d-12-学生核对异议排名与导出)
- **变更与锁定：** 生效方案修改先展示受影响人数和示例差异；结算页列出缺失输入、待审核、未解决异议和重算状态。锁定后提示快照时间及只读状态，更正要求理由和重新开放流程；结果变化后旧确认不能冒充新确认。[正式规格 D-05、D-13](../../.scratch/comprehensive-evaluation/spec.md)

首轮原型优先做三张主页面和两段流程：学生成绩解释、管理员证据审核、评分树编辑；名单导入预览与结算前核对。使用相同虚拟数据验证“待录入与零分”“触及封顶后活动仍保留但总分不增加”“锁定后的更正入口”。通过这些页面确认布局，再进入已发布任务的实现；不以静态效果图替代业务验收。
