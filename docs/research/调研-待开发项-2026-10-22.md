## 二、拖动：原生 HTML5 DnD vs 指针事件

**已发生的实测事实**：
- 自写的指针事件方案（长按 180ms + `elementFromPoint` 命中）在本机浏览器里多次“移动无效”。定位到两个原因：按下后一移动就取消了长按计时；触屏/文本选择会打断 `pointermove`。改成“鼠标一移动即拖动 + `setPointerCapture`”后仍被用户判定无效。
- 表格行由 `DataTable` 内部渲染，无法给 `<tr>` 传 props，导致必须用事件委托 + 命令式设置 `draggable`。

**调研结论**：
- 原生 HTML5 拖放（`dragstart` / `dragover` / `drop` / `dragend`）是浏览器内置、无需第三方库、桌面端最稳的方案；对 `<tr>` 设置 `draggable = true` 后拖放可正常工作，事件会冒泡到列表容器，可用委托处理。参考 MDN [HTML Drag and Drop API](https://developer.mozilla.org/en-US/docs/Web/API/HTML_Drag_and_Drop_API)。
- 原生 DnD 不支持“长按才开始”，移动端触摸不触发原生拖放（移动端需另给“移动到”入口或用指针方案）。这与用户“长按任意位置拖动”的要求存在平台差异，需在下一轮明确：桌面原生拖放 + 移动端保留显式移动入口，或引入 dnd-kit。
- 若要一套代码同时满足桌面/触屏长按/键盘无障碍，主流做法是 [dnd-kit](https://github.com/clauderic/dnd-kit)（MIT，社区活跃，支持 `PointerSensor` 长按激活、`KeyboardSensor`、树形排序）。引入它是一个新依赖，需用户确认。

**本轮已实施**：`scheme-editor.tsx` 改为在 `useEffect` 里给表格行打 `draggable` 并用原生 `dragstart/dragover/drop` 委托处理；落点规则为上沿/下沿排序、中间移入（任意层级、可移出到父级同级）。代码已通过 `tsc`，`lint` 仅剩 4 条告警（旧的指针处理函数未删除、effect 依赖），功能等价代码尚未清理。

## 三、第 5 批：公式 XLSX 导出

**需求要点**（来自规范）：班级/学院/本人严格限域；模块树动态生成；叶子原始分、扣分、制度参数为数值输入；小计/封顶/折算/权重/扣分/总分全部是 Excel 公式；缺录与零分区分；冻结表头；打开即算，不依赖宏。

**选型对比**：

| 方案 | 许可 | 公式写入 | 风险 |
|---|---|---|---|
| 手写 OOXML（自己打包 zip + sheet XML） | 无新增依赖 | 直接写 `<f>` 节点 | 需自己实现 zip 写入与样式，工作量中等但完全可控 |
| [exceljs](https://github.com/exceljs/exceljs) | MIT | `cell.value = { formula: "SUM(...)" }` | 成熟、流式写入；新增依赖 |
| [SheetJS/xlsx](https://github.com/SheetJS/sheetjs) | Apache-2.0（社区版） | 公式支持有限，写入时会丢样式 | 样式与冻结窗格能力弱 |

**结论**：优先手写 OOXML（`node:zlib` 的 `deflateRaw` + 手工 zip 目录），因为项目已禁止无必要新依赖，且导出需要精确控制表头、冻结窗格、数字格式与 `<calcPr fullCalcOnLoad="1"/>`（打开即重算）。若后续发现样式工作量过大，再评估引入 exceljs 并记录许可。

**公式生成规则**（已可从 `src/lib/scoring/calculate.ts` 推导）：自底向上，子项合计用 `SUM`，封顶用 `MIN`，折算用 `比例×目标满分`，权重用乘法，扣分与下限按制度参数引用同一张“参数区”工作表，避免把比例写死在公式里。

**验收**：导出初值与同版本系统结果逐模块对账；改一个叶子分数后只有祖先与总分变化；缺录不转零；跨范围下载被拒。

| 列 G 起 | 按模块树前序展开，每个**最底层可录分模块**一列（叶子）；父模块只出现“小计”列，位置在其子列之后 |

### 公式规则（自底向上，只引用直接子项）

- 叶子 GRADE/ACTIVITY：该列为**输入单元格**（无公式），用户可改。
- 父模块小计：`=SUM(子列1:子列n)` 或 `=子列1*权重1+子列2*权重2`（比例汇总）。
- 封顶：`=MIN(小计, 上限)`；上限取参数区单元格，不写死数字。
- 折算：`=封顶/原始满分*目标满分`，两个满分都引用参数区。
- 扣分：`=折算-参数区扣分合计`；扣分合计本身由参数区明细 `=SUM(...)` 得出。
- 下限：`=MAX(扣分后, 最低计入分)`。
- 总分：`=SUM(顶层模块小计)` 或按顶层权重加权。

### 表 2「参数」

| 行 | 内容 |
|---|---|
| 1 | 表头：模块、上级、封顶、原始满分、目标满分、最低计入分、占上级权重、是否必填 |
| 2 起 | 每个模块一行，数值为**制度参数输入**，被表 1 公式引用（如 `参数!$C$5`） |

### 学校明细表版式（按用户提供的截图定稿，用于班级导出）

用户提供的样板是学校现行《综合素质测评成绩明细表》，按它的列序生成，不再单独摆参数表：

1. 第 1 行大标题：`<学校/学院><学年><学期><班级>综合素质测评成绩明细表`，居中跨全表。
2. 第 2 行分组表头：按顶级模块分组，文字形如 `基础性素质×80%`、`发展性素质×20%`（比例来自评分方案，直接写进标题）。
3. 第 3 行明细列头：`序号 | 姓名 | 学号`，随后每个最底层可录分项目一列，列头写「项目名 + 占比/上限」，例如 `红色文化引领工程 0.1（不超过100分）`；每组末尾给 `实际分合计 | 比例分 | 比例合计`。
4. 第 4 行起：一名学生一行，按学号排序；叶子列是可改的数值输入，其余全部公式。
5. 末尾固定三列：`扣分（法制与校规校纪×100%） | 合计 | 学生本人签字确认`，其中扣分与合计是公式，签字列留空。
6. 冻结：前 3 行 + 前三列（序号/姓名/学号）。
7. 参数（占比、上限、折算）写在**列头文字里**，不出现“封顶/原始满分/目标满分/最低计入分/占上级权重”这类内部术语；确需汇总参数时放最后一页「评分规则」，列名用 `单项上限 / 原满分 / 折算满分 / 最低分 / 扣分 / 占比`。

### 缺录与文本安全

- 缺录列留空，不写 0；总分列在缺录时用 `=IF(COUNT(...)=0,"","...")` 形式避免把空白算成 0。
- 学号等可能以 `= + - @` 开头的文本，全部按文本单元格写入（`inlineStr`），不执行公式。
- 文件命名：`成绩_<周期>_<范围>_<时间>.xlsx`，工作簿内不再出现其他学生数据。

### 列式班级表的关键陷阱（本轮试写后回退，下一轮按此实现）

第一次试写「一人一行、一模块一列」时，叶子列同时承担“原始输入”和“计入分”两个含义，父模块公式直接引用叶子输入列，导致叶子自身的**上限、折算、扣分、最低分四处变换被整体跳过**，总分偏大。结论与做法：

1. 每个节点都要有**表达式函数** `expr(id)`，叶子返回 `IF(输入列="","",变换(输入列))`，父节点返回子节点表达式按 `SUM`/权重组合后再套自己的变换；不要用“单元格引用”代替“表达式”。
2. 叶子列只放原始输入；父模块列和总计列放公式；不要指望一列同时表达输入与结果。
3. 生成后必须有一条测试断言：给定构造数据，公式展开后的手工演算值等于系统 `calculate()` 的结果；仅断言公式字符串存在不足以证明正确。
4. 相关测试还应覆盖：叶子带封顶 + 折算 + 扣分 + 最低分同时生效，以及缺录为空时不产生 0。
