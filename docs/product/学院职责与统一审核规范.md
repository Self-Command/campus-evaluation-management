# 学院职责与统一审核规范

日期：2026-10-20。状态：用户已确认的需求规范，待实施与验证。适用 ENT-02/06/07/08/09/10/13/15/17。

用户在连续需求讨论后明确要求“整理了写入规范”。本文件统一学院/辅导员职责、申报评分、退回修改、活动证明、严格导入和详细成绩导出。与旧文档中的三角色、管理员单级审核、学院统一退回辅导员、活动追加导入等条款冲突时，以本文件为准；决策背景见 [ADR0005](../adr/0005-college-review-and-return-policy.md)。本文件规定目标行为，不表示现有代码、数据库或页面已完成改造。

## 1. 角色、组织与范围

- 四类身份：学校管理员、学院管理人员、辅导员、学生。不再单设“活动发布者”角色；学院工作人员各用个人账号，活动归主办学院，创建人与经办人留痕。
- 建立学院→专业→班级目录，班级绑定当前责任辅导员，一名辅导员可负责本院多个班。学生绑定已配置班级，由系统推导专业、学院及责任辅导员，不使用自由文本或三套独立填写的归属。
- 学校管理员负责全校组织、账号、统一周期/制度、发布锁定和受控异常处理；学院负责本院学生终审和本院活动；辅导员负责所授权班级的初审、成绩和扣分提交；学生办理本人事项。
- 学院只能管理/审批/导出本院学生，辅导员只能管理/审批/导出授权班级，学生只能访问本人。服务端对列表、详情、统计、筛选选项、批量操作、导入、导出、证据预览/下载及历史查询统一限域。
- 跨院主办方只因本活动得到参与学生的必要身份、参加情况、本活动原始分和关联材料，不得到外院学生完整档案、其他成绩、个人申报、扣分或综合结果。普通导出仍只含本院学生。
- 组织/责任关系不完整时进入待完善清单，不能自动交给任意人审核。人员交接、转班及转院须受控移交，保留生效时间与历史归属，不改写已发布身份快照。

## 2. 学生申报保持简单，评分由辅导员负责

1. 学生直接填写申报标题、发生日期、必要事实说明并上传本人证明；无需先由其他角色创建“可申报项目”，不选择或关联系统活动。不设置申报分数输入，不让学生选择审核人员，也不暴露技术性事实标识作为普通必填字段。
2. 学生提交、补充、修改接口禁止接收其自报分数。前端隐藏字段不足以完成约束，不能信任改包提交的 score/points 等值。
3. 辅导员只能为授权班级申报评分。“通过并提交学院”前必须从生效制度选定可计分的最底层模块并填写该次申报分数，按该模块的计分约束校验；合法零分与未填写区别处理。退回修改不要求评分。学生不承担计分归类，不依赖独立申报项目目录。
4. 辅导员评分绑定当前申报修订及审核记录；不能只用项目固定值静默代替此次必需评分。学生可查看辅导员拟认定分及进度，学院终审通过之前不是正式有效分。
5. 学院只决定通过或退回，不直接修改学生个人申报的分数。学院批准后直接成为有效认定，不增加学校管理员终审。
6. “个人申报仅辅导员评分”不改变活动主办学院维护本活动原始分的职责；两类来源仍执行同一事实不得重复计分。

### 取消关联活动和申报项目管理

- 删除个人申报的关联活动选择、搜索、预选和新建/重提请求参数，不保留隐藏绑定或自动关联替代。新申报是独立事实申请，既有活动参与由活动业务维护。
- 取消“可申报项目/认定项目”目录、学生选项目、管理员新建/编辑/启停项目，以及专为该项目目录服务的更正、导航、按钮和写接口。不得换名为分类配置再恢复前置条件，也不能因为旧项目还有引用而继续开放该功能。
- 评分制度模块、活动管理及扣分规则有独立业务用途，继续保留；它们不成为“管理员先为学生建立具体申报事项”的替代目录。辅导员审核时选择计分模块和分数，学院只终审。
- 旧项目、旧活动关联及已认定分仅保留为历史解释依据，迁移不得删旧申报、材料或改变已发布分。旧字段的历史读取不代表新功能继续开放。
- 不再宣称依赖活动关联自动识别新个人申报与活动事实。系统保留可验证的同一申请/同一事实唯一控制；其他疑似重复展示可核实依据，由辅导员/学院检查，不能仅因标题相似自动合并或绕过已知重复事实计分检查。

## 3. 审核链与生效

| 业务 | 原发起人 | 正常审核链 | 生效时点 |
|---|---|---|---|
| 学生个人申报 | 学生 | 学生提交→责任辅导员评分初审→归属学院终审 | 学院批准后计分 |
| 非活动成绩 | 提交的辅导员 | 辅导员录入/导入并核对→归属学院审核 | 学院批准后成为有效输入 |
| 扣分 | 提交的辅导员 | 辅导员填写事件、项目、原始扣分、依据→归属学院审核 | 学院批准后扣分 |
| 活动参与/活动分 | 主办学院发起经办人 | 主办学院提交参与事实/原始分→按学生归属分派辅导员初核→对应学院终审 | 各学生所属学院批准后分别计分 |
| 补录、更正或撤销申请 | 发起该申请的人 | 按被更正业务的必要审核链办理 | 批准后原子切换有效版本 |

辅导员提交成绩/扣分已经承担初核，不再让其另点一次“审核自己的提交”。个人申报不能跳过辅导员直接被学院批准；同一人兼任身份不能代替该事项的全部必需审核。待审输入不影响正式分；已通过记录申请更正期间保留原有效版本，不能在新修订尚未批准时先覆盖正式分。

## 4. 所有申请统一退回修改

适用于有发起人和审核环节的个人申报、成绩/扣分提交、活动名单认定、补录/更正及异议补充等流程。规则统一不等于把发布、锁定、导出下载等不同业务硬改成同一审批链。

- 对外统一使用“退回修改”，不再用“驳回”“待补充”“拒绝”表示三个含义相同但走法不同的普通修正入口。历史状态码不因文案统一而自动改写。
- 任一级退回必须由当前有权审核人填写明确、非空、有长度限制的理由，说明需要修正的问题。前后端均校验，批量退回逐条检查权限、状态和修订；共同理由仅能用于确有相同问题的项目。
- 记录退回人、所在环节、时间、理由、原发起人、接收处理人和对象修订。原发起人由服务端确定，不接受客户端任意改收件人；离岗由受控交接指派经办人，原发起历史不变。

| 事项 | 普通退回接收人 | 禁止的错误去向 |
|---|---|---|
| 学生申报材料/事实问题 | 原学生 | 不逐级卡在辅导员处让其代学生改材料 |
| 辅导员提交的成绩、扣分问题 | 原辅导员 | 不退给被录分或被扣分的学生 |
| 学院提交的活动名单/原始分/活动材料问题 | 原主办学院经办人，或完成交接的经办人 | 不退给名单中的参加学生，不由学生归属学院代改活动事实 |
| 补录、更正、异议材料问题 | 发起该申请的人 | 不混淆被影响学生与申请发起人 |

原发起人处理界面仅保留“修改并重新提交”和“删除申请”等直接动作，展示具体理由、审核节点及历史。接收人完成修正后产生新修订，重新检查当前归属、角色、期限、周期阶段和重复事实，并从该业务第一必要审核环节重新办理；旧版本的通过记录仅保留为历史，不能直接沿用。个人申报再次到辅导员时，旧评分可作为历史参考，必须由辅导员针对新修订重新填写或确认有效评分后再提交学院。

### 唯一必要的内部例外：退回重评

学院确认学生材料无须修改、只是辅导员对个人申报评分不正确时，使用“退回重评”，交责任辅导员处理并填写评分问题理由。学生可查看原因和进度，不要求其重复提交材料，更不能让其改分。辅导员针对新评分修订重新确认后提交学院，旧评分审批不沿用。若同时存在学生材料问题，则使用普通“退回修改”交原学生；不能借“重评”代学生改事实、添证明或绕过完整审核。

中文状态建议为草稿、待辅导员、待学院、退回修改、待辅导员重评、已通过、已放弃。成绩/扣分可从提交后直接进入待学院。这些为业务语义，不宣称当前 Prisma 枚举或 API 已支持，不直接用文字替换数据库状态。

## 5. 删除表示放弃，审计与有效事实保留

- 退回申请由原发起人或完成受控交接的经办人执行“删除申请”，语义为放弃该申请并从正常申请/待办列表移除。保留提交版本、审核意见、理由、操作者和必要材料引用，不物理抹除已提交审核记录。
- 删除前检查当前状态、对象修订和权限；已被重新提交、审核通过或他人更改时不能使用旧页面删除。删除与重新提交并发只能有一种合法结果。
- 已生效认定、正式成绩、已生效扣分及已发布结果不能通过删除申请消失，应走有理由撤销/更正；被退回的是更正申请时，放弃申请不影响原有效成绩。
- 删除或撤销某条活动认定申请不等于删除活动出席事实。参与历史和计分状态分别保留；删除申请也不自动删除共享证明或历史已引用附件。
- 删除后即使重新发起，也须再次执行周期、归属、事实唯一和跨来源去重检查，不能借新申请重复计分。

## 6. 活动证明、参与可见性与严格导入

- 活动证明在活动详情单独上传并版本化，参与记录自动关联活动材料。CSV/XLSX 名单只含学号、姓名、学院、专业、班级及必要业务字段，不设证明文件、地址或证明编号列。名单可先准备和预检，提交审核时再核验必需证明。
- 活动普通导入逐项核对权威档案的必需身份字段和固定活动/周期上下文，再校验范围、分值及重复。任一行身份不符、缺字段、班级/辅导员未配置、越权、重复学生或非法分值，整份正式名单零写入，不用 SKIP 掩盖错误。只按约定处理首尾空白，不模糊匹配或自动覆盖学生档案。
- 一活动一份正式名单，首次成功提交后封存普通导入；失败预检可重试。重复文件、换名文件、换账号和并发提交不得形成第二份名单；同批次网络重试返回原结果。漏报、错分走有理由、差异预览和重新审核的补录/更正流程。
- 当前100人批次上限不是新需求中活动人数上限；若采用有界分段处理，各段属于同一草稿，全部校验成功才统一形成正式名单，不能部分生效后再发现错误。
- A 学院活动向 B 学院开放后，B 及符合范围学生可看到活动。A 维护本活动的参与事实及原始分，B 学生由 B 辅导员初核、B 学院终审，A 不能审批 B 学生的测评认定。
- 辅导员按班级看本班全部实际参与活动，包括外院主办、待审、退回、更正和已通过记录。名单成功登记即可显示，不等审核通过；参与可见不等于已计分，也不授予其他班级名单访问权。
- 图片、PDF 等允许且浏览器可显示的证据提供同一授权范围内的预览窗口及下载；不能因预览变公开链接，活动共享证明也不能暴露其他学生个人申报材料。

## 7. 详细成绩导出以公式计算

- 辅导员可导出所负责一个或多个班级的全部学生详细成绩，含缺录者；学生可导出本人，学院只导出本院。正式导出绑定对应发布/锁定版本的身份、规则与有效原始输入，不混用当前修改后的资料或待审成绩。
- 班级版每生一行、分层表头；个人版按模块树展开。覆盖所有大模块、小模块及更深层级、原始分、权重、贡献与扣分，根据系统制度动态生成。参考学校工作簿只抽象信息关系，不固定其模块名称、列位置或比例，不随代码分发原始学生文件。
- 导出为真正 XLSX：叶子模块有效原始分、原始扣分及权重/封顶/折算等规则参数为输入；小计、封顶结果、折算分、比例分、扣分合计、总分均存 Excel 公式，不写死后台派生结果。计算列仍显示，输入和公式区域清楚区分。
- 按制度自底向上执行汇总→可选封顶→可选折算→扣分→可选下限，再交父模块汇总/加权；只引用直接子节点，不把小计和展示比例分重复相加。用户修改输入后相关公式自动重算，不依赖宏或外部链接。
- 缺录与零分分开，必需输入缺失时不得伪装完整总分。导出初始结果必须与同规则版本系统结果对账，并验证封顶、精度、舍入和修改输入后的传播。文件本地修改不回写系统，正式成绩变更仍按审核处理。

## 8. 迁移、并发与验收

本次文档变更不执行迁移，不修改账号密码、附件或旧业务。后续先备份、隔离恢复并核对增量迁移；旧 PUBLISHER 及活动需明确学院归属和经办授权，不默认授予全校权限。保留历史审核依据，不伪造辅导员审批，不批量把旧 REJECTED/REVOKED 改成可重提，更不能复活已撤销事实。新流程有明确切换点和在途移交方案。普通重新提交仍受周期和窗口限制，CHECKING/LOCKED 不能用修改/删除绕过更正与锁定治理，旧发布、确认和快照不改。

后续最低验收如下，均为待实现断言，不是通过记录：

| 编号 | 必须验证 |
|---|---|
| REV-01 | 学生表单无分数，伪造评分请求被拒绝且零写入；学院不能修改个人申报分 |
| REV-02 | 辅导员空分不能通过、合法零分与未填写区分、越范围拒绝；退回不要求分数 |
| REV-03 | 未经辅导员不能学院终审，学院通过生效一次；同一人不能绕过必需审核 |
| REV-04 | 各环节无理由退回失败，普通退回正确到原发起人，历史及接收人可查 |
| REV-05 | 学院仅因评分问题退回辅导员重评，学生不补材料；兼有材料问题回学生 |
| REV-06 | 重提产生新修订并重走审核，旧分数/审批和旧页面不能直接生效 |
| REV-07 | 退回申请可逻辑删除，待办移除且历史保留；删除/重提竞态及共享附件引用安全 |
| REV-08 | 更正申请放弃不改变原有效分，参与事实与认定删除区分，旧发布快照不变 |
| REV-09 | 严格导入错误零写入，一活动普通导入一次、并发及网络重试不重复；证明独立上传 |
| REV-10 | 跨院活动正确分派；辅导员看到本班全部参与，详情/附件/批量/导出不能越权 |
| REV-11 | 班级及本人导出完整模块树；公式初始对账及修改输入后联动，缺录不伪装零 |
| REV-12 | 停用、转班、交接、阶段变化后旧待办/预览正确失效或受控移交，历史不改写 |

前端继续只能从指定完整模板源页改造并记录来源；用户自行操作浏览器与 Excel/WPS 验收。CLI、隔离数据库测试、HTTP、构建和实际交互验收分别记录；不以本规范、旧测试结果或公式字符串宣称新流程完成。
