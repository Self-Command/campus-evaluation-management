# 权限、数据范围与生命周期

日期：2026-10-20。状态：企业目标契约 v0.1，尚未完整实现。关联 ENT-01～15。当前证据见[现状台账](../audit/现状与功能缺口.md)。

## 1. 授权原则

权限由“当前有效会话 ∩ 基础角色 ∩ 对象范围 ∩ 周期阶段 ∩ 操作前置条件”共同决定。浏览器导航、URL 中的学生 ID、客户端缓存角色都不构成授权依据。停用、角色变化、密码重置及认证修订改变后，旧会话不能继续敏感操作；写事务内再次复核。

系统以单部署组织为边界，不因此引入多租户。组织目录表示学院、专业、班级等业务归属；管理员数据范围使用稳定组织 ID 与授权记录，不使用显示名称。迁移期间已有管理员保持现有全局范围，新增限域管理员需显式授权，不默认为全局。发布者的活动所有权不等于访问所有学生档案的权限。

## 2. 操作矩阵（目标）

表中“范围内”均须服务端检查；无明确授权一律拒绝。基础角色不允许通过自定义名称或图标扩大权限。

| 对象/动作 | 管理员 | 发布者 | 学生 | 附加条件 |
|---|---|---|---|---|
| 账号列表、创建、导入、角色调整 | 管理范围内；全局管理员才能授予全局权限 | 禁止 | 禁止 | 角色提升不可越过操作者范围 |
| 学生完整档案 | 范围内 | 禁止；认定名单只返回必要姓名/学号 | 本人 | 不提供任意学号枚举接口 |
| 密码修改 | 本人 | 本人 | 本人 | 验证旧密码，成功撤销全部旧会话 |
| 密码重置 | 范围内其他账号 | 禁止 | 禁止 | 理由、revision；不得重置自身 |
| 周期与适用学生范围 | 范围内维护 | 读取获授权周期 | 读取本人适用周期 | 匹配结果唯一，不隐式跨组织 |
| 评分草稿、模板、生效 | 范围内 | 只读已生效说明 | 只读本人适用说明 | 生效需完整校验及影响分析 |
| 活动创建/维护 | 范围内 | 本人负责且在授权周期内 | 禁止 | 分值/归属更正与普通文本维护分开 |
| 活动分值确认 | 范围内 | 禁止 | 禁止 | 确认当前 revision |
| 活动目录和详情 | 范围内 | 本人负责及明确授权可读对象 | 本人周期可见对象 | 草稿及内部备注不向学生公开 |
| 提交认定 | 范围内学生 | 本人负责活动的授权名单 | 本人 | 材料属于提交者、事实唯一 |
| 审核/撤销有效认定 | 范围内 | 禁止 | 禁止 | 不能以自有材料访问权代替审核权 |
| 个人项目申报/补充/撤回 | 代办必须留身份及理由 | 无默认代办权限 | 本人 | 截止及审核状态满足条件 |
| 成绩/扣分录入、覆盖、撤销 | 范围内 | 禁止 | 禁止 | ACTIVE；CHECKING 需更正通道 |
| 证明下载 | 关联对象范围内 | 自有或本人负责活动的授权关联 | 自有或本人事实的关联 | 文件存在不意味着可下载 |
| 本人结果/确认/异议 | 管理查询但不可冒充本人确认 | 禁止 | 本人 | 确认绑定结果身份 |
| 发布、排名、导出、锁定、重开 | 范围内 | 禁止 | 本人允许公开的排名信息 | 不导出超范围人员 |
| 审计查询 | 管理范围内且具备审计权限 | 本人业务历史的受限展示 | 本人申报/异议历史 | 不返回密码、令牌、材料正文 |
| 站点设置、公开品牌发布 | 全局管理员 | 禁止 | 禁止 | 不允许外观修改权限策略 |

以上细粒度组织授权尚未实现。现有 `accounts.ts` 只区分基础管理员；不得声称当前已有范围隔离。

## 3. 周期状态机

沿用数据库阶段 CONFIGURATION / ACTIVE / CHECKING / LOCKED，中文展示可配置但语义固定。归档是可见性标记，不隐式成为另一计分阶段。

| 转换 | 前置条件 | 同事务/原子发布结果 | 拒绝/补救 |
|---|---|---|---|
| CONFIGURATION → ACTIVE | 范围已冻结初始版本、每学生唯一匹配、规则有效；管理员确认 | 固定首个规则版本及范围身份，递增周期修订，记录开启事件 | 校验错误定位节点/成员；不创建半套生效规则 |
| ACTIVE → CHECKING | 完整计算批次 READY，规则/输入/范围基线未变；无阻断缺失 | 发布结果集指针，记录核对窗口及策略 | 409 要求重算；缺失者清单不可伪装零分 |
| CHECKING → CHECKING（更正重发布） | 有更正理由、影响预览、全部候选结果完成 | 新结果集原子发布；保留旧集与确认/异议；标记过时确认 | 失败仍读取旧完整发布集 |
| CHECKING → LOCKED | 核对窗口结束；异议已处理或经明确例外策略；有效确认满足制度 | 生成不可变结算快照并固定结果、范围、规则、排名策略 | 列出阻断学生/异议/任务；不静默忽略 |
| LOCKED → ACTIVE | 特权管理员、重开理由、指定原快照及更正范围 | 新更正轮次关联旧快照；旧快照仍可读；当前开放写入 | 旧页面 revision 冲突；不原地覆写快照 |

当前仅第一项部分实现：`activateTerm` 校验并开启已保存 scheme，尚无范围/不可变版本。其余是目标，不是现有接口。

## 4. 阶段写入矩阵

- CONFIGURATION：编辑周期基础信息、范围及规则草稿；不得录入正式学生事实。
- ACTIVE：提交/审核认定、成绩及扣分写入；规则变更必须走影响预览和统一重算，不直接改生效 JSON。
- CHECKING：普通录入入口只读；异议处理产生显式更正操作和候选集。更正生效前后的结果身份不同，不能携带旧确认到新集。
- LOCKED：除授权读取、下载和发起重开外只读。禁止通过导入、批量操作、旧 API、后台任务绕过锁定。
- 时间窗口与阶段同时检查，时间使用服务端时钟。未配置核对/申报窗口时不得猜测学校制度，发布前要求管理员确认策略。

## 5. 并发与错误

同周期敏感写入与转换采用同一短事务锁域；保存必须携带对象 revision。后台计算不长时间持锁，准备时固定输入身份，切换时复核。全局账号锁与周期锁禁止无约定嵌套；跨域操作应拆分准备与提交，提交前复核权限，不靠长锁维持登录状态。

401 会话失效，403 无操作权限，404 不存在或按接口约定隐藏不可见对象，409 修订/阶段/输入身份已变化，422 目标契约的业务校验错误，429 资源限流。现有接口仍多用 400 和纯 error 文本；新错误码需经兼容迁移，不能仅凭本文件改变现有客户端。

## 6. 验收

同一操作覆盖匿名、首次改密、停用、撤销会话、三角色、跨对象、跨组织、阶段变化及并发旧页面。锁定与导入提交竞态只能有一种合法结果；拒绝后没有部分写入或未经授权的附件下载。重开不改变旧快照及其确认、排名与展示映射。制度未确定的核对时限、确认比例和例外锁定政策必须在周期发布前显式配置，本文件没有代替用户确认数值。
