# Domain Docs

本项目采用 single-context：业务术语统一放在根目录 `GLOSSARY.md`，架构决策放在 `docs/adr/`。

## 阅读顺序

探索业务、编写规格或修改实现前：

1. 读取根目录 `GLOSSARY.md`（如果存在）。
2. 读取 `docs/adr/` 中与本次工作有关的决策（如果存在）。
3. 在规格、任务、实现和审查中统一使用术语表里的业务名称。

文件尚不存在时继续工作；由 `/domain-modeling` 在术语或重要决策得到明确结论时按需创建。

## 文档职责

- `GLOSSARY.md` 只解释业务术语，技术方案写入规格或 ADR。
- ADR 保留重要选择的背景、取舍与结论。只有难以逆转、缺少背景会令人疑惑且确有方案取舍的决定，才单独记录。
- 新方案与已有 ADR 冲突时，明确指出冲突并说明重新讨论的理由。
