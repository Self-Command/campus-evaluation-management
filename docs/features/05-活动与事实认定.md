# 活动与事实认定详细设计

日期：2026-10-20。状态：目标设计 v0.1；现有能力与新增目标分列。关联 ENT-06/07/08/10/15/17。

## 1. 已核查实现

`src/server/activities.ts` 提供活动维护与管理员分值确认，只允许 ACTIVE 写入。发布者只维护本人活动；已确认活动不能改变 nodeId 或 points，但可更新名称、内容、要求和时间。现有错误提到统一更正，不代表更正功能存在。

`src/server/recognitions.ts` 使用唯一(activityId, studentId)参与事实。一个事实可关联多个认定来源，结果通过至少一个 APPROVED 来源计一次。提交要求确认活动、有效学生档案及提交者自有证明（1～5个）；同提交者同事实已有 PENDING 时拒绝重复。审核需管理员和 revision，但当前没有仅允许 PENDING 的状态限制，已通过/驳回可再被直接审核覆盖。列表最多200条，无游标与截断提示。

上述为静态代码事实；不是本轮运行验收结论。个人项目、补充材料、撤回、批量审核、已确认分值更正及独立活动详情尚未形成完整闭环。

## 2. 事实身份与计分

活动是多人共同参加的现实事件；参与事实稳定键继续为活动ID+学生ID，不使用文件哈希、活动名称或证明文件名去重。认定来源记录谁、何时、凭什么申请认定，不是第二份计分输入。多来源通过只增强依据，不重复分值。

个人成果应关联独立个人项目定义及 Claim；不能为了复用活动界面，把每份个人申报自动创建为公开活动。不同来源声称同一成果时提供候选关联，管理员核实后合并到稳定事实；不得仅按标题/哈希自动认定同一事实。需要跨活动去重的制度必须建立明确事实键和冲突处理政策，不能擅自模糊去重。

## 3. 页面和场景

### 活动目录与详情

目录包含周期、关键词、时间、分值确认状态、负责方筛选；按 startsAt 和 id 稳定排序。学生只读本人适用周期可见活动。详情显示名称、组织者、时间、内容、参与要求、计分归属路径、已确认分值与可提交状态；内部审核备注不进入公开活动说明。

管理员/发布者创建使用分组表单：基本信息→时间与参与要求→评分归属与申请分值。保存后显示真实确认状态；未确认活动不出现可提交认定按钮。详情区分普通信息编辑与“申请分值/归属更正”，后者必须展示影响，不共享普通保存按钮。

### 学生认定

学生从活动详情进入本人提交页，选择证明、填写事实说明，查看当前已有来源。重复提交反馈链接到已有待审记录而不是空泛失败。驳回后可派生新提交版本，旧理由和材料引用保留。上传成功但尚未提交时明确显示材料关联状态，离开可恢复草稿或提示未提交，不把上传当业务提交成功。

### 管理审核

待办列表按来源呈现学生、活动、提交时间、材料数、状态及是否已有有效来源。详情可授权下载材料，展示同一事实的其他来源与历史，避免把多份来源误判为多次参与。通过和驳回均填写理由；批量审核先选对象并查看汇总与阻断项，再提交，不能对未加载/跨筛选的隐形集合操作。

## 4. 来源状态机（目标）

采用 SUBMITTED / APPROVED / REJECTED / WITHDRAWN / REVOKED；现有 PENDING 映射 SUBMITTED，必须兼容已有枚举而非直接重命名线上数据。

| 操作 | 转换与主体 | 校验 | 历史/计分 |
|---|---|---|---|
| 提交 | 草稿→SUBMITTED；本人或授权代办 | 活动已确认、窗口开放、材料可用、事实键唯一 | 创建提交版本和材料引用，不计分 |
| 通过 | SUBMITTED→APPROVED；管理员 | 当前revision、周期、对象范围 | 追加 ReviewEvent；首次有效来源使事实计入 |
| 驳回 | SUBMITTED→REJECTED；管理员 | 非空业务理由 | 不计分；保留原材料与意见 |
| 撤回 | SUBMITTED→WITHDRAWN；原提交者 | 审核尚未发生且阶段允许 | 保留来源；不能直接物理删除 |
| 补充重提 | REJECTED/WITHDRAWN→新SUBMITTED版本 | 窗口、材料、无其他本人待审来源 | 不覆盖旧审核；新revision有独立身份 |
| 撤销通过 | APPROVED→REVOKED；管理员更正 | 理由、影响预览、基线身份匹配 | 无其他有效来源时才移除事实分值；触发重算 |

不提供 APPROVED→REJECTED 的无理由快捷覆盖。误审核先撤销并记录更正，再按授权流程派生新提交。现有审核接口必须迁移到同一服务规则，不能新页面严格、旧API仍可绕过。

材料补充请求作为审核意见/待补充任务记录，不能允许学生原地替换已审核版本的材料。若引入 NEEDS_INFORMATION 状态，应同步枚举、时限、提交版本与通知契约；本版不以隐含状态实现。

## 5. 分值与归属更正

已确认活动更正以原revision及规则版本为基线，生成受影响参与事实数、有效来源数、学生范围、缺失/总分变化及确认失效清单。未产生有效事实也要记录更正理由，但可简化为零影响确认。归属只能迁移到有效 ACTIVITY 叶节点；金额保持十进制字符串并验证非负。

ACTIVE 完成候选计算后短事务切换；CHECKING 必须进入结果更正重发布；LOCKED 先重开。失败不修改原 points、nodeId 或结果指针。普通文本修改不得顺带改变计分字段；时间/参与要求若会改变既有资格，必须展示资格影响，不能把描述更改自动当作撤销认定。

## 6. 批量审核原子边界

每次请求显式列出 sourceId+revision，数量上限在容量核准后固定；不接受“全选全部数据”布尔参数。默认同一周期一个批次全成功或全拒绝。任一越权、旧修订、非待审或周期变化则返回逐对象阻断原因，业务不部分写入。异步大批次按任务准备候选，但最终仍采用明确批次边界，不能暗中改成逐行成功。

幂等键绑定操作者、周期、排序规范化对象集合、动作及理由。同键相同载荷返回原结果，同键不同载荷409。已成功重试不重复递增 inputRevision 或重复发通知。

## 7. 数据与接口方向

复用 Activity、Participation、RecognitionSource、EvidenceReference。新增提交版本/ReviewEvent、更正预览与任务身份；人员外键补齐前检查孤立数据。活动详情、来源分页、提交/撤回/审核/撤销分别形成明确操作契约。当前 `GET/POST /api/activities` 的 action 分派保留兼容，但所有写入调用同一领域服务；目标接口未完整纳入OpenAPI前不得声称已可调用。

分页必须返回 items、nextCursor、hasMore，稳定复合游标，服务端检查筛选及授权范围；不再用静默 take:200 代替列表完整性。对不存在/不可见对象的处理保持一致，避免通过详情错误枚举学生及材料。

## 8. 手机与异常

手机列表用业务卡片显示活动、学生、状态和时间，不仅横向滚动桌面表。筛选在抽屉中明确应用/重置；返回详情恢复筛选与滚动位置。审核页材料列表与理由表单分段，主按钮固定在安全区上方，键盘弹起不遮挡错误。材料不可用时禁止通过并给出补充/重试入口，不用空白预览伪装成功。

上传失败可重试单文件，提交失败保留文本及已上传文件ID。401提示重新登录并保留非敏感本地文本；409保留用户意见但要求重新核对当前对象；403不显示不属于当前人的材料信息。多来源已有效时提示本次审核的真实计分影响，不承诺必增分。

## 9. 审计及验收

记录创建/维护、确认、更正预览/生效、提交/重提/撤回、审核/撤销及批量身份；包含操作者、对象、前后revision、理由、周期、输入修订及结果版本关联，不记录材料正文。

必须覆盖：发布者越权、学生替他人提交、借用他人证明、同事实并发提交、多通过来源只计一次、撤销一个来源仍有效/撤销最后来源失效、旧审核revision、批量任一失败全回滚、审核与锁定竞态、分值更正失败不改变旧结果、材料版本不可替换、超过200条分页可达及320/390px上传审核全流程。现有测试 `tests/integration/activities.test.ts` 可保留业务断言，但不代表上述新增状态已经通过。
