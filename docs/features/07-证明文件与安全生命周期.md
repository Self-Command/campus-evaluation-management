# 证明文件与安全生命周期

日期：2026-10-20。状态：目标详细设计 v0.1，尚未实现完整安全流水线。关联 ENT-07/08/15/18。

本轮用户明确要求立即提供授权图片/PDF预览；以[资源治理最新补充](07-证明文件与资源治理.md)为准，覆盖下文“仅attachment/必须等待衍生件”的旧实施顺序。仅放行现有受控PNG/JPEG/PDF，保持私有鉴权、类型/哈希及同源边界；不声称已安装病毒扫描、PDF清理或新资源生命周期。

## 1. 当前证据

`src/server/evidence.ts` 当前限单文件5MiB，识别PNG/JPEG/PDF部分特征，随机48位十六进制storageKey，私有目录写入使用wx，数据库失败尝试删除刚写文件。保存SHA-256，下载时重新校验。未关联且最近24小时上传文件数量达到30后拒绝继续上传；这是查询后写入，不能视为严格并发配额。

`POST /api/evidence` 接收原始二进制请求体（不是multipart），文件名由URI编码的x-file-name传入，读取流累计限额，并按账号限流。`GET /api/evidence/{id}` 强制attachment、private no-store、nosniff和sandbox CSP。服务授权当前允许管理员、文件所有者、关联事实学生及关联活动负责人读取。

文件签名不是完整解析、杀毒或PDF主动内容清理；当前无隔离扫描状态、下载审计、清理任务及总存储配额。下载整个文件读入内存，容量与并发需验证。上述不足不通过改文案宣称已解决。

## 2. 目标数据与状态

学生证明Evidence与公开品牌BrandAsset分开存储命名空间及服务，不通过“公开”字段把证明变成Logo。文件业务元数据包含稳定ID、ownerId、原始显示名、可信mime、大小、sha256、storageKey、状态、扫描策略/结果身份、createdAt、可关联截止、隔离原因；扫描详情只向授权运维可见。

状态：UPLOADING→QUARANTINED→AVAILABLE；校验/扫描拒绝为REJECTED；存储缺失/校验异常为UNAVAILABLE；满足清理政策后进入DELETE_PENDING→DELETED。状态变化必须可重试，数据库状态与磁盘状态不能靠单次异常假定一致。旧文件迁移为待验证存量，不冒充扫描通过；存量复核先只读建立清单，不自动删除。

EvidenceReference为引用事实，新增提交版本应引用确定文件，已审核版本禁止换文件。文件哈希校验完整性，不用于合并参与事实。相同字节但不同归属可存为不同业务对象；物理去重若实施也不能共享授权身份。

## 3. 上传流程

1. 检查有效会话、首次改密、角色、用途、文件数/体积与并发配额。客户端accept只是提示；服务端重新校验。
2. 有界读取到隔离存储，以随机键写入，绝不把用户文件名拼入路径。超限及时取消读取并清理临时片段。
3. 校验真实类型、完整结构、图片尺寸/解压资源边界、PDF策略，计算哈希并持久化隔离对象。未完成前不允许业务关联或下载。
4. 安全扫描由受控实现执行，有超时、版本及失败状态；扫描不可用时保持隔离并明确重试，不能fail-open。具体扫描产品选择须来源/许可/部署验证，不凭本设计宣称已安装。
5. AVAILABLE后返回安全元数据与文件ID。业务提交事务重新检查所有者、状态、用途、配额和引用对象权限；上传者客户端说“已扫描”无效。
6. 上传成功而业务失败留下可恢复未关联对象，经过保留窗口再清理，不立即删除用户刚上传材料。

现有5MiB作为兼容默认，不是容量承诺。管理员可配置更严格限制；扩大限制必须不超过经验证的服务硬上限，不能只调前端。数量检查需配额锁或原子预留，防止并发绕过。

## 4. 下载授权与异常

每次下载重新检查会话与引用对象范围。自有未关联AVAILABLE文件可读；已关联文件按提交者和事实/审核对象权限读取。限域管理员只能读范围内文件，不能沿用“任何ADMIN全局可读”。共享证明仅因确有共享引用而授权，不返回其他学生名单。

数据库读取后校验storageKey白名单和受控根目录；拒绝路径分隔符及非预期文件。存储缺失与哈希不一致返回稳定业务错误，记录安全事件并标记UNAVAILABLE，禁止返回损坏字节。响应不包含绝对路径、堆栈或storageKey。下载文件名清除控制字符，保持attachment和no-store；服务端记录下载者/对象/时间/结果，不记录文件正文或会话令牌。

404/403具体隐藏政策应与API统一，不能由不同角色产生可枚举的细节差异。限流/并发/带宽策略与上传独立。未来预览必须转换为受控安全衍生件，不以内联原始PDF/HTML绕过下载策略。

## 5. 引用与清理

业务材料默认不能由用户物理删除已引用文件。撤回、驳回、认定撤销不自动清除历史材料；历史保留政策由组织核准。未关联临时文件的保留窗口可配置，默认值需在设置中明确展示并审计变更；未核准前不对存量执行批量删除。

清理过程：只读候选→核对引用/历史保留/任务占用→取得对象级锁→标记DELETE_PENDING→移到隔离回收位置→记录成功→保留恢复窗口后最终删除。引用创建与清理使用同一对象状态检查，禁止清理判断后新引用落库。失败可重试；无数据库记录的磁盘孤儿单独出清单，不能整目录清空。备份内的已删除文件按备份保留政策处理，不伪称即时从所有备份擦除。

本轮及后续迁移不得删除现有证明文件；清理功能上线需要专门验收和授权，不能以文档清理名义执行。

## 6. 手机交互

支持系统文件选择和相册选择；显示名称、大小、逐文件上传/校验状态、失败原因及重试，不能用总体旋转图标掩盖失败。提交按钮在材料尚不可用时解释业务阻断，不能先提交后静默缺材料。离开页面确认未提交内容；返回后以服务端文件状态为准。长中文文件名换行、不遮挡移除/重试按钮；触控操作有可见文字及无障碍名称。

## 7. 备份恢复与验收

备份必须包含数据库引用与文件清单、大小和哈希，并具有一致性边界。恢复只在独立数据库与独立附件根目录验证；不得覆盖campus_dev或现有目录。恢复后检查引用可达、缺失、孤儿、哈希及权限，证明可下载不等于恢复完整。

验收覆盖：伪造扩展名/MIME、损坏结构、过大/空文件、恶意文件名、路径穿越、扫描超时、同时上传绕配额、会话撤销、共享引用越权、重复字节不重复计分、关联与清理竞态、文件缺失/篡改、数据库写入失败残留、隔离恢复与手机上传中断。必须在隔离夹具中进行，不修改真实附件验证破坏场景。
