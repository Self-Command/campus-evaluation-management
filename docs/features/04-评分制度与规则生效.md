# 评分制度与规则生效详细设计

日期：2026-10-20。关联：ENT-03/04/05/11/14。状态：目标设计v0.1；算法和配置现状已核查，目标模型/接口尚未实现。

## 1. 用户与页面

管理员在“测评管理 → 评分方案”选择周期和适用范围。页面包含方案摘要/版本状态、目录、选中节点设置、校验结果；试算、版本差异、影响分析为明确的子视图，不把整套参数和所有学生输入堆在一个长页面。学生和发布者只能读取已生效的授权规则说明，不可调用写入接口。

桌面目录与节点属性分栏；手机先选目录再进入节点编辑，保持路径及返回位置。比例字段按百分比展示，由客户端明确转换为标准十进制系数，服务端不猜“80”是80%还是80倍。

## 2. 规则对象

- 方案：稳定身份、名称、描述、适用周期/范围、当前生效版本；名称不是计算分支。
- 方案版本：不可变生效内容、草稿修订、来源版本、创建人与变更理由、schemaVersion、内容哈希；草稿编辑不直接修改已生效规则。
- 节点：稳定ID、parentId、同级order、名称、类型、进入父级系数、输入范围、封顶/下限、折算配置、缺失政策；移动不换ID，复制生成新ID并重写内部引用。
- 扣分项目：稳定ID、目标节点、名称、系数、启停与引用约束。项目当前值、逐笔事实与历史如何映射须在扣分设计中统一，不能靠删除项目消除既有扣分。
- 适用范围：依据稳定组织/学生范围标识匹配，不通过可变显示名判断；多方案范围重叠必须阻断发布或依据明确、可解释的唯一匹配策略处理。

当前scheme JSON结构只包含nodes/deductions，暂不存在方案版本及范围实体；新增时保持旧Term.scheme兼容读取，经过回填校验后再切换，不能立即删除旧字段。

## 3. 算法与验证

基础算子继续复用现有SUM、WEIGHTED、ACTIVITY、GRADE。汇总只取直接子级；计算顺序为汇总→封顶→可选折算→节点扣分→可选下限→向父级贡献。Rational中间精确，最终展示半入两位。增加任何新算子先定义输入、精度、缺失、边界与测试，不开放任意JS、SQL或eval公式。

保存与发布都验证：唯一根、ID唯一、无循环/游离、父子归属一致、输入节点无子级、汇总节点非空、权重合法且比例合计符合规则、范围最小不大于最大、折算基数正数、扣分引用有效、叶来源与引用数据相容。错误返回节点ID、字段路径、稳定错误码和可理解描述；不能只提示“配置无效”。

必需成绩缺失则该路径不完整、总分不可发布为完整成绩；明确0有效。可选缺失按策略计零并保留缺失说明。零活动不等于成绩缺失。显示精度与排序口径需在结果设计明确，不能让主题设置改变算分精度。

## 4. 编辑操作契约

| 操作 | 前置检查 | 结果与失败 |
|---|---|---|
| 新建/模板创建 | 名称与范围合法、模板版本可用 | 生成独立草稿，模板后续变化不联动已有方案 |
| 新增下级 | 父节点类型允许；叶已有输入时要求迁移设计 | 不允许静默转汇总导致输入丢失 |
| 移动/排序 | 无跨方案、无自身/后代挂接、修订匹配 | 原ID不变，父级权重合计重新校验 |
| 子树复制 | 目标父合法、容量边界满足 | 所有新ID和扣分内部引用完整映射，不复制学生事实 |
| 删除 | 查子级及活动/成绩/扣分等引用 | 有引用需归档或显式迁移，不级联抹除事实 |
| 保存草稿 | 当前身份/权限和draftRevision匹配 | 成功递增修订；409提示重新载入并保留本地修改供对照 |
| 试算 | 配置通过校验、输入符合精度/范围 | 返回每节点原始/封顶/折算/扣分/贡献、缺失及规则哈希；不写学生成绩 |

未保存修改切换节点可保留本地草稿；离开方案/套模板/重载需明确确认，不能悄悄丢失。服务端错误在当前表单/弹窗可见并能定位字段。

## 5. 有数据后的生效流程

目标状态：DRAFT→VALIDATED→PREVIEWED→PREPARING→READY→APPLIED；准备失败为FAILED，放弃为CANCELLED。已生效版本不可原地编辑，通过派生草稿更正。

1. 提交变更草稿及修订；服务端生成结构/参数差异，标识删除、拆分、来源变化与适用范围变化。
2. 检查活动、个人项目、成绩、扣分和现有结果引用，要求逐项迁移映射。来源不兼容、遗漏、目标无效则阻断。
3. 创建影响预览，绑定actor、草稿哈希、当前规则/输入/范围修订及有效期；展示受影响人数、缺失人数、迁移阻断和受授权的样例分数差异。
4. 确认时重新鉴权与核对所有修订；预览过期或输入变化返回409，不自动用旧确认套新输入。
5. 从固定输入视图准备完整候选结果，结果与当前有效集分离；分批处理需进度、失败定位、取消和恢复契约，不能持有15秒事务执行整个大规模运算。
6. 短事务内取得周期锁并复核版本，完成迁移及结果完整性核验后原子切换生效指针；失败保留上一完整结果，绝不半批可见。
7. 发布后审计记录前后版本、预览、理由、范围、结果集和任务身份。旧结果及已确认身份保留但不能冒充新版本确认。

配置期间允许首次生效；ACTIVE变更按上述流程；CHECKING按更正策略处理并失效受影响确认；LOCKED必须先经理由重开。现有实现仅支持CONFIGURATION保存及开启，不得在页面承诺目标流程已可用。

## 6. API目标与迁移

现有`POST /api/terms/{id}/scheme`保留save/preview/activate兼容。新增资源应分清草稿保存、validate、simulate、change-preview、apply和任务查询；请求携revision，预览确认只携服务端previewId和必要理由，不相信客户端提供的影响人数/结果。所有目标接口须在OpenAPI中完整定义后实施；此处不是现有接口清单。

版本哈希使用规范化配置内容，不能依赖普通对象键顺序。幂等键绑定操作者、对象、操作和请求哈希，同键不同载荷409。试算与影响预览限流、输入体积和资源上限独立于业务树深度；超限明确返回，不截断节点。

## 7. 审计与测试

审计覆盖草稿创建/保存、模板套用、迁移确认、生效/失败/取消、重开关联；不记录无必要学生材料正文。至少测试：结构循环、深树、比例和精度、负分、折算扣分顺序、零与缺失、不同学校模板、越权、并发草稿保存、旧预览、迁移遗漏、计算故障、切换前输入变化、重试幂等、锁定竞态、历史不可变及320px完整编辑流程。

完成标准不是“能保存节点”：管理员需在页面从空白或模板建立制度→定位错误→试算→启用→产生真实数据→预览变更→迁移/重算→核对新旧结果，且失败不会损坏原数据。
