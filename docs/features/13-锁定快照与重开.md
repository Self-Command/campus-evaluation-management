# 结算快照与理由重开

日期2026-10-20；ENT-14；目标详细设计v1；当前只有LOCKED枚举，未具备完整结算。

管理员在CHECKING发起锁定预检，列出缺失成绩、待审、未决异议、未确认学生（按周期政策）、过期结果集、范围/规则不一致和运行中变更。每个阻断可定位到业务对象。不能只检查phase或展示“无异常”占位。全部通过后生成SettlementSnapshot内容、hash与备份关联，短事务再校验基线并锁定。

快照包含固定学生和组织展示、规则版本、所有计分输入依据、结果树精确值、排名策略/名次、确认与异议处理引用；不是仅保存总分或hash。LOCKED后源事实/规则/成绩/扣分/发布指针不得普通修改，服务层统一阻断旧页面和导入提交。外观可变，快照导出用冻结字段，不重算历史。

重开只允许管理员，填写2..1000字符理由、选择旧快照，原子写TermReopen并转ACTIVE、使当前发布确认不可沿用。旧快照不可变且仍可查；更正后重新计算→发布→确认/处理→新快照，形成版本链。不能把“解锁”实现为删除旧快照或更新旧结果内容。

API目标POST /api/terms/{id}/lock-preview、POST /api/terms/{id}/lock、POST /api/terms/{id}/reopen、GET /api/terms/{id}/snapshots、GET /api/snapshots/{id}。预检绑定操作者/修订/有效期，锁定与写入竞态由同周期锁裁决；幂等重放返回原快照；重开旧revision409。

手机预检按阻断分类卡片可逐项跳转，最终确认写明周期、人数、版本和后果；历史列表可对比hash与时间，无假恢复按钮。验收LOCK-01全阻断覆盖、LOCK-02锁定写竞态、LOCK-03旧批次拒绝、LOCK-04重开历史不变、LOCK-05品牌/转班不污染快照、LOCK-06多轮结算链。
