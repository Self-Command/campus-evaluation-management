# 导入中心与版本化模板详细设计

日期：2026-10-20。状态：企业目标设计 v0.1；当前实现经源码核查，模板、批次查询及完整目标UI尚未实现。关联 ENT-02/07/09/10/15/17。

## 1. 当前能力及复用边界

| 类型 | 权限/阶段 | 行结果 | 现有提交语义 |
|---|---|---|---|
| 学生账号 | ADMIN；无周期 | NEW/SKIP/ERROR | 仅新建STUDENT；已有相同信息跳过且不重置密码，不同信息阻断；首次成功交付新密码，重放为空 |
| 活动名单 | ADMIN或本人活动PUBLISHER；ACTIVE | NEW/EXISTING/SKIP/ERROR | 已有效事实跳过；本人已有待审跳过；已有无效事实补新来源；提交后仍待审核 |
| 成绩 | ADMIN；ACTIVE | NEW/SAME/OVERWRITE/SKIP/ERROR | 新值写入/覆盖当前值；同值跳过；不同重复行阻断；有写入整批递增一次inputRevision |

复用 `spreadsheet.ts:parseAccountFile`、`upload-form.ts:boundedForm`、三类 `*-import.ts` 预检及批次事务，不另建一套独立计分逻辑。当前文件解析通用但函数名称沿用账号场景，后续可在兼容调用下调整命名。

当前约束：单文件1MiB、multipart总读取1100KiB、CSV为UTF-8、XLSX单工作表、表头加1～100数据行、最多30列、文本单元格最多200字符。XLSX预检最多300 ZIP条目及10MiB声明解压体积，拒绝检测到的公式、宏部件和外部链接；不能声称已完整验证所有恶意工作簿变体。学号列不允许数字Excel单元格，以保留前导零和长标识；成绩允许数字转十进制文本但仍受数值格式约束。

现有预览15分钟有效，状态字符串PREVIEW/COMMITTED。批次提交检查操作者，账号使用全局账号事务锁；业务导入使用周期短事务锁。没有模板下载、批次列表/详情HTTP入口、过期清理及统一状态枚举，错误部分为整文件拒绝而非逐行反馈。文件内`line=index+2`是解析后的逻辑行，不保证与含空行/多行CSV字段的物理行号一致。

## 2. 入口、页面与完整流程

导入中心按“学生账号 / 活动名单 / 成绩”分类，分别进入真实步骤：选择业务上下文→下载模板/字段说明→上传→列映射→预检差异→确认→提交结果。不得提供尚未实现类型的可用入口。

- 账号入口展示仅新建学生，不用于更改组织、角色或重置密码；更正引导到受控账号维护。
- 名单先选周期与本人有权维护的已确认活动，显示活动分值/归属及“提交认定后仍需审核”，选择自有共享证明及事实说明。
- 成绩先选周期与GRADE节点，显示合法范围、必需项、缺失语义及更正理由；确认页明确覆盖数量，不把覆盖叫“新增”。

每步返回保留非敏感输入。更换文件、映射、活动、节点、证明或理由即使已有预览也必须生成新预览身份；禁止把旧previewId和新参数拼接提交。提交只使用服务端批次，客户端不得传入可信行状态、影响统计或学生ID替代预检。

## 3. 模板契约

模板类型稳定标识：STUDENT_ACCOUNT、ACTIVITY_PARTICIPATION、GRADE_INPUT。模板版本是不可变的解析/字段约定，不绑定主题文案；下载响应给templateId/version/contentHash、文件名、格式及字段说明。字段显示名可配置，但稳定key与类型不变。

| 类型 | 必填列 | 校验与示例规范 |
|---|---|---|
| STUDENT_ACCOUNT | login、name、college、major、className | 学号文本、3～64字符允许字母数字._-；其余trim后非空且最多80；示例采用明显样例身份，不使用真实学生 |
| ACTIVITY_PARTICIPATION | login | 学号文本；活动/证明/说明由页面确定，不接受表格悄悄切换活动 |
| GRADE_INPUT | login、value | 学号文本；value为标准十进制，最多10位整数12位小数；节点/理由由页面确定；空白不是零 |

正式交付优先提供UTF-8带BOM的CSV模板及独立字段说明；XLSX支持作为现有上传兼容保留。提供XLSX下载时必须生成真正文本格式学号列，不能通过文件扩展名伪装CSV。示例数据与正式数据区分，上传前提示删除示例行；模板说明不得偷偷成为必填数据行。具体模板文件中不放可执行公式、外链、宏或真实账号密码。

业务自定义附加列仅在服务端配置白名单中允许；不支持任意JS/SQL表达式或从电子表格公式推导权限/分值。模板版本未知或停用不能静默按最新版本解释；提供明确版本错误与重下载入口。旧CSV无版本标记时作为legacy-upload处理并要求人工列映射，不伪称来源可验证。

## 4. 列映射与预检

读取表头后给建议映射但必须显示确认；重复/空表头以列位置和显示名区分。账号五字段必须一对一映射；成绩学号/成绩列不能相同。映射范围以实际表头为准，0-based索引仅为API兼容，不作为用户文字。

预检层次：请求体/编码/压缩安全→表结构→字段类型→学生身份与组织范围→业务节点/活动→数据库当前状态→批内重复→写入差异。文件无法安全解析时整文件拒绝；安全可解析的业务错误尽可能逐行给稳定code/字段/逻辑行/说明，现有整批schema拒绝处需改造，不能伪造已有逐行结果。

预览显示原值与拟写值、NEW/SKIP/OVERWRITE/ERROR及原因；统计和行内容由同一次服务端检查产生。存在ERROR则确认禁用，并提供错误明细下载（需公式注入防护）；用户修复后重新上传，不允许只勾掉错误行暗改原子边界。未来支持剔除行时必须生成新预览并明确展示新的批次范围。

空成绩：默认ERROR，不删既有值、不计0；若需要“清除输入恢复缺失”应单独更正操作，具备理由、影响分析与确认，不能用空单元格隐式触发。

## 5. 状态机与提交

目标批次状态PREVIEW→COMMITTING→COMMITTED；可变为EXPIRED/CANCELLED，准备失败为FAILED。现有同步提交不会持久化COMMITTING；新增状态必须通过迁移及恢复处理实现，不能仅前端加状态。

- PREVIEW固定操作者、类型、模板版本、规范化行/映射哈希、上下文、规则及相关输入基线、过期时间。
- 提交重新检查当前会话、角色、对象范围、周期状态、过期与快照；失败不产生部分业务事实。
- 账号密码哈希在锁外准备，写入前再次检查快照及权限；不把所有密码哈希工作放在长锁事务。
- COMMITTED重试返回已持久化非敏感结果，重复请求不重复建号、来源或覆盖。当前活动/成绩重放仍先受ACTIVE限制；目标统一批次查询可在只读阶段返回历史结果，但不能借重放再次写入。
- 同键不同载荷409；幂等不能仅依赖浏览器按钮或内存Map。预览与幂等结果均属操作者私有，管理员身份不自动允许获取他人初始密码。
- 异步大批量不在本版默认扩大100行限制；扩大前需容量、取消/恢复及明确原子边界验证。

快照应使用规范化确定性序列及明确字段集合，不能把整个可变对象JSON序列化当永久协议。相关变化才使预览失效；变化原因说明到“学生资料/活动分值/评分节点/当前成绩”，不得把全部冲突变成无法理解的上传失败。

## 6. 账号凭据一次性交付

现有账号批次仅首次提交响应交付新账号初始密码，数据库result不存明文，重放不再返回。若网络在提交成功后中断，用户可能拿不到凭据；不能重试时偷偷再输出，或自动重置刚创建的密码。

目标结果页只显示本次已安全接收的交付项，敏感数据不写localStorage、URL、审计或普通批次详情。凭据下载必须是显式操作、有清晰保管提示、响应no-store，导出不含无关档案；页面离开后不保证可恢复原密码。丢失时通过已授权的单账号重置流程，理由和会话撤销明确，并遵守本次用户禁止重置现有测试密码的保护边界。

## 7. API及目标数据

现有路径见[OpenAPI现状](../api/openapi.current.yaml)：三个POST multipart入口，action=columns/preview/commit。迁移期维持入口兼容并调用同一服务。

目标新增模板查询/下载、批次列表/详情/取消与错误明细下载；逐接口OpenAPI目标契约另行定稿，本文不宣称已可调用。批次不得仅靠JSON万能字段保存未校验任意对象；字段必须有版本schema。

批次新增字段方向：kind/templateVersion/schemaVersion、contextId、requestHash、baseIdentity、state、expiresAt、committedAt、resultSummary、errorSummary、actorId。源文件是否保留与保留时限独立配置；默认不为审计无限保留原始学生表。明细包含logicalRow、稳定字段key、规范化数据、状态与code，不保存初始密码。外键与索引按actor+createdAt、context+createdAt、state+expiresAt建立，具体完整字典在数据设计中确认后迁移。

## 8. 手机交互及无障碍

手机每步一屏，不把上传、映射、100行表、确认弹窗堆在同页。列映射使用字段标签+选择框，提供少量样例值；差异按学生卡片展示，能按错误/覆盖筛选并逐条访问。固定底部主操作保持在安全区，键盘不遮挡理由与错误。确认弹窗显示类型、周期、目标活动/节点、新增/覆盖/跳过/错误数量及不可部分提交提示，禁止只有“确定”。

上传进度和解析/预检/提交状态分开，失败保留可重试步骤；不要假定上传100%表示已落库。长学号/长中文换行，触控无需悬停。错误摘要支持键盘定位到映射字段或具体行；状态不只依赖颜色。

## 9. 审计、测试与验收

审计批次创建、提交、取消、过期清理与结果，覆盖实际写入前后值/理由及操作者；不记录上传文件正文、整批凭据或认证令牌。错误明细、结果和模板下载应用Excel公式注入防护，文本以=、+、-、@及控制前缀的处理需按字段类型区分，合法负分不能被粗暴破坏。

测试至少包括：UTF-8/BOM、前导零/长学号、数值Excel学号拒绝、公式/损坏ZIP/外链/多工作表、超行列/体积、重复同值与冲突、空值与零、无效学生、越权活动/材料、覆盖范围错误、过期/他人批次/旧快照、并发提交、提交与锁定竞态、事务中途故障全回滚、账号首次凭据/重放/响应丢失、超过一页差异可达及320px完整流程。

现有测试可复用：`tests/integration/account-import.test.ts`和`activities.test.ts`，浏览器账号导入测试的业务断言应保留并适配新UI。当前浏览器套件使用开发库临时数据，需完成独立测试服务/数据库/附件隔离后再作为企业验收证据；不能把历史10项通过替代新流程验证。
