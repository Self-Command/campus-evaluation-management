# 部署、维护与隔离恢复

日期2026-10-20；ENT-18；目标详细设计v1。Docker实际部署暂缓；[操作手册](../operations/运行维护与恢复.md)区分开发、构建、生产运行、容器、恢复证据。

运维先完成配置核验、备份和迁移演练，再部署生产构建，验证三角色和数据写入、重启持久化、健康探针、日志及恢复。应用不在启动时自动清库/seed或初始化管理员。迁移用deploy，不改已执行SQL；生产连接和secret通过受限环境注入，禁止输出到普通文档。

维护模式阻断新的业务写入但保留健康与授权只读；已有导入/计算任务完成或安全取消后进入备份。数据库逻辑备份与附件清单、规则/快照hash一同生成manifest，记录版本/时间/字节/sha256，不记录明文密码。备份存储权限与运行应用分开，保留策略组织核准，异地或离线副本需要实际运维条件。

恢复只接受全新隔离数据库和独立附件目录；验证目标连接不是campus_dev/生产源库，禁止覆盖恢复。恢复后核对迁移版本、表计数、孤立引用、附件hash、若干固定结果和快照hash，再运行授权冒烟。恢复环境关闭外部通知、使用独立会话secret，使旧生产cookie无效。验证通过后切换需按发布步骤执行，不把数据库恢复成功直接视为全系统恢复。

API公开仅/live和/ready；恢复命令不开放Web接口。ready检查连接/迁移/必要目录而不泄露拓扑，HTTP503进入告警。当前ready仅查未完成迁移记录，不比较仓库待部署迁移且未查附件写权限，需补齐。上线门禁还包含依赖安全/容量/备份演练，不能以build通过替代。
