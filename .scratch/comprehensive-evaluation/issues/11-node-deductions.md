# 11: 节点扣分登记与解释

**What to build:** 管理员选择学生与扣分项目，登记正数扣分额和理由，学生在分项明细中看到正确节点、系数和扣减结果；更正扣分后保留前后依据。

**Blocked by:** 05 学校模板、通用计分与试算明细。

**Status:** in-progress

## 实施证据（2026-10-20）

- 已实现 `DeductionInput` 唯一当前记录、正数限制、服务端项目/系数、修订防覆盖、登记/更正/撤销与前后依据审计。
- `/deductions` 管理员真实查询与操作；学生 `/results` 展示本人扣分项目、节点、系数、理由和更新结果。
- 数据库测试覆盖低权限、零额拒绝、总分后扣100形成负分、旧修订拒绝及理由撤销；浏览器覆盖83→78→撤销回83。
- 最新类型、lint、26项数据库测试、10项浏览器测试与构建通过。不同节点/系数/下限已有纯评分测试，但仍需补齐扣分业务入口组合验收及审计历史查询页面，暂不全勾。

**Spec coverage:** US-019、047、049、050、052、054、075、076、077、078、079；D-03、D-04、D-07、D-08、D-13；AC-02、AC-04、AC-08、AC-13。

- [ ] 管理员通过页面选择学生、学期和已配置扣分项目，录入合法正数与必填理由；客户端不能随意改变扣减节点和系数。
- [ ] 登记与更正经过角色和学期状态检查，保存有效扣分及必要审计记录并触发相应结果更新。
- [ ] 在节点汇总、封顶和可选折算之后按项目系数扣减，再应用明确配置的下限，与通用评分明细一致。
- [ ] 本校模板在加权总分后按100%扣减，未启用下限时允许展示负总分，不把扣分藏入普通加分项目。
- [ ] 重复请求与并发更正不能重复扣减或丢失新修改；失败操作不留下部分结果，旧值、修改理由和操作者可追溯。
- [ ] 学生仅查看本人扣分与结果，其他学生和发布者不能越权登记或读取；浏览器页面明确显示成功、错误和当前结果状态。
- [ ] 通过真实业务入口和数据库验证不同节点与系数、下限开关、总分扣分、重复请求和权限拒绝，并走通登记至学生查看流程。
