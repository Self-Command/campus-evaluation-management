# 01: 生产部署下的管理员登录与首次改密

**What to build:** 部署维护者从干净环境启动生产应用与 PostgreSQL、建立首个管理员，管理员在浏览器登录并完成首次改密后进入受保护的管理页面，退出后不能继续访问。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec coverage:** US-001、004、005、008、070、071、072、075、076、078、079、080；D-01、D-02、D-04、D-14；AC-01、AC-02、AC-14、AC-16。

- [ ] 使用已确认的 TypeScript、Next.js、React、Node、Prisma、PostgreSQL 和 NextAuth.js Credentials 路线，核对实际兼容版本并保留锁定信息。
- [ ] Docker Compose 可运行生产构建和真实数据库，维护者按环境示例完成配置、迁移、首个管理员初始化与启动；不提供可复用的公开默认密码。
- [ ] 首次管理员登录进入改密流程，改密前只能执行必要的改密和退出操作，改密后可访问受保护管理首页。
- [ ] 密码持久化为哈希；登录有频率限制，凭据失败、服务错误和会话密钥不会泄露给页面或日志。
- [ ] 受保护页面与业务请求验证会话；退出或密码变化使旧会话不能继续使用，Cookie 与可信来源设置适合实际演示访问环境。
- [ ] PostgreSQL 使用持久存储；迁移失败、数据库不可用与应用健康状态可区分，应用重启后管理员账号仍存在。
- [ ] 已建立以真实登录入口、真实测试数据库验证成功／失败登录、首次改密、退出及密码变化的测试，并在生产构建中走通本任务浏览器链路。
- [ ] 类型检查、代码检查、相关测试与生产构建有可复现命令，启动与初始化说明可由维护者照做。
