# 02: 三角色账号与学生档案管理

**What to build:** 管理员在页面创建学生、活动发布者和管理员账号，维护学生归属、重置密码及停用账号；不同角色登录后只访问各自允许的页面和数据。

**Blocked by:** 01 生产部署下的管理员登录与首次改密。

**Status:** ready-for-agent

**Spec coverage:** US-002、004、005、006、007、008、009、054、075、076、078、079；D-03、D-04；AC-01、AC-02、AC-16。

- [ ] 管理员可通过表单建立三类账号，学生绑定唯一学号并维护学院、专业与班级；学号按字符串处理，保留前导零。
- [ ] 学生使用学号、其他角色使用分配的登录名和密码登录；重复登录标识与无效字段在服务端拒绝。
- [ ] 初始与重置密码安全生成并通过受控界面交付，不持久化明文；新建与重置后要求首次改密。
- [ ] 管理员能重置密码、调整角色和停用账号，受保护操作检查最新账号状态及会话有效性，旧令牌无法继续沿用失效权限。
- [ ] 学生能查看本人档案；其他学生无法通过替换标识读取该档案，学生与发布者不能执行管理员账号操作。
- [ ] 角色导航、管理表单、确认提示、加载、空状态和错误状态与真实操作结果一致。
- [ ] 保存账号与档案变更的审计依据，不记录密码；数据库约束与事务防止重复建号或半成品档案。
- [ ] 通过真实登录与数据库测试创建、改密、重置、停用、角色变化和跨学生访问，关键浏览器流程通过且生产构建可用。
