# 学院、辅导员与跨学院活动流程方案

Status: ready-for-agent

日期：2026-10-20。用户已确认写入规范并要求按文档顺序开发修复。正式规则以[学院职责与统一审核规范](../../docs/product/学院职责与统一审核规范.md)及[ADR0005](../../docs/adr/0005-college-review-and-return-policy.md)为准。本文件保留前期核查及需求推演；新增规范不代表实现完成，后续逐任务记录代码、迁移和验证事实。GitHub此前保存的实现仍是原三角色版本，未授权自动推送本轮后续修改。

实施顺序：01组织/身份/范围→02直接申报及两级审核/退回→03学院活动/严格名单/独立证明→04成绩扣分审核→05公式导出/证据预览→06全流程对齐与迁移复核。各批自身先隔离验证、备份恢复及安全增量迁移，不等第六批才验证。第一批代码与52项隔离集成已通过，用户界面验收待进行；后续依赖以已验证接口和模型为基础，不把第一批当全部完成。见[实际实施记录](../../docs/audit/学院流程实施与验证-2026-10-20.md)。

## 1. 需求与优化结论

用户要求严格导入核对和活动防重复；引入辅导员、学院审核；个人申报先辅导员后学院终审；成绩和扣分由辅导员处理、学院审核；学生必须有有效学院、班级和辅导员归属；辅导员和学院分别只能导出自己管理的班级、本院学生。学院发布的活动允许其他学院参加，但不能因此获得其他学院学生档案、成绩或审批权限。

采用四类身份：学校管理员、学院管理人员、辅导员、学生。活动发布是学院管理人员的业务能力，不再另设“活动发布者”角色。学院是组织实体，工作人员使用各自账号，避免整个学院共用一个账号。活动归主办学院所有，具体创建人、经办人留痕，人员离岗不造成活动无人可维护。

区分两种权限：主办学院负责本活动的参与事实和活动原始分；学生归属学院负责是否认定计入该学生测评。活动可见、参与事实维护、学生档案访问和成绩导出分别授权。只有经过相应审核的事实才计分。

本方案涉及角色、组织、两级审核和导入语义调整；已同步正式基线及 ADR0005，替代旧三角色、审核分级延后、个人owner和追加导入等冲突目标。不把修改角色显示名当成完成权限迁移。

## 3. 组织与人员绑定

- 学校管理员建立学院，配置各学院管理人员；学院管理人员在本院维护专业、班级和辅导员分班，学校管理员保留全局配置及异常处理权限。
- 组织关系为学院→专业→班级；班级必须配置一名当前生效的责任辅导员，一名辅导员可负责本院多个班级。
- 学生必须选择已配置的班级，专业和学院由班级推导，责任辅导员由班级责任关系推导。不让学生档案同时手工填写三套可能矛盾的归属。不能绑定外院辅导员。
- 使用稳定 ID、组织编码和外键约束；名称用于展示，完整路径防止同名班级串院。引用中的组织只能归档，不能直接删除。
- 未完成组织/辅导员配置的学生进入待完善清单，不接受正式申报、录分或导入，不静默交给任意学院处理。
- 责任辅导员交接有生效时间、操作者、理由和交接记录；原人员权限及时撤销，未结事项显式移交。转院/转班不能偷偷改写已发布成绩及历史审核归属。
- 周期保存学生参评归属。未结事项发生转院等变化时展示影响、显式改派并重新校验审核；已发布、锁定历史保留当期身份，历史访问另按有效授权检查。

## 4. 角色与数据范围

| 身份 | 查看/维护 | 审核 | 导出 |
|---|---|---|---|
| 学校管理员 | 全校组织、账号、周期与规则、发布锁定及有理由异常处理 | 不自动代替日常两级审核；特殊更正须独立受控并留痕 | 授权的全校范围 |
| 学院管理人员 | 本院档案与测评；本院主办活动；开放给本院的跨院活动信息 | 本院学生终审，不能终审外院学生 | 本院授权学生；筛选只能继续缩小 |
| 辅导员 | 当前授权班级的学生和待办 | 本班学生申报/活动认定初审；发起成绩、扣分及更正 | 所负责班级；可多选自己负责的班级 |
| 学生 | 本人资料、符合条件的活动、本人参与/申报/成绩及异议 | 无代审权，不能选择审核学院或辅导员 | 本人允许下载的材料/结果 |

唯一必要的跨院学生数据访问：主办学院在“本活动参与名单”内可维护参与学生的最少字段，即学号、姓名、归属、参加情况、本活动原始分及相关证明；没有该学生完整档案、其他活动、学业成绩、扣分、个人申报或综合结果的访问权。这是活动对象权限，不是跨院学生管理权限。跨院人员的活动材料也不能扩展为其全部私有证据的访问权。

所有普通导出继续按操作者的学生归属范围裁剪：A 学院即使主办跨院活动，也不能导出 B 学院学生。跨院活动全名单导出如确需办理，由学校管理员的全校授权入口处理并记录用途；不默认向主办学院开放。

列表、详情、搜索建议、筛选选项、数量统计、证据预览/下载、批量操作、导入预检、提交、导出和历史版本统一执行服务端范围约束；不依靠隐藏菜单或请求里的 college/className 筛选值。拒绝请求不得回传越权学生的真实档案供比对。

## 5. 审核与计分

| 业务 | 提交与流转 | 计分时点 |
|---|---|---|
| 学生个人申报 | 学生提交→责任辅导员初审→归属学院终审 | 学院通过后成为有效认定，不再等待学校管理员 |
| 学业等非活动成绩 | 辅导员录入/导入本班成绩并提交→学院审核 | 学院通过后生效；辅导员提交已承担初核，无需让其再审核自己的提交 |
| 活动参与和活动分 | 主办学院提交正式活动名单/原始分→按学生归属分派辅导员初核→对应学院终审 | 每名学生经归属学院通过后计分，不等其他学院整场全部处理完 |
| 扣分 | 辅导员填写事件、项目、分值、依据并提交→学院审核 | 学院通过后扣分；待审不影响总分 |
| 已通过记录更正/撤销 | 有理由提出新修订→按该业务链路重新审核 | 保留旧有效版本，修订批准后原子替换/撤销，不在提交更正时先改正式分 |

个人申报与活动认定为待辅导员→待学院→已通过；普通退回统一有理由交原发起人，修正后新修订重走必要审核。仅学生个人申报的评分问题，学院内部退回辅导员重评，学生不重交不变材料。学生不自报分，辅导员通过前必须选择计分模块并填写当前修订分数，学院只终审。学生直接提交标题、日期、说明、证明，删除关联活动和认定项目目录/配置前置条件，旧引用只保留历史解释。

成绩、扣分从辅导员提交后直接进入待学院；学院不能绕过初审批准学生直接提交的申报。同一人不能通过兼任身份完成同一事项的全部必需审核。支持按活动/班级批量审核，但逐条检查归属、状态、修订和异常，不提供“忽略错误全部通过”。

活动来源与关联个人申报坚持同一事实只计一次；收到主办方导入时若已有个人申报，展示关联与冲突，不能新建第二份有效成绩。扣分按独立事件记录，不把不同违纪事件覆盖成一条，也不能让同一事件重试重复扣分。

学院审核拒绝某生计分不等于删除主办学院确认的出席事实；两者状态分别显示。辅导员或归属学院不能直接改主办学院的活动分，发现事实错误应退回主办学院更正，再重新审核。

## 6. 跨学院活动示例

1. A 学院创建活动，选择允许参加的 A、B 学院和进一步的班级/学生限制，发布前显示实际可见人数及范围。
2. B 学院管理人员、相关辅导员收到活动待办/通知，可查看活动内容和计分说明；符合范围的 B 学生在活动信息流看到该活动。此时均不需要查看 A 学院学生信息。
3. 活动结束后，由 A 学院的授权经办人提交包含 A、B 学生的实际参与名单及活动原始分。B 学院不能代改该活动名单。
4. 系统按每名学生的归属派发：A 学生到 A 辅导员和 A 学院，B 学生到 B 辅导员和 B 学院。A 学院不能批准 B 学生计分，B 学院不能浏览 A 学生的审核队列。
5. B 学院终审通过后，B 学生成绩生效。A 只看到本活动的参与和处理状态，不能查看 B 学生综合结果；B 查看/导出本院学生结果。学生“已参加”与“已计分”分开显示。

范围设置建议保留学院、班级、指定学生的交集语义，但为班级/学生提供明确的“所选范围内全部”选项，避免公开活动必须逐个勾选全校学生。跨院指定个别学生由对应院辅导员确认或提供名单，主办学院不获取可任意枚举的全校学生目录。这是对原三组全部非空、必须枚举学生的易用性优化，确认后才调整现实现。

## 7. 严格导入与重复控制

### 身份与业务字段

活动参与模板至少包含学号、姓名、学院、专业、班级；逐人录分模式另含本活动原始分，固定分模式从活动配置取分，不允许文件自定义。活动编号及目标周期由导入上下文固定，模板携带时也须一致。学校学号唯一，组织使用稳定编码/完整路径确认，不用姓名模糊匹配。

成绩等其他导入同步执行相同身份核验，再检查对应成绩字段。辅导员归属由系统推导，不信任文件自行指定审核人。所谓“全部字段一致”是全部必需身份/上下文字段与权威档案一致；新成绩、活动分或扣分属于新增业务数据，检查格式、精度、范围和重复，不要求与旧值相等，否则无法录入或更正。

除明确约定的首尾空白处理外，不自动纠错、改姓名、改学号、忽略错学院、替学生改档案或用导入覆盖归属。学号按文本精确处理，不吞前导零。任何一行身份不符、字段缺失、班级未配置、无责任辅导员、超活动范围、越管理范围、分值非法、批内重复学生，整份正式名单失败，不写入部分学生，也不按 SKIP 掩盖错误。预检显示行号、字段和错误原因；跨院错误不给出未经授权的档案真实值。

### 一活动一份正式参与名单

- 导入前先生成草稿预检；校验失败不消耗首次提交机会，修正后可重新上传。
- 首次成功提交形成一份正式名单并封存普通导入入口。重复文件、改文件名再上传、用另一账号导入，都不能创建第二份正式名单。
- 漏报、错分、撤销走独立的“补录/更正”流程：填写理由，展示新增/移除/修改差异，核验身份，再提交新修订及相应审核。遗漏行不能在普通上传时静默删除原学生。
- “同活动+同学生”业务唯一约束继续兜底；文件内容指纹用于发现重复文件，不能替代业务唯一约束。
- 同一批次因超时再次确认，返回原提交结果，不再写入，不当作第二次正式导入。两个账号并发提交同一活动，最多一个正式名单成功。
- 成绩导入按周期+学生+成绩项识别同一输入；已通过值只能走理由更正，不再普通覆盖。扣分按事件唯一识别。

完整流程为选择上下文→下载本范围模板/说明→上传→逐字段预检与差异→确认→事务提交→审核进度。预览失效时间、组织/责任分派、活动规则、档案、已有事实或权限变化都在提交前重新核验，旧预览不能提交。

当前单批上限100人；一活动一正式名单不能因此被解释为一场最多100人。实现时需对较大名单有明确容量及有界校验方案；需要分段上传时，各段仍属于同一草稿，在全部校验成功后统一形成正式名单。不能第一段落库后才发现后续错误，或借分段形成第二次普通导入。

## 8. 页面与迁移边界

页面继续仅根据指定完整模板具体页面改造。组织目录、班级及责任辅导员配置完整联动；学生档案不用自由文本填组织；学院/辅导员工作台与待办按职责展示；申报显示两级审核、材料、意见和历史；成绩、扣分、参与名单各有独立完整页面及预检、更正、进度。跨院活动信息与本院学生管理是不同入口，不靠混合学生名录解决活动发现问题。证据预览沿用同一对象权限。

迁移必须先备份并隔离恢复验证。原账号密码、数据库业务、证明和学校模板保留。旧 PUBLISHER 账号及个人 owner 活动不能仅改显示名称就获得学院权限：先明确学院归属和经办权限，无法明确的进入待归属清单，禁止默认赋予全校权限。已通过旧记录保留原有审核依据及来源，标记历史流程，不伪造辅导员审批；新流程从明确切换点启用，未结事项按显式规则移交。旧发布、确认、结算快照不可重写。

本方案不新增学院独立评分制度，继续每周期一套生效制度；学院业务终审与学校统一发布、锁定是不同动作。用户自行浏览器验收；后续实现按静态检查、隔离集成测试、HTTP、构建分别留下真实证据，不自动推送后续修改。

## 9. 必须覆盖的验收

1. 同学号但姓名、学院、专业、班级任一不符，批内重复、越权或非法分值：整批零写入。
2. 同活动重复文件、换名文件、不同账号、并发提交不能重复生效；网络重试返回原批次结果；有理由补录、更正保留历史并重新审核。
3. 学生申报未经过责任辅导员时，学院不能终审；学院批准后直接生效；退回、补充、改分及旧页面并发不绕过审核修订。
4. 辅导员只能查看、操作和导出授权班级；学院只能操作/导出本院学生；篡改请求、批量接口、筛选、证据和历史查询均不能越权。
5. A 学院活动开放 B：B 看得到活动；A 维护该活动最少参与数据；B 辅导员/学院仅处理 B 学生；A 不得查看或导出 B 的完整档案及综合成绩。
6. 转班、转院、辅导员交接、账号停用和角色变化后，旧待办及预览正确失效/移交，历史快照及原审核不改写。
7. 待审核成绩/扣分不影响总分，批准只生效一次；已生效记录修改不会立即覆盖正式值；个人申报与活动来源不双计。

## 10. 活动证明、辅导员参与视图与公式成绩导出补充

2026-10-20 用户补充，本节是新增需求整理，尚未实现。已只读分析用户提供的旧版 XLS 附件；只提取表头、模块关系和公式结构作为设计依据，未修改原文件、未执行宏，也不将原文件、学生原始值或附件副本放入项目或 GitHub。原表的固定列位置、模块名称、80%/20%等比例不作为通用导出规则。

### 活动证明独立于名单文件

- 活动详情设置独立材料区，由主办学院上传活动证明；文件成为活动的共享材料，参与记录按活动及材料版本关联，不要求每个学生或每次名单导入重复上传。
- CSV/XLSX 名单只含身份字段和必要的活动业务字段，不设证明文件、证明地址、证明 ID 列，不用单元格承载附件。活动是否具备必需证明在提交审核时单独检查；名单草稿和预检不因尚未上传证明而无法准备。
- 活动证明的增补、更换保留版本和操作者。已审核事项绑定当时材料版本；实质更换依据按影响范围重新审核，不以共享文件覆盖偷偷改变已通过依据。
- 学生个人申报仍单独上传本人材料。活动共享材料与学生个人私有证明权限不同，不能因为参加同一活动就浏览其他学生个人申报材料。

### 辅导员看到本班全部参与活动

- 辅导员视图按所负责班级的真实参与记录查询，覆盖本院和外院主办活动，不按活动主办学院把本班记录漏掉。
- 名单成功登记即可显示，并展示待初核、待学院、已通过、退回、更正等状态；不等审核通过才显示，待审记录仍不计入正式成绩。
- 展示学生、活动、主办学院、日期、所属模块、活动原始分、审核进度及相关材料，支持学生/班级/活动/状态筛选、分页和历史。
- 班级参与历史不会因活动撤回发布或不再面向该生开放而消失。辅导员只看到负责学生的参与情况，不自动得到整场活动其他班级名单的权限。

### 导出范围、布局与来源

- 辅导员可导出自己授权班级的全部学生详细成绩，包括未录齐成绩的学生，不能只导出已有有效分数的学生；可选一个或多个负责班级，不能篡改筛选导出他班。
- 学生可导出本人完整详细成绩，使用同一评分规则和版本；学院仍只能导出本院授权学生。
- 正式成绩默认取最新已发布/锁定版本，绑定对应规则、身份和有效原始输入快照。若提供当前录入进度导出，必须明确其状态，不混入不同版本或把待审值伪装成正式成绩。
- 班级版按学生逐行展开，分层表头覆盖所有大模块、小模块及更深层级；个人版按模块树逐行展开，保留原始分、封顶/折算、权重、贡献和扣分等核算信息。按系统制度动态生成，不固定学校模块名称或列数。
- 输出采用真正的 XLSX 公式工作簿；CSV 仅作为名单等数据交换格式，不承担完整公式成绩单。按实际需要提供主成绩表和一处规则参数区，不为每个模块创建重复工作表。

### 哪些是输入，哪些是公式

| 内容 | 导出方式 |
|---|---|
| 学生身份、周期和结果版本 | 对应版本的原始元数据；学号为文本 |
| 最底层模块的有效原始分 | 数值输入，允许用户在导出的工作簿内修改 |
| 原始扣分项目金额及必要状态 | 数值输入；累计、系数折算及扣减由公式完成 |
| 权重、封顶、原始满分、目标满分、下限等制度参数 | 取对应规则版本，集中列明，由公式引用，不把可变比例埋在公式里 |
| 子模块合计、大模块合计、封顶结果、折算分、加权贡献、扣分合计、总分 | Excel 公式，不写死服务端算出的结果数值 |

按系统现有顺序自底向上生成公式：输入/直接子节点汇总→可选封顶→可选满分折算→扣分及系数→可选下限→交给父模块按直接累加或权重计算。只引用直接子节点，不把明细、小计、比例分再重复相加。简单示意：小计使用 SUM，封顶使用 MIN，比例分引用参数权重乘算，总分引用各贡献分并在规则指定位置扣分；不把这些示意当成全校固定制度。

输入与公式区域采用清晰样式区分，冻结姓名学号与表头。用户修改原始分后，相关小计、比例分、总分自动联动。缺录与真实零分分开表示；必需输入不完整时标明缺录，不用空白转零造成虚假完整总分。设置自动重算，打开即能正常显示公式结果，不依赖宏、外部链接或用户手工重写公式。

导出文件的本地修改不自动回写正式系统；系统成绩更正仍按权限和审核流程处理。导出时附有周期、规则/发布版本和时间，避免把本地修改后的表格冒认为新的系统发布成绩。

### 参考文件观察与后续验证

已核查参考表的多层表头（大模块、工程/子模块、实际分、比例分、合计、扣分和总分）及代表性公式。原表有按权重乘算、MIN/SUM封顶和多级汇总；也存在表头写了100分上限、代表性合计公式却只是直接相加的情况。因此只抽象信息关系，新导出统一由系统生效制度生成公式，不照搬旧表公式或依赖其缓存结果。

后续必须验证：导出初始公式结果与同版本系统结果逐模块对账；改一个叶子原始分后仅沿其祖先及总分传播；封顶上下边界、权重、折算、扣分位置、下限、缺录与零、舍入均一致；不能重复计入展示比例分。检查 Excel 数值精度边界及跨客户端重算行为，不以写入公式字符串冒称已验证自动计算。学生和辅导员导出的范围与版本也须隔离测试。用户自行使用 Excel/WPS 验收，本轮尚未生成或验收导出工作簿。
